# 🏆 SQL最佳实践

> [!abstract] 📋 本节概览
> - 🎯 **学习目标**：用最简单的方式掌握写SQL的好习惯和实用技巧

> - ⏱️ **预计用时**：10分钟
> - 🔧 **开发环境**：MySQL/PostgreSQL/[SQL] Server
> - 📊 **数据集**：users、orders等表

## 🌟 通俗解释

SQL最佳实践就像"做饭的好习惯"，让你写的SQL更安全、更高效、更容易维护。

比如：做饭前先洗手、用完锅要洗干净，这些好习惯能让你少出错、效率高。

## 🧩 常用建议与典型场景

- **只查需要的字段**：不要用SELECT *，只查用得上的
  ```sql
  SELECT 姓名, 年龄 FROM 用户;
  ```
- **加注释**：复杂SQL要写注释，方便自己和别人看懂
  ```sql
  -- 查询北京用户的姓名和年龄
  SELECT 姓名, 年龄 FROM 用户 WHERE 城市 = '北京';
  ```
- **用参数化查询防止SQL注入**：不要拼接字符串
- **定期备份数据**：防止意外丢失
- **用事务保护批量操作的原子性**：在数据库和相关操作支持事务、且正确提交或回滚的前提下，同一事务内的操作可以全部提交或全部回滚；事务不能替代备份，也不保证所有方面的数据安全
- **多用WHERE筛选，减少数据量**
- **用EXPLAIN分析SQL效率**
- **命名规范**：表名、字段名要有意义，避免用a、b、c

## 🚦 典型场景举例

- 网站、APP开发时，防止用户输入恶意SQL
- 数据分析时，写清楚每一步的目的
- 团队协作时，大家都能看懂SQL

## 常见问题

- 用SELECT * 可能读取不需要的字段，增大返回数据量
- 拼接SQL字符串，容易被攻击
- 没有注释，自己都看不懂
- 表名、字段名太随意，后期难维护

## 总结小贴士

- SQL最佳实践就是"写得好、查得快、用得安全"
- 养成好习惯，能让你少踩坑、效率高
- 多看多练，遇到问题及时查资料

## 📊 实战练习

### 练习1：只查需要的字段并加注释
```sql
-- 查询上海用户的姓名
SELECT 姓名 FROM 用户 WHERE 城市 = '上海';
```

### 练习2：用EXPLAIN分析SQL（适用于MySQL/PostgreSQL；SQL Server需使用其执行计划功能）
```sql
EXPLAIN SELECT 姓名 FROM 用户 WHERE 年龄 > 30;
```
