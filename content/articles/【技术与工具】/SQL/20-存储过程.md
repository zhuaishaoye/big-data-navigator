## 🔧 技术定义

**存储过程（Stored Procedure）**是存储在数据库服务器中、可通过名称调用的一组数据库程序语句，可以接受参数、执行复杂的业务逻辑并返回结果；其解析、编译和执行计划缓存机制取决于具体数据库实现。存储过程是数据库端编程的核心组件，用于封装复杂的数据操作和业务规则。

### 🛠️ 核心特征

**执行机制**：
- **编译与计划管理**：具体行为取决于数据库实现，不能统一假定创建时完成全部编译优化或每次执行都无需重新解析
- **服务器端执行**：在数据库服务器端运行，减少网络传输
- **参数化调用**：支持输入、输出和输入输出参数
- **事务控制**：可以包含完整的事务处理逻辑

**技术优势**：
- **潜在性能收益**：服务器端执行及部分数据库的执行计划缓存可能减少开销，实际收益取决于查询、调用方式和数据库实现
- **代码复用**：一次创建，多处调用，减少重复代码
- **安全性增强**：减少SQL注入风险，集中权限管理
- **业务逻辑封装**：在数据层实现复杂的业务规则

## 📝 存储过程基础语法

### 🔨 创建存储过程

```sql title="CREATE PROCEDURE基本语法"
CREATE PROCEDURE procedure_name (
    [parameter_mode] parameter_name datatype,
    [parameter_mode] parameter_name datatype,
    ...
)
BEGIN
    -- SQL语句集合
    -- 业务逻辑处理
END;
```

#### 📄 参数类型说明

- **IN参数**：输入参数，只能向存储过程传递值
- **OUT参数**：输出参数，存储过程可以向外返回值
- **INOUT参数**：输入输出参数，既可以传入值，也可以返回值

```sql title="基础存储过程创建示例"
-- 创建用户积分更新存储过程
CREATE PROCEDURE UpdateUserPoints(
    IN user_id INT,
    IN points_to_add INT
)
BEGIN
    UPDATE users 
    SET points = points + points_to_add 
    WHERE id = user_id;
END;

-- 创建带输出参数的存储过程
CREATE PROCEDURE GetUserOrderCount(
    IN user_id INT,
    OUT order_count INT
)
BEGIN
    SELECT COUNT(*) INTO order_count
    FROM orders
    WHERE orders.user_id = user_id;
END;
```

### 📞 调用存储过程

```sql title="存储过程调用语法"
-- 调用无返回值的存储过程
CALL UpdateUserPoints(1001, 50);

-- 调用带输出参数的存储过程
CALL GetUserOrderCount(1001, @count);
SELECT @count as user_order_count;
```

## 🏗️ 高级存储过程特性

### 🔄 流程控制语句

存储过程支持完整的编程语言特性，包括条件判断和循环控制：

```sql title="条件控制和循环结构"
-- 带条件判断的存储过程
CREATE PROCEDURE ProcessUserLevel(
    IN user_id INT
)
BEGIN
    DECLARE user_points INT DEFAULT 0;
    DECLARE user_level VARCHAR(20);
    
    -- 获取用户积分
    SELECT points INTO user_points 
    FROM users WHERE id = user_id;
    
    -- 根据积分设置用户等级
    IF user_points >= 10000 THEN
        SET user_level = 'VIP';
    ELSEIF user_points >= 5000 THEN
        SET user_level = 'Premium';
    ELSEIF user_points >= 1000 THEN
        SET user_level = 'Regular';
    ELSE
        SET user_level = 'Basic';
    END IF;
    
    -- 更新用户等级
    UPDATE users SET level = user_level WHERE id = user_id;
END;

-- 带循环的批量处理存储过程
CREATE PROCEDURE BatchUpdateInactiveUsers()
BEGIN
    DECLARE done INT DEFAULT FALSE;
    DECLARE v_user_id INT;
    DECLARE cur CURSOR FOR 
        SELECT id FROM users 
        WHERE last_login_date < DATE_SUB(CURDATE(), INTERVAL 90 DAY);
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET done = TRUE;
    
    OPEN cur;
    
    read_loop: LOOP
        FETCH cur INTO v_user_id;
        IF done THEN
            LEAVE read_loop;
        END IF;
        
        -- 标记不活跃用户
        UPDATE users SET status = 'inactive' WHERE id = v_user_id;
    END LOOP;
    
    CLOSE cur;
END;
```

### 🔒 事务处理和错误管理

```sql title="事务控制和异常处理"
-- 带事务控制的转账存储过程
CREATE PROCEDURE TransferMoney(
    IN from_account INT,
    IN to_account INT,
    IN amount DECIMAL(10,2),
    OUT result_code INT,
    OUT result_message VARCHAR(255)
)
BEGIN
    DECLARE from_balance DECIMAL(10,2);
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        ROLLBACK;
        SET result_code = -1;
        SET result_message = '转账失败：系统异常';
    END;
    
    START TRANSACTION;
    
    -- 检查源账户余额
    SELECT balance INTO from_balance 
    FROM accounts WHERE account_id = from_account;
    
    IF from_balance < amount THEN
        SET result_code = -2;
        SET result_message = '转账失败：余额不足';
        ROLLBACK;
    ELSE
        -- 执行转账操作
        UPDATE accounts SET balance = balance - amount 
        WHERE account_id = from_account;
        
        UPDATE accounts SET balance = balance + amount 
        WHERE account_id = to_account;
        
        -- 记录转账日志
        INSERT INTO transfer_log (from_account, to_account, amount, transfer_time)
        VALUES (from_account, to_account, amount, NOW());
        
        COMMIT;
        SET result_code = 0;
        SET result_message = '转账成功';
    END IF;
END;
```

## 🏢 业务应用场景

### 📊 电商业务存储过程

```sql title="订单处理业务逻辑"
-- 创建订单处理存储过程
CREATE PROCEDURE ProcessOrder(
    IN user_id INT,
    IN product_id INT,
    IN quantity INT,
    IN unit_price DECIMAL(10,2),
    OUT order_id INT,
    OUT result_message VARCHAR(255)
)
BEGIN
    DECLARE product_stock INT DEFAULT 0;
    DECLARE user_points INT DEFAULT 0;
    DECLARE order_amount DECIMAL(10,2);
    
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        ROLLBACK;
        SET result_message = '订单处理失败';
    END;
    
    START TRANSACTION;
    
    -- 检查商品库存
    SELECT stock INTO product_stock 
    FROM products WHERE id = product_id;
    
    IF product_stock < quantity THEN
        SET result_message = '库存不足';
        ROLLBACK;
    ELSE
        SET order_amount = quantity * unit_price;
        
        -- 创建订单
        INSERT INTO orders (user_id, product_id, quantity, unit_price, order_amount, order_date)
        VALUES (user_id, product_id, quantity, unit_price, order_amount, NOW());
        
        SET order_id = LAST_INSERT_ID();
        
        -- 更新库存
        UPDATE products SET stock = stock - quantity WHERE id = product_id;
        
        -- 更新用户积分（消费1元=1积分）
        UPDATE users SET points = points + FLOOR(order_amount) WHERE id = user_id;
        
        COMMIT;
        SET result_message = '订单创建成功';
    END IF;
END;

-- 用户数据统计存储过程
CREATE PROCEDURE GetUserStatistics(
    IN user_id INT,
    OUT total_orders INT,
    OUT total_spent DECIMAL(10,2),
    OUT avg_order_value DECIMAL(10,2),
    OUT user_level VARCHAR(20)
)
BEGIN
    SELECT 
        COUNT(*),
        COALESCE(SUM(order_amount), 0),
        COALESCE(AVG(order_amount), 0)
    INTO total_orders, total_spent, avg_order_value
    FROM orders
    WHERE orders.user_id = user_id AND orders.order_status = 'completed';
    
    -- 根据消费金额确定用户等级
    CASE 
        WHEN total_spent >= 50000 THEN SET user_level = 'Diamond';
        WHEN total_spent >= 20000 THEN SET user_level = 'Platinum';
        WHEN total_spent >= 10000 THEN SET user_level = 'Gold';
        WHEN total_spent >= 5000 THEN SET user_level = 'Silver';
        ELSE SET user_level = 'Bronze';
    END CASE;
END;
```

### 🏭 数据维护存储过程

```sql title="系统维护和数据清理"
-- 数据归档存储过程
CREATE PROCEDURE ArchiveOldOrders(
    IN archive_days INT,
    OUT archived_count INT
)
BEGIN
    DECLARE archive_date DATE;
    SET archive_date = DATE_SUB(CURDATE(), INTERVAL archive_days DAY);
    
    -- 将旧订单移动到归档表
    INSERT INTO orders_archive 
    SELECT * FROM orders 
    WHERE order_date < archive_date;
    
    SET archived_count = ROW_COUNT();
    
    -- 删除已归档的订单
    DELETE FROM orders WHERE order_date < archive_date;
END;

-- 用户活跃度分析存储过程
CREATE PROCEDURE AnalyzeUserActivity()
BEGIN
    -- 更新用户活跃度标记
    UPDATE users SET 
        activity_status = CASE 
            WHEN last_login_date >= DATE_SUB(CURDATE(), INTERVAL 7 DAY) THEN 'highly_active'
            WHEN last_login_date >= DATE_SUB(CURDATE(), INTERVAL 30 DAY) THEN 'active'
            WHEN last_login_date >= DATE_SUB(CURDATE(), INTERVAL 90 DAY) THEN 'inactive'
            ELSE 'dormant'
        END;
    
    -- 生成活跃度统计报告
    INSERT INTO user_activity_report (report_date, highly_active, active, inactive, dormant)
    SELECT 
        CURDATE(),
        SUM(CASE WHEN activity_status = 'highly_active' THEN 1 ELSE 0 END),
        SUM(CASE WHEN activity_status = 'active' THEN 1 ELSE 0 END),
        SUM(CASE WHEN activity_status = 'inactive' THEN 1 ELSE 0 END),
        SUM(CASE WHEN activity_status = 'dormant' THEN 1 ELSE 0 END)
    FROM users;
END;
```

## ⚡ 性能优化要点

### 🚀 存储过程性能优化

1. **参数化查询**：避免动态SQL拼接，防止SQL注入
2. **索引优化**：为存储过程中常用的查询字段建立索引
3. **事务控制**：合理使用事务，避免长时间锁定
4. **错误处理**：完善的异常处理机制

```sql title="性能优化示例"
-- 优化前：使用动态SQL（不推荐）
CREATE PROCEDURE BadExample(IN table_name VARCHAR(50))
BEGIN
    SET @sql = CONCAT('SELECT * FROM ', table_name);
    PREPARE stmt FROM @sql;
    EXECUTE stmt;
    DEALLOCATE PREPARE stmt;
END;

-- 另一种设计：针对固定业务表使用参数化查询（与上例功能不同，不构成等价性能对照）
CREATE PROCEDURE GoodExample(IN user_id INT)
BEGIN
    -- 使用索引优化查询
    SELECT * FROM users WHERE id = user_id;
    
    -- 批量操作减少网络往返
    INSERT INTO user_log (user_id, action, action_time)
    SELECT id, 'login', NOW() FROM users WHERE id = user_id;
END;
```

## ⚠️ 使用注意事项

### 🚫 常见错误与限制

1. **参数类型匹配**：建议按声明类型传参；隐式类型转换是否成功取决于数据库、输入值及相关配置
2. **变量作用域**：DECLARE的变量只在当前BEGIN...END块中有效
3. **数据库兼容性**：不同数据库的存储过程语法有差异
4. **调试困难**：存储过程调试相对复杂

```sql title="常见错误示例及修正"
-- ⚠️ 不推荐：依赖隐式类型转换
CALL UpdateUserPoints('1001', 50);  -- MySQL可能将该字符串转换为整数，不应将其一概视为调用错误

-- ✅ 正确：参数类型匹配
CALL UpdateUserPoints(1001, 50);

-- ❌ 错误：变量作用域问题
CREATE PROCEDURE BadScope()
BEGIN
    IF 1=1 THEN
        DECLARE temp_var INT DEFAULT 10;  -- 错误：DECLARE必须在BEGIN后立即声明
    END IF;
END;

-- ✅ 正确：变量声明位置
CREATE PROCEDURE GoodScope()
BEGIN
    DECLARE temp_var INT DEFAULT 10;  -- 正确：在BEGIN后立即声明
    IF 1=1 THEN
        SET temp_var = 20;
    END IF;
END;
```

## 📋 最佳实践

### ✅ 设计原则

1. **命名规范**：使用清晰的命名约定（如sp_前缀）
2. **参数验证**：在存储过程开始时验证输入参数
3. **错误处理**：实现完善的异常处理机制
4. **文档注释**：为复杂存储过程添加详细注释

```sql title="最佳实践示例"
-- 规范的存储过程设计
CREATE PROCEDURE sp_user_order_summary(
    IN p_user_id INT,
    IN p_start_date DATE,
    IN p_end_date DATE,
    OUT p_result_code INT,
    OUT p_result_message VARCHAR(255)
)
/*
用途：生成用户订单汇总报告
参数说明：
  p_user_id: 用户ID
  p_start_date: 开始日期
  p_end_date: 结束日期
  p_result_code: 返回码（0=成功，-1=参数错误，-2=无数据）
  p_result_message: 返回消息
创建人：数据团队
创建日期：2025-01-02
*/
BEGIN
    DECLARE v_order_count INT DEFAULT 0;
    
    -- 参数验证
    IF p_user_id IS NULL OR p_user_id <= 0 THEN
        SET p_result_code = -1;
        SET p_result_message = '用户ID无效';
    ELSEIF p_start_date > p_end_date THEN
        SET p_result_code = -1;
        SET p_result_message = '日期范围无效';
    ELSE
        -- 业务逻辑处理
        SELECT COUNT(*) INTO v_order_count
        FROM orders
        WHERE user_id = p_user_id
          AND order_date BETWEEN p_start_date AND p_end_date;
        
        IF v_order_count = 0 THEN
            SET p_result_code = -2;
            SET p_result_message = '指定时间段内无订单数据';
        ELSE
            SET p_result_code = 0;
            SET p_result_message = CONCAT('成功生成', v_order_count, '个订单的汇总报告');
        END IF;
    END IF;
END;
```
