# 🛡️ 权限与安全

> [!abstract] 📋 本节概览
> - 🎯 **学习目标**：用最简单的方式理解并会用权限保护数据库安全
> - 📚 **前置知识**：[[【技术与工具】/SQL/06-SELECT语句结构|SELECT语句结构]]
> - ⏱️ **预计用时**：10分钟
> - 🔧 **开发环境**：MySQL/PostgreSQL/SQL Server
> - 📊 **数据集**：users、orders等表

## 🌟 通俗解释

权限就像"门禁卡"，谁能进、能看、能改，都要有相应的权限。

安全就像"防盗门"，防止陌生人乱动你的数据。

在数据库里，权限和安全就是控制谁能访问、修改、删除哪些数据，防止数据被误删、泄露。

## 🧩 语法和例子

```sql title="给用户授权只读权限"
GRANT SELECT ON 用户 TO 张三;
```
意思是：这条示意语句向张三授予用户表的查询权限。只有在张三没有通过其他直接授权、角色或更大范围的授权获得写权限时，才能将其视为该表的只读访问者。

再举个例子：收回某人的写权限：
```sql
REVOKE UPDATE ON 用户 FROM 李四;
```

## 🚦 权限与安全的常见用法

- 只给需要的人开放最小权限
- 定期修改密码，防止泄露
- 备份数据，防止丢失

## ❗ 常见小白易错点

- 权限给多了，容易被误操作或攻击
- 忘记收回离职员工的权限
- 密码太简单容易被破解

## 📚 总结小贴士

- 权限就是"门禁卡"，安全就是"防盗门"
- 只给需要的人最小权限
- 定期检查和备份，防止意外

## 📊 实战练习

### 练习1：给王五只读订单表的权限
```sql
GRANT SELECT ON 订单 TO 王五;
```

### 练习2：收回张三的删除权限
```sql
REVOKE DELETE ON 用户 FROM 张三;
```
