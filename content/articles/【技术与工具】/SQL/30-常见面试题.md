## 🟢 初级面试题

### 题目1：查找薪资最高的员工 ⭐

**题目描述**：
有员工表employees(id, name, salary, department_id)，查找薪资最高的员工姓名。

**解题思路**：
1. 先找到最高薪资
2. 再查找拥有最高薪资的员工

```sql title="方法一：子查询"
SELECT name 
FROM employees 
WHERE salary = (SELECT MAX(salary) FROM employees);
```

```sql title="方法二：窗口函数"
SELECT name
FROM (
    SELECT name, 
           RANK() OVER (ORDER BY salary DESC) as rk
    FROM employees
) t 
WHERE rk = 1;
```

> [!tip] 💡 面试要点
> - 考虑并列最高薪资的情况
> - 了解两种方法的性能差异
> - 能解释RANK()和ROW_NUMBER()的区别

### 题目2：统计每个部门的平均薪资 ⭐

**题目描述**：
统计每个部门的员工数量和平均薪资，按平均薪资降序排列。

```sql title="标准解答"
SELECT 
    d.department_name,
    COUNT(e.id) as employee_count,
    ROUND(AVG(e.salary), 2) as avg_salary
FROM departments d
LEFT JOIN employees e ON d.id = e.department_id
GROUP BY d.id, d.department_name
ORDER BY avg_salary DESC;
```

> [!warning] ⚠️ 常见错误
> - 忘记使用LEFT JOIN，导致没有员工的部门被遗漏
> - GROUP BY中遗漏非聚合字段
> - 平均薪资精度处理

### 题目3：查找重复数据 ⭐⭐

**题目描述**：
查找users表中手机号重复的所有用户记录。

```sql title="查找重复手机号"
-- 方法一：使用窗口函数
SELECT id, name, phone
FROM (
    SELECT id, name, phone,
           COUNT(*) OVER (PARTITION BY phone) as phone_count
    FROM users
) t
WHERE phone_count > 1
ORDER BY phone, id;

-- 方法二：使用GROUP BY
SELECT u.*
FROM users u
INNER JOIN (
    SELECT phone
    FROM users
    GROUP BY phone
    HAVING COUNT(*) > 1
) dup ON u.phone = dup.phone
ORDER BY u.phone, u.id;
```

### 题目4：连续登录用户分析 ⭐⭐⭐

**题目描述**：
有用户登录记录表login_logs(user_id, login_date)，查找连续登录超过3天的用户。

**解题思路**：
使用窗口函数和日期差值来识别连续登录。

```sql title="连续登录分析"
WITH login_with_rn AS (
    SELECT 
        user_id,
        login_date,
        ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY login_date) as rn
    FROM (
        SELECT DISTINCT user_id, login_date 
        FROM login_logs
    ) t
),
login_groups AS (
    SELECT 
        user_id,
        login_date,
        DATE_SUB(login_date, INTERVAL rn DAY) as group_date
    FROM login_with_rn
),
consecutive_counts AS (
    SELECT 
        user_id,
        group_date,
        COUNT(*) as consecutive_days,
        MIN(login_date) as start_date,
        MAX(login_date) as end_date
    FROM login_groups
    GROUP BY user_id, group_date
)
SELECT 
    user_id,
    consecutive_days,
    start_date,
    end_date
FROM consecutive_counts
WHERE consecutive_days > 3
ORDER BY user_id, start_date;
```

> [!tip] 💡 解题关键
> - 理解连续性问题的通用解法
> - 掌握窗口函数在序列分析中的应用
> - 注意去重处理（同一天多次登录）

### 题目5：用户留存率分析 ⭐⭐⭐

**题目描述**：
分析新用户的留存率，计算注册后1天、7天、30天的留存率。

```sql title="用户留存率分析"
WITH new_users AS (
    SELECT 
        user_id,
        MIN(DATE(created_at)) as registration_date
    FROM users
    GROUP BY user_id
),
user_activity AS (
    SELECT DISTINCT
        user_id,
        DATE(activity_date) as activity_date
    FROM user_activities
),
retention_analysis AS (
    SELECT 
        nu.registration_date,
        nu.user_id,
        -- 1日留存
        MAX(CASE WHEN ua.activity_date = DATE_ADD(nu.registration_date, INTERVAL 1 DAY) 
                 THEN 1 ELSE 0 END) as day1_retained,
        -- 7日留存
        MAX(CASE WHEN ua.activity_date = DATE_ADD(nu.registration_date, INTERVAL 7 DAY)
                 THEN 1 ELSE 0 END) as day7_retained,
        -- 30日留存
        MAX(CASE WHEN ua.activity_date = DATE_ADD(nu.registration_date, INTERVAL 30 DAY)
                 THEN 1 ELSE 0 END) as day30_retained
    FROM new_users nu
    LEFT JOIN user_activity ua ON nu.user_id = ua.user_id
        AND ua.activity_date >= nu.registration_date
    GROUP BY nu.registration_date, nu.user_id
)
SELECT 
    registration_date,
    COUNT(*) as new_users,
    SUM(day1_retained) as day1_retained_users,
    SUM(day7_retained) as day7_retained_users,
    SUM(day30_retained) as day30_retained_users,
    ROUND(AVG(day1_retained) * 100, 2) as day1_retention_rate,
    ROUND(AVG(day7_retained) * 100, 2) as day7_retention_rate,
    ROUND(AVG(day30_retained) * 100, 2) as day30_retention_rate
FROM retention_analysis
GROUP BY registration_date
ORDER BY registration_date;
```

### 题目6：销售同比环比增长 ⭐⭐⭐

**题目描述**：
计算每月销售额的同比增长率和环比增长率。

```sql title="销售增长率分析"
WITH monthly_sales AS (
    SELECT 
        DATE_FORMAT(order_date, '%Y-%m') as sales_month,
        SUM(total_amount) as monthly_revenue
    FROM orders
    WHERE status = 'completed'
    GROUP BY DATE_FORMAT(order_date, '%Y-%m')
),
sales_with_comparison AS (
    SELECT 
        sales_month,
        monthly_revenue,
        -- 环比：与上月比较
        LAG(monthly_revenue, 1) OVER (ORDER BY sales_month) as prev_month_revenue,
        -- 同比：与去年同月比较
        LAG(monthly_revenue, 12) OVER (ORDER BY sales_month) as same_month_last_year
    FROM monthly_sales
)
SELECT 
    sales_month,
    monthly_revenue,
    prev_month_revenue,
    same_month_last_year,
    
    -- 环比增长率
    CASE 
        WHEN prev_month_revenue IS NOT NULL AND prev_month_revenue > 0 THEN
            ROUND((monthly_revenue - prev_month_revenue) / prev_month_revenue * 100, 2)
        ELSE NULL 
    END as mom_growth_rate,
    
    -- 同比增长率
    CASE 
        WHEN same_month_last_year IS NOT NULL AND same_month_last_year > 0 THEN
            ROUND((monthly_revenue - same_month_last_year) / same_month_last_year * 100, 2)
        ELSE NULL 
    END as yoy_growth_rate
    
FROM sales_with_comparison
ORDER BY sales_month;
```

### 题目7：层次数据查询（员工上下级关系）⭐⭐⭐⭐

**题目描述**：
有员工表employees(id, name, manager_id)，查找每个员工的完整上级链路。

```sql title="递归查询上级链路"
-- MySQL 8.0+ 递归CTE
WITH RECURSIVE employee_hierarchy AS (
    -- 起始点：所有员工
    SELECT 
        id,
        name,
        manager_id,
        name as hierarchy_path,
        0 as level
    FROM employees
    
    UNION ALL
    
    -- 递归部分：向上查找上级
    SELECT 
        eh.id,
        eh.name,
        e.manager_id,
        CONCAT(e.name, ' -> ', eh.hierarchy_path) as hierarchy_path,
        eh.level + 1
    FROM employee_hierarchy eh
    INNER JOIN employees e ON eh.manager_id = e.id
    WHERE eh.manager_id IS NOT NULL
)
SELECT 
    id,
    name,
    -- 获取完整的上级链路（取最长路径）
    hierarchy_path as full_hierarchy
FROM employee_hierarchy
WHERE (id, level) IN (
    SELECT id, MAX(level)
    FROM employee_hierarchy
    GROUP BY id
)
ORDER BY id;
```

```sql title="从顶级管理者展开下属层级"
WITH RECURSIVE subordinate_tree AS (
    -- 起始点：所有顶级管理者
    SELECT 
        id,
        name,
        manager_id,
        0 as level,
        CAST(name AS CHAR(1000)) as hierarchy_path
    FROM employees
    WHERE manager_id IS NULL  -- 从顶级管理者开始
    
    UNION ALL
    
    -- 递归部分：向下查找下属
    SELECT 
        e.id,
        e.name,
        e.manager_id,
        st.level + 1,
        CONCAT(st.hierarchy_path, ' -> ', e.name)
    FROM subordinate_tree st
    INNER JOIN employees e ON st.id = e.manager_id
)
SELECT 
    id,
    name,
    level,
    hierarchy_path
FROM subordinate_tree
ORDER BY level, id;
```

### 题目9：复杂业务场景：电商漏斗分析 ⭐⭐⭐⭐⭐

**题目描述**：
练习统计有商品浏览行为的用户中，各事件的覆盖人数及人数比值；当前示例不约束事件顺序或转化时间窗口，不能直接作为有序转化漏斗。

```sql title="用户转化漏斗分析"
WITH user_funnel_events AS (
    -- 收集所有用户事件
    SELECT 
        user_id,
        'page_view' as event_type,
        created_at as event_time
    FROM page_views 
    WHERE page_type = 'product'
    
    UNION ALL
    
    SELECT 
        user_id,
        'add_to_cart' as event_type,
        created_at
    FROM cart_additions
    
    UNION ALL
    
    SELECT 
        user_id,
        'checkout_start' as event_type,
        created_at
    FROM checkout_starts
    
    UNION ALL
    
    SELECT 
        user_id,
        'payment_success' as event_type,
        created_at
    FROM orders
    WHERE status = 'completed'
),
user_funnel_summary AS (
    SELECT 
        user_id,
        MAX(CASE WHEN event_type = 'page_view' THEN 1 ELSE 0 END) as has_page_view,
        MAX(CASE WHEN event_type = 'add_to_cart' THEN 1 ELSE 0 END) as has_add_to_cart,
        MAX(CASE WHEN event_type = 'checkout_start' THEN 1 ELSE 0 END) as has_checkout_start,
        MAX(CASE WHEN event_type = 'payment_success' THEN 1 ELSE 0 END) as has_payment_success,
        
        -- 获取各步骤的时间戳
        MIN(CASE WHEN event_type = 'page_view' THEN event_time END) as first_page_view,
        MIN(CASE WHEN event_type = 'add_to_cart' THEN event_time END) as first_add_to_cart,
        MIN(CASE WHEN event_type = 'checkout_start' THEN event_time END) as first_checkout_start,
        MIN(CASE WHEN event_type = 'payment_success' THEN event_time END) as first_payment_success
    FROM user_funnel_events
    GROUP BY user_id
),
funnel_analysis AS (
    SELECT 
        COUNT(DISTINCT user_id) as total_users,
        
        -- 各步骤用户数
        SUM(has_page_view) as page_view_users,
        SUM(has_add_to_cart) as add_to_cart_users,
        SUM(has_checkout_start) as checkout_start_users,
        SUM(has_payment_success) as payment_success_users,
        
        -- 转化率计算
        ROUND(SUM(has_add_to_cart) * 100.0 / NULLIF(SUM(has_page_view), 0), 2) as page_to_cart_rate,
        ROUND(SUM(has_checkout_start) * 100.0 / NULLIF(SUM(has_add_to_cart), 0), 2) as cart_to_checkout_rate,
        ROUND(SUM(has_payment_success) * 100.0 / NULLIF(SUM(has_checkout_start), 0), 2) as checkout_to_payment_rate,
        ROUND(SUM(has_payment_success) * 100.0 / NULLIF(SUM(has_page_view), 0), 2) as overall_conversion_rate
    FROM user_funnel_summary
    WHERE has_page_view = 1  -- 只统计有浏览行为的用户
)
SELECT 
    '商品浏览' as funnel_step,
    page_view_users as user_count,
    100.00 as conversion_rate
FROM funnel_analysis

UNION ALL

SELECT 
    '加入购物车' as funnel_step,
    add_to_cart_users as user_count,
    page_to_cart_rate as conversion_rate
FROM funnel_analysis

UNION ALL

SELECT 
    '开始结账' as funnel_step,
    checkout_start_users as user_count,
    cart_to_checkout_rate as conversion_rate
FROM funnel_analysis

UNION ALL

SELECT 
    '完成支付' as funnel_step,
    payment_success_users as user_count,
    checkout_to_payment_rate as conversion_rate
FROM funnel_analysis;
```

### 题目10：性能优化实战题 ⭐⭐⭐⭐⭐

**题目描述**：
有一个慢查询，需要分析并优化其性能。

```sql title="优化前的慢查询"
-- 问题查询：查找每个用户最近的订单信息
SELECT 
    u.id,
    u.name,
    o.order_date,
    o.total_amount
FROM users u
LEFT JOIN orders o ON u.id = o.user_id
WHERE o.order_date = (
    SELECT MAX(order_date) 
    FROM orders o2 
    WHERE o2.user_id = u.id
)
ORDER BY u.id;
```

```sql title="候选改写：选取一条最近订单，需另行验证并列语义与性能"
-- 方法一：使用窗口函数
SELECT 
    u.id,
    u.name,
    o.order_date,
    o.total_amount
FROM users u
INNER JOIN (
    SELECT 
        user_id,
        order_date,
        total_amount,
        ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY order_date DESC) as rn
    FROM orders
) o ON u.id = o.user_id AND o.rn = 1
ORDER BY u.id;

-- 方法二：使用FIRST_VALUE窗口函数和DISTINCT改写
SELECT 
    u.id,
    u.name,
    latest_orders.order_date,
    latest_orders.total_amount
FROM users u
INNER JOIN (
    SELECT DISTINCT
        user_id,
        FIRST_VALUE(order_date) OVER (PARTITION BY user_id ORDER BY order_date DESC) as order_date,
        FIRST_VALUE(total_amount) OVER (PARTITION BY user_id ORDER BY order_date DESC) as total_amount
    FROM orders
) latest_orders ON u.id = latest_orders.user_id
ORDER BY u.id;
```

> [!tip] 💡 优化要点
> - **索引设计**：在(user_id, order_date)上建立复合索引
> - **避免相关子查询**：使用窗口函数替代
> - **减少数据扫描**：先筛选后连接
> - **执行计划分析**：使用EXPLAIN查看执行计划

### 练习1：第N高薪资 ⭐⭐⭐

编写SQL查询，获取Employee表中第二高的薪资。如果不存在第二高的薪资，查询应该返回null。

<details>
<summary>💡 点击查看解答</summary>

```sql
-- 方法一：使用LIMIT和OFFSET
SELECT 
    (SELECT DISTINCT salary 
     FROM employees 
     ORDER BY salary DESC 
     LIMIT 1 OFFSET 1) as SecondHighestSalary;

-- 方法二：使用窗口函数
SELECT 
    (SELECT salary
     FROM (
         SELECT salary, 
                DENSE_RANK() OVER (ORDER BY salary DESC) as rk
         FROM employees
     ) t
     WHERE rk = 2
     LIMIT 1) as SecondHighestSalary;
```
</details>

### 练习2：部门工资前三高的员工 ⭐⭐⭐⭐

查找每个部门工资前三高的员工。

<details>
<summary>💡 点击查看解答</summary>

```sql
SELECT 
    d.name as Department,
    e.name as Employee,
    e.salary as Salary
FROM (
    SELECT 
        name,
        salary,
        department_id,
        DENSE_RANK() OVER (PARTITION BY department_id ORDER BY salary DESC) as rk
    FROM employees
) e
INNER JOIN departments d ON e.department_id = d.id
WHERE e.rk <= 3
ORDER BY d.name, e.salary DESC;
```
</details>

### 练习3：连续出现N次的数字 ⭐⭐⭐⭐⭐

找出所有至少连续出现三次的数字。

<details>
<summary>💡 点击查看解答</summary>

```sql
SELECT DISTINCT num as ConsecutiveNums
FROM (
    SELECT 
        num,
        LAG(num, 1) OVER (ORDER BY id) as prev1,
        LAG(num, 2) OVER (ORDER BY id) as prev2
    FROM logs
) t
WHERE num = prev1 AND num = prev2;
```
</details>
