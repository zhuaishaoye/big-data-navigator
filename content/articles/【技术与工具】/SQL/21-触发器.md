## 触发器技术概述

**触发器（Trigger）** 是数据库管理系统中的特殊存储过程，它会在特定的数据库事件发生时自动执行。触发器是事件驱动的程序单元，其触发器入口由数据库事件触发，不能像普通存储过程一样直接调用。

### 核心特性

- **自动执行**：响应预定义的数据库事件
- **事务一致性**：与触发事件在同一事务中执行
- **数据访问**：MySQL和PostgreSQL的行级触发器按事件访问OLD或NEW；INSERT没有OLD，DELETE没有NEW；SQL Server的DML触发器使用inserted和deleted集合
- **级联效应**：可触发其他触发器执行

## 触发器类型与语法结构

### 按触发时机分类

1. **BEFORE触发器**：在触发事件执行前触发，可修改NEW数据
2. **AFTER触发器**：在触发事件执行后触发，用于后续处理
3. **INSTEAD OF触发器**：替代原始操作执行（主要用于视图）

### 按触发事件分类

- **INSERT触发器**：新增数据时触发
- **UPDATE触发器**：更新数据时触发  
- **DELETE触发器**：删除数据时触发

### 基本语法结构

```sql title="MySQL触发器语法"
CREATE TRIGGER trigger_name
{BEFORE | AFTER} {INSERT | UPDATE | DELETE}
ON table_name
FOR EACH ROW
BEGIN
    -- MySQL的条件执行逻辑应在触发器体内使用IF ... THEN ... END IF
    -- 触发器逻辑
END;
```

## 实际应用示例

### 数据审计日志系统

```sql title="用户数据变更审计触发器"
-- 创建审计日志表
CREATE TABLE audit_log (
    id INT AUTO_INCREMENT PRIMARY KEY,
    table_name VARCHAR(50),
    operation_type VARCHAR(10),
    old_data JSON,
    new_data JSON,
    user_id INT,
    operation_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 用户插入审计触发器
CREATE TRIGGER user_insert_audit
AFTER INSERT ON users
FOR EACH ROW
BEGIN
    INSERT INTO audit_log (table_name, operation_type, new_data, user_id)
    VALUES ('users', 'INSERT', 
            JSON_OBJECT('id', NEW.id, 'name', NEW.name, 'email', NEW.email),
            NEW.id);
END;

-- 用户更新审计触发器
CREATE TRIGGER user_update_audit
AFTER UPDATE ON users
FOR EACH ROW
BEGIN
    INSERT INTO audit_log (table_name, operation_type, old_data, new_data, user_id)
    VALUES ('users', 'UPDATE',
            JSON_OBJECT('id', OLD.id, 'name', OLD.name, 'email', OLD.email),
            JSON_OBJECT('id', NEW.id, 'name', NEW.name, 'email', NEW.email),
            NEW.id);
END;
```

### 业务规则自动化执行

```sql title="订单状态变更的库存管理触发器"
-- 订单发货时自动减少库存
CREATE TRIGGER order_shipped_inventory
AFTER UPDATE ON orders
FOR EACH ROW
WHEN NEW.status = 'SHIPPED' AND OLD.status != 'SHIPPED'
BEGIN
    UPDATE products 
    SET stock_quantity = stock_quantity - NEW.quantity,
        last_updated = CURRENT_TIMESTAMP
    WHERE product_id = NEW.product_id;
    
    -- 库存不足时记录警告
    IF (SELECT stock_quantity FROM products WHERE product_id = NEW.product_id) < 10 THEN
        INSERT INTO inventory_alerts (product_id, alert_type, message)
        VALUES (NEW.product_id, 'LOW_STOCK', 
                CONCAT('Product ', NEW.product_id, ' stock below threshold'));
    END IF;
END;

-- 订单取消时恢复库存
CREATE TRIGGER order_cancelled_inventory
AFTER UPDATE ON orders
FOR EACH ROW  
WHEN NEW.status = 'CANCELLED' AND OLD.status IN ('PENDING', 'PROCESSING')
BEGIN
    UPDATE products 
    SET stock_quantity = stock_quantity + OLD.quantity,
        last_updated = CURRENT_TIMESTAMP
    WHERE product_id = OLD.product_id;
END;
```

### 数据同步触发器

```sql title="主从表数据同步触发器"
-- 用户信息变更时同步到用户统计表
CREATE TRIGGER sync_user_stats
AFTER UPDATE ON users
FOR EACH ROW
WHEN NEW.email != OLD.email OR NEW.status != OLD.status
BEGIN
    -- 更新用户统计信息
    UPDATE user_statistics 
    SET email_domain = SUBSTRING_INDEX(NEW.email, '@', -1),
        status = NEW.status,
        last_profile_update = CURRENT_TIMESTAMP
    WHERE user_id = NEW.id;
    
    -- 如果统计记录不存在则插入
    IF ROW_COUNT() = 0 THEN
        INSERT INTO user_statistics (user_id, email_domain, status, last_profile_update)
        VALUES (NEW.id, SUBSTRING_INDEX(NEW.email, '@', -1), NEW.status, CURRENT_TIMESTAMP);
    END IF;
END;
```

## 触发器管理与维护

### 查看现有触发器

```sql title="查看触发器信息"
-- MySQL查看触发器
SHOW TRIGGERS FROM database_name;

-- 查看特定触发器详情
SHOW CREATE TRIGGER trigger_name;

-- PostgreSQL查看触发器
SELECT tgname, tgrelid::regclass, prosrc 
FROM pg_trigger t
JOIN pg_proc p ON t.tgfoid = p.oid
WHERE tgname = 'trigger_name';
```

### 修改和删除触发器

```sql title="触发器维护操作"
-- 删除触发器
DROP TRIGGER trigger_name;

-- 临时禁用或启用指定触发器（PostgreSQL；MySQL不支持以下语法）
ALTER TABLE table_name DISABLE TRIGGER trigger_name;
ALTER TABLE table_name ENABLE TRIGGER trigger_name;
```

## 性能优化与最佳实践

### 性能考虑要素

1. **触发器复杂度**：避免在触发器中执行复杂查询和长时间操作
2. **事务影响**：触发器与主操作在同一事务中，失败会导致回滚
3. **级联效应**：控制触发器链的深度，避免无限循环
4. **批量操作**：仅在数据库支持且已明确业务一致性方案时考虑临时禁用触发器；MySQL不支持上述禁用语法。禁用期间审计、统计和库存逻辑不会自动执行，须明确替代校验、派生数据补齐及恢复边界

### 最佳实践指南

```sql title="触发器最佳实践示例"
-- ✅ 好的实践：简洁高效的触发器
CREATE TRIGGER good_practice_trigger
AFTER INSERT ON orders
FOR EACH ROW
BEGIN
    -- 使用索引字段进行更新
    UPDATE customer_stats 
    SET total_orders = total_orders + 1,
        last_order_date = NEW.order_date
    WHERE customer_id = NEW.customer_id;
END;

-- ❌ 避免的做法：复杂查询和多表关联
CREATE TRIGGER bad_practice_trigger
AFTER INSERT ON orders  
FOR EACH ROW
BEGIN
    -- 避免：复杂的子查询和多表关联
    UPDATE customers c
    SET total_spent = (
        SELECT SUM(o.amount) 
        FROM orders o 
        JOIN order_items oi ON o.id = oi.order_id
        JOIN products p ON oi.product_id = p.id
        WHERE o.customer_id = c.id
    )
    WHERE c.id = NEW.customer_id;
END;
```

### 错误处理机制

```sql title="触发器异常处理"
CREATE TRIGGER error_handling_trigger
BEFORE UPDATE ON products
FOR EACH ROW
BEGIN
    -- 数据验证
    IF NEW.price < 0 THEN
        SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Product price cannot be negative';
    END IF;
    
    -- 业务规则检查
    IF NEW.stock_quantity < 0 THEN
        SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Stock quantity cannot be negative';
    END IF;
    
    -- 自动数据修正
    IF NEW.discount_rate > 1.0 THEN
        SET NEW.discount_rate = 1.0;
    END IF;
END;
```


2. **条件执行法**
```sql title="条件调试触发器"
CREATE TRIGGER conditional_debug
AFTER UPDATE ON users
FOR EACH ROW
WHEN NEW.debug_mode = 1  -- 仅在调试模式下执行

    -- 调试逻辑
```

### 常见错误类型

| 错误类型 | 原因 | 解决方案 |
|---------|------|----------|
| 同表修改或递归触发 | 行为取决于数据库；MySQL禁止触发器再次修改触发语句正在使用的表 | MySQL需要调整触发器设计，适用时在BEFORE触发器中赋值NEW字段；支持递归触发的数据库还需控制递归条件 |
| 事务死锁 | 多个触发器锁定相同资源 | 优化锁定顺序和范围 |
| 性能下降 | 触发器逻辑过于复杂 | 简化逻辑或异步处理 |
| 数据不一致 | 非事务型表、事务边界或外部副作用可能使失败后的状态不一致；事务型表上的触发器错误通常会使相关语句回滚 | 明确存储引擎、事务边界和外部副作用，并验证失败后的数据与日志状态 |

## 数据库差异性说明

### MySQL特性
- 支持BEFORE、AFTER触发器
- 不支持INSTEAD OF触发器
- 支持多个触发器按创建顺序执行

### PostgreSQL特性  
- 支持所有触发器类型
- 支持语句级触发器（FOR EACH STATEMENT）
- 支持条件触发器（WHEN子句）

### SQL Server特性
- 支持INSTEAD OF触发器（用于视图）
- 支持DDL触发器（数据库结构变更）
- 提供inserted和deleted虚拟表

## 实战练习与项目案例

### 练习1：电商系统订单处理触发器

```sql title="电商订单管理触发器系统"
-- 创建必要的表结构
CREATE TABLE orders (
    id INT PRIMARY KEY AUTO_INCREMENT,
    customer_id INT,
    product_id INT,
    quantity INT,
    unit_price DECIMAL(10,2),
    status ENUM('PENDING', 'PAID', 'SHIPPED', 'CANCELLED'),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

CREATE TABLE products (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100),
    stock_quantity INT,
    price DECIMAL(10,2)
);

CREATE TABLE order_history (
    id INT PRIMARY KEY AUTO_INCREMENT,
    order_id INT,
    old_status VARCHAR(20),
    new_status VARCHAR(20),
    changed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 订单状态变更历史记录触发器
CREATE TRIGGER track_order_status_changes
AFTER UPDATE ON orders
FOR EACH ROW
WHEN NEW.status != OLD.status
BEGIN
    INSERT INTO order_history (order_id, old_status, new_status)
    VALUES (NEW.id, OLD.status, NEW.status);
END;

-- 订单支付完成后的库存管理
CREATE TRIGGER process_paid_order
AFTER UPDATE ON orders
FOR EACH ROW
WHEN NEW.status = 'PAID' AND OLD.status = 'PENDING'
BEGIN
    -- 检查库存充足性
    IF (SELECT stock_quantity FROM products WHERE id = NEW.product_id) >= NEW.quantity THEN
        -- 预留库存
        UPDATE products 
        SET stock_quantity = stock_quantity - NEW.quantity
        WHERE id = NEW.product_id;
    ELSE
        -- 库存不足，拒绝本次状态更新；本触发器不将订单持久化为CANCELLED
        SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Insufficient stock for order';
    END IF;
END;
```

### 练习2：用户积分系统触发器

```sql title="用户积分自动化管理"
CREATE TABLE users (
    id INT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50),
    email VARCHAR(100),
    points INT DEFAULT 0,
    level ENUM('BRONZE', 'SILVER', 'GOLD', 'PLATINUM') DEFAULT 'BRONZE'
);

CREATE TABLE point_transactions (
    id INT PRIMARY KEY AUTO_INCREMENT,
    user_id INT,
    points_change INT,
    transaction_type VARCHAR(20),
    description TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 积分变更自动更新用户等级；此示例要求积分为非NULL值
CREATE TRIGGER update_user_level
BEFORE UPDATE ON users
FOR EACH ROW
BEGIN
    IF NOT (NEW.points <=> OLD.points) THEN
        IF NEW.points IS NULL OR OLD.points IS NULL THEN
            SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Points must not be NULL';
        END IF;

        -- 记录积分变更；记录与原更新处于同一事务
        INSERT INTO point_transactions (user_id, points_change, transaction_type, description)
        VALUES (NEW.id, NEW.points - OLD.points, 'LEVEL_CHECK', 'Points updated');

        -- BEFORE触发器通过NEW赋值，不再次UPDATE users
        SET NEW.level = CASE
            WHEN NEW.points >= 10000 THEN 'PLATINUM'
            WHEN NEW.points >= 5000 THEN 'GOLD'
            WHEN NEW.points >= 1000 THEN 'SILVER'
            ELSE 'BRONZE'
        END;
    END IF;
END;

-- 订单完成自动增加积分
CREATE TRIGGER award_points_on_completion
AFTER UPDATE ON orders
FOR EACH ROW
WHEN NEW.status = 'SHIPPED' AND OLD.status != 'SHIPPED'
BEGIN
    -- 按消费金额的1%给予积分
    SET @points_earned = FLOOR(NEW.quantity * NEW.unit_price * 0.01);
    
    UPDATE users 
    SET points = points + @points_earned
    WHERE id = NEW.customer_id;
    
    INSERT INTO point_transactions (user_id, points_change, transaction_type, description)
    VALUES (NEW.customer_id, @points_earned, 'ORDER_COMPLETION', 
            CONCAT('Order #', NEW.id, ' completed'));
END;
```

### 练习3：数据质量监控触发器

```sql title="数据质量自动监控系统"
CREATE TABLE data_quality_alerts (
    id INT PRIMARY KEY AUTO_INCREMENT,
    table_name VARCHAR(50),
    alert_type VARCHAR(30),
    record_id INT,
    message TEXT,
    severity ENUM('LOW', 'MEDIUM', 'HIGH', 'CRITICAL'),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 用户数据质量检查触发器
CREATE TRIGGER user_data_quality_check
BEFORE INSERT ON users
FOR EACH ROW
BEGIN
    -- 邮箱格式验证
    IF NEW.email NOT REGEXP '^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$' THEN
        INSERT INTO data_quality_alerts (table_name, alert_type, message, severity)
        VALUES ('users', 'INVALID_EMAIL', 
                CONCAT('Invalid email format: ', NEW.email), 'HIGH');
        SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Invalid email format';
    END IF;
    
    -- 用户名长度检查
    IF CHAR_LENGTH(NEW.username) < 3 THEN
        INSERT INTO data_quality_alerts (table_name, alert_type, message, severity)
        VALUES ('users', 'USERNAME_TOO_SHORT', 
                CONCAT('Username too short: ', NEW.username), 'MEDIUM');
        SET NEW.username = CONCAT(NEW.username, '_user');
    END IF;
END;
```

## 关键技术要点总结

### 触发器设计原则

1. **单一职责**：每个触发器专注处理一种业务逻辑
2. **性能优先**：避免复杂查询和长时间操作
3. **错误处理**：完善的异常处理和数据验证
4. **可维护性**：清晰的命名和充分的注释

### 生产环境部署建议

- **测试环境验证**：充分测试触发器逻辑和性能影响
- **监控告警**：设置触发器执行监控和异常告警
- **版本管理**：触发器代码纳入版本控制系统
- **文档维护**：完整记录触发器功能和业务规则

2. 理解事务一致性和并发控制

4. 实践复杂业务场景应用
