# 实践案例总览

> [!abstract] 项目视角
> 讨论“实践案例总览”时，最容易犯的错误是直接从工具或报表开始。更有用的顺序是：先看业务链条，再找可观察指标，随后确认数据粒度，最后才选择 SQL、模型或平台组件。本文按这个顺序给出可执行方案和常见的失败样本。

## 1. 项目背景与边界

“实践案例总览”作为项目，必须同时定义业务目标、数据范围、技术边界和验收方式。建议在立项材料里写清：

- **业务目标**：改善哪个流程、服务哪个角色、影响什么决策。
- **现状基线**：当前耗时、错误率、覆盖率、成本或用户反馈，不能只写“比较落后”。
- **范围**：覆盖业务域、系统、表、指标和团队；明确不做什么。
- **约束**：数据权限、上线窗口、依赖系统、预算、合规和人员。
- **成功标准**：主指标、护栏指标、验收样例和观察周期。

一个合格目标示例：

> 在【时间】前，为【用户】交付“实践案例总览”能力，使【规则通过率】达到【可解释目标】，同时保证资产责任唯一、规则可执行且可解释、问题分级明确，上线后由【负责人】按周复盘。

## 2. 现状诊断与数据资产盘点

先梳理数据目录、元数据平台、质量平台、权限系统、调度平台、工单系统之间的数据流，记录源系统、接口、表、任务、负责人和延迟。不要用一张“系统架构图”掩盖数据质量问题，必须把主键、时间、状态和数量关系标出来。

| 角色 | 业务对象 | 主键示例 | 在流程中的位置 |
| --- | --- | --- | --- |
| 核心对象 | 数据资产 | `asset_id` | 资产盘点 |
| 过程对象 | 字段 | `column_id` | 标准定义 |
| 过程对象 | 指标 | `metric_id` | 责任认领 |
| 结果对象 | 质量规则 | `rule_id` | 规则设计 |
| 结果对象 | 问题工单 | `issue_id` | 执行监控 |
| 专题分析 | 实践案例总览 | `topic_key = 'subject'` | 用于把通用事件收窄到本主题 |

盘点阶段至少输出：资产清单、接口清单、指标基线、质量问题清单、权限清单和依赖矩阵。对每个问题标记影响范围、发生频率、现有临时方案和根本原因。

## 3. 目标架构与方案取舍

| 层次 | 本文建议 | 关键问题 | 验收证据 |
| --- | --- | --- | --- |
| 数据源 | 数据目录、元数据平台、质量平台 | 权威源、更新频率、主键和权限 | 接口或表清单 |
| 接入 | 批、流或 CDC 按业务时延选择 | 重复、顺序、断点续传和回放 | 延迟与幂等测试 |
| 存储 | 按访问模式选择数据湖、数仓或 OLAP | 分区、格式、生命周期和成本 | 容量与查询评测 |
| 计算 | SQL、Spark、Flink 或 Python 服务 | 粒度、状态、资源和失败恢复 | 压测与执行计划 |
| 治理 | 元数据、质量、血缘、权限 | 责任、规则、影响分析和审计 | 规则结果与变更记录 |
| 服务 | 指标、API、看板或应用 | SLA、缓存、限流和版本 | 监控与验收样例 |

方案评审至少比较两种选择。例如批处理与实时处理、现成工具与自研、集中式平台与数据网格。比较维度包括交付速度、时延、成本、可维护性、权限边界、扩展性和失败恢复，而不是只比较功能清单。

## 4. 数据模型与指标口径

| 专题观测面 | 需要回答的问题 | 关键证据 | 判定与动作 |
| --- | --- | --- | --- |
| 采用与收益（本标题优先） | 谁在使用，是否改变决策，副作用如何 | 使用日志、主指标、护栏和复盘 | 上线数量不等于项目成功 |
| 上线 | 权限、质量、监控、培训和回滚是否就绪 | 上线清单、演练、验收和责任人 | 关键风险未关闭不发布 |
| 方案与证据 | 为什么选择当前方案，关键假设如何验证 | 替代方案、原型、数据和评审记录 | 重大假设必须有试验 |
| 问题与范围 | 项目改变什么行为，边界和不做什么是什么 | 决策记录、需求说明和现状基线 | 范围不清时先做诊断 |

| 指标 | 计算思路 | 主要维度 | 使用边界 |
| --- | --- | --- | --- |
| 规则通过率 | `COUNT(DISTINCT passed_rule_id) / COUNT(DISTINCT executed_rule_id)`（视图字段 `rule_pass_rate`） | 业务域、资产层级、规则类型 | 不混用测试、撤销和跨期状态；与“实践案例总览”相关时还要补充主题筛选 |
| 问题闭环率 | `COUNT(DISTINCT closed_issue_id) / COUNT(DISTINCT raised_issue_id)`（视图字段 `issue_closure_rate`） | 资产层级、规则类型、责任团队 | 不混用测试、撤销和跨期状态；与“实践案例总览”相关时还要补充主题筛选 |
| 资产完整率 | `COUNT(DISTINCT complete_asset_id) / COUNT(DISTINCT asset_id)`（视图字段 `asset_completeness`） | 规则类型、责任团队、严重等级 | 不混用测试、撤销和跨期状态；与“实践案例总览”相关时还要补充主题筛选 |
| 血缘覆盖率 | `COUNT(DISTINCT lineage_asset_id) / COUNT(DISTINCT critical_asset_id)`（视图字段 `lineage_coverage`） | 责任团队、严重等级 | 不混用测试、撤销和跨期状态；与“实践案例总览”相关时还要补充主题筛选 |

模型设计优先保证粒度清晰和可重算。事实表负责事件或结果，维度表负责对象属性与历史归属，汇总表负责稳定消费。对于“实践案例总览”，如果既有事件又有状态，应分别建模，避免用最新状态覆盖历史。

## 5. 案例一：华北某制造数据治理项目

### 案例 1：华北某制造数据治理项目的“实践案例总览”现场

这是一个结合公开方法、常见工程故障和脱敏数据构造的复合案例，不对应任何单一企业事实。

- **标题落点**：先把正常链路跑通，再人为制造一次失败和恢复。本例把“实践案例总览”映射到“数据项目交付、验收与运营”中的采用与收益，而不是泛泛讨论概念。
- **触发事件**：试点质量问题改善明显，但推广到更多工厂后效果迅速衰减。
- **业务与数据范围**：试点机制、责任人、规则、工单、培训和复制成本。数据侧重点采集使用日志、主指标、护栏和复盘，并与数据目录、元数据平台、质量平台中的时间、状态和责任人信息对齐。
- **需要回答的问题**：谁在使用，是否改变决策，副作用如何。
- **关键障碍**：项目依赖少数专家手工推动，没有形成角色、模板和自动化。同时要防止资产没有负责人把表面指标带偏。
- **处理过程**：把试点拆成可复制资产，建立本地负责人、规则模板、培训认证和月度复核。实施时把“上线前完成质量、权限、监控、培训和回滚验收”写成上线检查项，并为每一项保留日志、样本和负责人。
- **验证方式**：示例推广以复制周期、规则复用、问题复发和本地自治能力评估。验收至少同时看主指标、使用日志、主指标、护栏和复盘和一次故障回放，不能只截取优化后最快的一次结果。
- **可迁移结论**：遇到类似标题时，先按“从问题、范围、基线、方案、数据、上线、采用和复盘管理项目，确保交付的是可验证的业务能力而不是一次性材料。”建立判断顺序，再决定是否调整代码、资源、口径或组织流程。

项目里最重要的一次评审通常发生在写代码之前。把对象、粒度、时间和成功标准画在白板上，让业务、数据、安全和运维共同指出歧义，往往比上线后修复便宜得多。

    Milestone("采用与复盘", "产品负责人", date(2026, 12, 6), "使用日志、主指标与护栏"),
]

required_checks = [
    "项目目标包含业务行为、主指标、护栏指标和观察周期",

    "上线前完成质量、权限、监控、培训和回滚验收"
]

def release_gate(items: list[Milestone], checks: list[str]) -> dict:
    blockers = [item.name for item in items if not item.gate_passed]
    return {
        "project_id": PROJECT_ID,
        "topic": TOPIC,
        "blocked_by": blockers,
        "checks": checks,
        "release_allowed": not blockers and len(checks) >= 3,
    }

print(release_gate(milestones, required_checks))

### 上线前质量门禁

```python
# 实践案例总览：发布前的数据质量与分层检查
import pandas as pd
import numpy as np
import hashlib

TOPIC = "实践案例总览"
TOPIC_KEY = "subject"
RULE_ID = "rule_governance_1p37zq2"
GUIDE_CHECKS = [
    "项目目标包含业务行为、主指标、护栏指标和观察周期",
    "范围明确数据、系统、团队、权限和不在本期处理的事项",
    "上线前完成质量、权限、监控、培训和回滚验收",
    "项目复盘同时衡量采用、收益、副作用和可复制性"
]
RULES = {
    "required_columns": ["event_id", "asset_id", "check_time", "status"],
    "duplicate_key": "event_id",
    "entity_key": "asset_id",
    "time_field": "check_time",
    "max_duplicate_rate": 0.0005,
    "max_null_rate": 0.006,
    "allowed_status": {"valid", "completed", "cancelled", "refunded"},
}

def validate(frame: pd.DataFrame) -> pd.DataFrame:
    missing = [c for c in RULES["required_columns"] if c not in frame.columns]
    if missing:
        raise ValueError(f"{TOPIC}/{TOPIC_KEY} missing required columns: {missing}")

    checks = []
    checks.append(("duplicate_rate", frame[RULES["duplicate_key"]].duplicated().mean(), RULES["max_duplicate_rate"]))
    checks.append(("entity_null_rate", frame[RULES["entity_key"]].isna().mean(), RULES["max_null_rate"]))
    event_time = pd.to_datetime(frame[RULES["time_field"]], errors="coerce")
    checks.append(("invalid_time_rate", event_time.isna().mean(), 0.0))
    bad_status = (~frame["status"].isin(RULES["allowed_status"])).mean()
    checks.append(("invalid_status_rate", bad_status, 0.0))

    result = pd.DataFrame(checks, columns=["check_name", "value", "threshold"])
    result["rule_id"] = RULE_ID + "." + result["check_name"]
    result["topic"] = TOPIC
    result["topic_key"] = TOPIC_KEY
    result["passed"] = result["value"].le(result["threshold"])
    result["sample_fingerprint"] = hashlib.sha1(
        f"{TOPIC}|{RULE_ID}|{len(frame)}".encode("utf-8")
    ).hexdigest()[:12]
    return result

def diagnose(frame: pd.DataFrame) -> pd.DataFrame:
    return (
        frame.assign(stat_date=pd.to_datetime(frame[RULES["time_field"]]).dt.date)
        .groupby(["stat_date", "status"], dropna=False)
        .agg(
            event_cnt=(RULES["duplicate_key"], "nunique"),
            entity_cnt=(RULES["entity_key"], "nunique"),
        )
        .reset_index()
        .assign(topic=TOPIC, topic_key=TOPIC_KEY, rule_id=RULE_ID)
        .sort_values("stat_date")
    )

def release_gate(result: pd.DataFrame) -> None:
    failed = result.loc[~result["passed"], ["topic_key", "check_name", "value", "threshold"]]
    if not failed.empty:
        raise RuntimeError({"topic": TOPIC, "failed_checks": failed.to_dict("records")})

# 主题专属门禁：项目目标包含业务行为、主指标、护栏指标和观察周期；范围明确数据、系统、团队、权限和不在本期处理的事项；上线前完成质量、权限、监控、培训和回滚验收；项目复盘同时衡量采用、收益、副作用和可复制性
# 生产化时把结果写入质量平台，并携带批次、分区、代码版本、规则版本和处理工单。
```

代码交付要求：

- 参数化日期、环境和业务范围，不在代码里硬编码生产密钥。
- 任务可重复运行，重复执行不会产生重复数据。
- 关键步骤记录输入行数、输出行数、过滤行数和质量结果。
- 失败时保留日志和中间状态，支持按分区重跑。
- 代码、配置和表结构纳入版本管理，并有变更记录。

## 7. 案例二：华东某零售数据项目组

### 案例 2：华东某零售数据项目组的“实践案例总览”现场

这是一个结合公开方法、常见工程故障和脱敏数据构造的复合案例，不对应任何单一企业事实。

- **标题落点**：先把标题中的名词还原成一个可以观测的运行问题。本例把“实践案例总览”映射到“数据项目交付、验收与运营”中的上线，而不是泛泛讨论概念。
- **触发事件**：项目按期上线看板，但业务仍用 Excel 决策，数据团队无法证明价值。
- **业务与数据范围**：需求访谈、用户任务、使用日志、指标口径、决策记录和反馈。数据侧重点采集上线清单、演练、验收和责任人，并与数据目录、元数据平台、质量平台中的时间、状态和责任人信息对齐。

- **关键障碍**：项目只定义功能范围，没有定义采用动作和决策改变。同时要防止规则只告警不闭环把表面指标带偏。
- **处理过程**：把关键决策、使用场景和验收样例写入范围，按业务角色灰度并跟踪真实查询与行动。实施时把“项目复盘同时衡量采用、收益、副作用和可复制性”写成上线检查项，并为每一项保留日志、样本和负责人。
- **验证方式**：示例验收以采用率、决策闭环、口径争议和人工步骤变化评估。验收至少同时看主指标、上线清单、演练、验收和责任人和一次故障回放，不能只截取优化后最快的一次结果。
- **可迁移结论**：遇到类似标题时，先按“从问题、范围、基线、方案、数据、上线、采用和复盘管理项目，确保交付的是可验证的业务能力而不是一次性材料。”建立判断顺序，再决定是否调整代码、资源、口径或组织流程。

## 8. 测试、灰度与上线

| 测试类型 | 检查内容 | 通过标准 |
| --- | --- | --- |
| 单元测试 | 字段映射、计算逻辑、边界条件 | 用例覆盖正常、异常和极端值 |
| 集成测试 | 上下游接口、主键关联、权限 | 端到端能跑通 |
| 数据测试 | 唯一、完整、及时、平衡 | 关键规则通过并留存结果 |
| 性能测试 | 扫描量、执行时长、并发和资源 | 在容量预算内且可扩展 |
| 灰度 | 小范围业务与新旧结果对照 | 差异可解释，问题可回滚 |
| 验收 | 业务样例、指标和操作流程 | 验收人签字或有系统记录 |

灰度阶段应保留新旧链路对照。差异不能简单要求“完全一致”，因为修复本身可能改变结果；正确做法是对每类差异给出原因、影响和审批。

## 9. 第三个案例：华南某银行数据中台项目

### 案例 3：华南某银行数据中台项目的“实践案例总览”现场

这是一个结合公开方法、常见工程故障和脱敏数据构造的复合案例，不对应任何单一企业事实。

- **标题落点**：先确认业务对象和系统边界，再讨论工具或参数。本例把“实践案例总览”映射到“数据项目交付、验收与运营”中的方案与证据，而不是泛泛讨论概念。
- **触发事件**：平台组件全部交付，但跨部门数据接入进度严重滞后。
- **业务与数据范围**：资产范围、责任矩阵、接口、权限、迁移批次和依赖。数据侧重点采集替代方案、原型、数据和评审记录，并与数据目录、元数据平台、质量平台中的时间、状态和责任人信息对齐。

- **关键障碍**：技术任务完成被当作项目进度，业务口径、数据授权和源系统改造没有纳入计划。同时要防止口径变更缺少影响分析把表面指标带偏。

- **验证方式**：示例项目管理按可用资产、业务验收和依赖关闭而不是代码提交衡量。验收至少同时看主指标、替代方案、原型、数据和评审记录和一次故障回放，不能只截取优化后最快的一次结果。
- **可迁移结论**：遇到类似标题时，先按“从问题、范围、基线、方案、数据、上线、采用和复盘管理项目，确保交付的是可验证的业务能力而不是一次性材料。”建立判断顺序，再决定是否调整代码、资源、口径或组织流程。

- **关键异常或争议：** 一次错误发布已经产生结果，团队只能凭负责人记忆寻找影响范围，补数后仍无法确认是否重复或遗漏。初看时，调度平台与工单系统的状态字段似乎可以互换，但抽取边界记录后发现二者更新节奏和责任人不同。

- **处理步骤：** 第一步先冻结“实践案例总览”的当前定义并记录版本；第二步用质量规则明细核对调度平台到工单系统的关联；第三步按规则类型与严重等级做基线和结构比较；第四步记录异常样本、规则豁免与人工判断；第五步发布小范围结果，观察资产完整率和护栏指标平均修复时长。
- **行动与护栏：** 保存现场并停止下游扩散，按影响边界回滚或隔离结果，使用幂等任务从最小必要范围重新计算。专题检查项“项目复盘同时衡量采用、收益、副作用和可复制性”被写成发布门禁，恢复任务没有对账、没有版本记录或无法重复执行时，不宣布故障结束。
- **失败路径：** 直接覆盖目标表，或者把所有分区全部重跑以求省事。这类做法即使暂时让数字看起来一致，也会让后续无法区分“业务变化、数据缺失、规则例外和计算错误”。
- **可迁移结论：** 处理“实践案例总览”时，先验证决策记录、需求说明和现状基线，再讨论工具参数或资源调整。若证据只能支持一个假设，就把它标成假设，并为下一轮验证保留对照与样本。

> [!note] 本例验收
> 最终动作不是“把报表做出来”，而是由安全合规在明确时限内，根据资产完整率、平均修复时长和问题分级明确决定继续、回退、补查还是转人工。 若口径变更缺少影响分析或关键检查项没有证据，结论应停在“待核验”，不能用业务解释替代数据回放。

### 扩展代码一：从实践案例总览回到可核对明细

```sql
-- 实践案例总览：发布前质量画像
SELECT
  'subject' AS subject_key,
  stat_date,
  COUNT(*) AS row_cnt,
  COUNT(DISTINCT event_id) AS distinct_event_cnt,
  SUM(CASE WHEN event_id IS NULL THEN 1 ELSE 0 END) AS null_event_cnt,
  SUM(CASE WHEN check_time < business_time THEN 1 ELSE 0 END) AS time_reverse_cnt,
  SUM(CASE WHEN status NOT IN ('valid', 'completed', 'cancelled') THEN 1 ELSE 0 END) AS invalid_status_cnt,
  ROUND(COUNT(*) * 1.0 / NULLIF(COUNT(DISTINCT event_id), 0), 4) AS duplication_ratio
FROM fact_data_quality_result
WHERE stat_date BETWEEN :start_date AND :end_date
GROUP BY stat_date
HAVING SUM(CASE WHEN event_id IS NULL THEN 1 ELSE 0 END) > 0
    OR SUM(CASE WHEN check_time < business_time THEN 1 ELSE 0 END) > 0
    OR COUNT(*) <> COUNT(DISTINCT event_id)
ORDER BY stat_date;

-- 至少人工核对一次：资产责任唯一；规则可执行且可解释；问题分级明确。
```

执行这段 SQL 后，不要只看总量。应同时保存查询参数、口径版本、异常对象清单和对应原始记录抽样。若结果依赖人工过滤，要把过滤条件登记为规则，而不是留在个人脚本里。

### 扩展代码二：把实践案例总览的验收证据写成门禁

```python
from datetime import date
from hashlib import sha256

import pandas as pd

SUBJECT = "实践案例总览"
BLOCKING_RULES = ["资产责任唯一","规则可执行且可解释","问题分级明确"]


def validate_release(frame: pd.DataFrame, start: date, end: date) -> dict:
    scoped = frame.loc[
        frame["event_date"].between(pd.Timestamp(start), pd.Timestamp(end))
        & (frame["subject_key"] == "subject")
    ].copy()
    checks = {
        "has_rows": len(scoped) > 0,
        "event_id_unique": not scoped["event_id"].duplicated().any(),
        "entity_key_complete": scoped["entity_key"].notna().all(),
        "event_time_present": scoped["event_time"].notna().all(),
        "scope_matches": scoped["subject_key"].nunique() == 1,
    }
    payload = f"{SUBJECT}|{start}|{end}|{len(scoped)}|{sorted(checks.items())}"
    return {
        "subject": SUBJECT,
        "rows": len(scoped),
        "checks": checks,
        "blocking_rules": BLOCKING_RULES,
        "release_allowed": all(checks.values()),
        "evidence_hash": sha256(payload.encode("utf-8")).hexdigest(),
    }
```

示例中的行数、时间戳和版本号均为占位值。生产实现应从调度参数、数据契约和质量平台读取真实信息，并将失败结果回写到工单、发布系统和责任人，而不是只打印在日志中。
