# Agent权限审计与责任边界

> [!tip] 核心原则
> 讨论“Agent权限审计与责任边界”时，最容易犯的错误是直接从工具或报表开始。更有用的顺序是：先看业务链条，再找可观察指标，随后确认数据粒度，最后才选择 SQL、模型或平台组件。本文按这个顺序给出可执行方案和常见的失败样本。

## 1. 从业务任务定义 AI 能力

围绕“Agent权限审计与责任边界”，先把任务写成输入、输出、成功标准和失败边界。不要从“上一套模型”或“接一个聊天框”开始。

| 设计项 | 必须回答的问题 | 错误示例 | 更好做法 |
| --- | --- | --- | --- |
| 用户 | 谁使用，谁复核，谁承担后果 | 所有人都能用 | 按角色和权限明确使用边界 |
| 输入 | 文本、表格、图片还是工具调用 | 把所有数据都塞进上下文 | 只提供任务所需且获授权的数据 |
| 输出 | 分类、生成、检索、SQL 还是动作 | 只要求“回答准确” | 定义可检查的输出结构 |
| 成功 | 任务完成、采纳、质量、时延和成本 | 只看离线准确率 | 离线 + 线上 + 人工复核 |
| 失败 | 无答案、拒答、转人工还是回滚 | 失败也生成看似合理内容 | 明确置信阈值和降级路径 |

AI 项目的数据治理比传统报表更强调版本和来源。至少记录：

- 数据集和知识文档的来源、授权、时间、负责人和版本。
- 样本标注规则、标注人、抽检结果和争议处理。
- 训练、验证、测试与线上反馈是否隔离。
- 提示词、模型、温度、检索参数和工具权限的版本。
- 输入中的个人信息、商业秘密和敏感字段是否脱敏。

如果“Agent权限审计与责任边界”使用 RAG，文档切片应尊重标题、章节、表格和条款结构；如果使用微调，先证明提示词、检索或流程优化不足；如果使用 Agent，先限制工具白名单和最大执行步数。

## 3. 评估：不要只看一个准确率

| 评估层 | 指标 | 说明 |
| --- | --- | --- |
| 检索 | Hit@K、MRR、版本正确率、权限过滤 | 正确内容是否被召回且可用 |
| 生成 | 引用支持率、事实一致性、完整性 | 回答是否有证据、是否遗漏关键条件 |
| 任务 | 完成率、转人工率、采纳率、重复澄清 | 用户问题是否真的解决 |
| 安全 | 越权、注入、敏感输出、违规动作 | 是否突破权限与安全边界 |
| 工程 | P50/P95 延迟、错误率、并发、成本 | 能否稳定且经济地服务 |
| 业务 | 节省时间、转化、质量、投诉 | 是否带来可解释价值 |

离线集要包含高频问题、长尾问题、边界问题、对抗问题和“应该拒答”的问题。线上评估要按用户、任务和风险等级分层，避免总体平均掩盖高危错误。

## 4. 案例一：华北某金融分析 Agent

### 案例 1：华北某金融分析 Agent的“Agent权限审计与责任边界”现场

这是一个结合公开方法、常见工程故障和脱敏数据构造的复合案例，不对应任何单一企业事实。

- **标题落点**：先把正常链路跑通，再人为制造一次失败和恢复。本例把“Agent权限审计与责任边界”映射到“AI Agent、工具调用与安全边界”中的工具，而不是泛泛讨论概念。
- **触发事件**：Agent 生成 SQL 后自动执行并制作图表，但部分查询超出用户数据权限。
- **业务与数据范围**：用户身份、语义层权限、SQL、执行计划、数据范围、审计和答案。数据侧重点采集工具清单、Schema、权限、审计和回滚，并与数据目录、元数据平台、质量平台中的时间、状态和责任人信息对齐。
- **需要回答的问题**：工具白名单、参数校验、幂等和副作用边界。
- **关键障碍**：权限只在最终展示层处理，SQL 已读取敏感明细，工具还会使用共享服务账号。同时要防止资产没有负责人把表面指标带偏。
- **处理过程**：执行前由语义层注入行级和字段权限，服务端限制扫描与导出，高风险查询要求复核。实施时把“完整记录计划、工具参数、结果、错误、版本和人工操作”写成上线检查项，并为每一项保留日志、样本和负责人。
- **验证方式**：示例工程证明 Agent 安全必须落在工具和执行层，而不是只靠提示词。验收至少同时看主指标、工具清单、Schema、权限、审计和回滚和一次故障回放，不能只截取优化后最快的一次结果。
- **可迁移结论**：遇到类似标题时，先按“把任务目标、规划、工具、状态、权限、预算、评估和人工接管设计成受控系统，不允许模型绕过服务端授权直接执行高风险动作。”建立判断顺序，再决定是否调整代码、资源、口径或组织流程。

### 检索、Agent 或模型任务实现

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Tool:
    name: str
    read_only: bool
    allowed_roles: set[str]

TOOLS = {
    "search_logs": Tool("search_logs", True, {"operator", "analyst"}),
    "restart_service": Tool("restart_service", False, {"operator"}),
}

def execute_tool(name: str, arguments: dict, actor: dict, approved: bool = False) -> dict:
    tool = TOOLS.get(name)
    if not tool:
        raise PermissionError("tool_not_in_allowlist")
    if actor["role"] not in tool.allowed_roles:
        raise PermissionError("role_not_allowed")
    if not tool.read_only and not approved:
        raise PermissionError("human_approval_required")
    return {"tool": name, "arguments": arguments, "audit": "recorded"}

# 主题："Agent权限审计与责任边界"
```

### 标题专属数据与失败分层 SQL

```sql
-- Agent权限审计与责任边界：分位对比诊断（业务域 × 规则类型）
WITH scoped AS (
  SELECT
    asset_id AS entity_key,
    event_id,
    check_time AS event_date,
    dimension_value AS primary_dim,
    stage_code AS secondary_dim,
    metric_value,
    status
  FROM fact_data_quality_result
  WHERE check_time >= DATE '2026-07-01'
    AND check_time <  DATE '2026-10-01'
    AND subject_key = 'agent'
    AND is_deleted = 0
),
dedup AS (
  SELECT *
  FROM (
    SELECT
      scoped.*,
      ROW_NUMBER() OVER (
        PARTITION BY event_id
        ORDER BY event_date DESC
      ) AS version_no
    FROM scoped
  ) ranked
  WHERE version_no = 1
),
grouped AS (
  SELECT
    primary_dim,
    secondary_dim,
    COUNT(DISTINCT entity_key) AS entity_cnt,
    COUNT(DISTINCT event_id) AS event_cnt,
    SUM(metric_value) AS metric_sum,
    AVG(metric_value) AS metric_avg
  FROM dedup
  WHERE status IN ('valid', 'completed')
  GROUP BY primary_dim, secondary_dim
),
contribution AS (
  SELECT
    *,
    metric_sum * 1.0 / NULLIF(SUM(metric_sum) OVER (PARTITION BY secondary_dim), 0) AS contribution_ratio,
    metric_avg - AVG(metric_avg) OVER (PARTITION BY secondary_dim) AS delta_to_peer
  FROM grouped
)
SELECT
  '资产完整率' AS checked_metric,
  primary_dim,
  secondary_dim,
  entity_cnt,
  event_cnt,
  ROUND(metric_sum, 4) AS metric_sum,
  ROUND(contribution_ratio, 4) AS contribution_ratio,
  ROUND(delta_to_peer, 4) AS delta_to_peer
FROM contribution
ORDER BY ABS(delta_to_peer) DESC, entity_cnt DESC;
```

示例代码只展示可测试结构。真实系统还需要模型服务、向量库、权限、日志、缓存、限流、敏感检查和人工反馈，不应把安全完全交给提示词。

## 6. 案例二：华东某企业运维 Agent

### 案例 2：华东某企业运维 Agent的“Agent权限审计与责任边界”现场

这是一个结合公开方法、常见工程故障和脱敏数据构造的复合案例，不对应任何单一企业事实。

- **标题落点**：先把标题中的名词还原成一个可以观测的运行问题。本例把“Agent权限审计与责任边界”映射到“AI Agent、工具调用与安全边界”中的任务，而不是泛泛讨论概念。
- **触发事件**：智能体可以自动查日志并重启服务，一次错误判断导致非目标实例被操作。
- **业务与数据范围**：用户指令、工具参数、服务清单、权限、审批、执行日志和回滚记录。数据侧重点采集目标说明、完成条件、最大步数和失败分类，并与数据目录、元数据平台、质量平台中的时间、状态和责任人信息对齐。
- **需要回答的问题**：成功是什么、何时停止、什么情况必须转人工。
- **关键障碍**：模型能直接调用高权限工具，目标实例仅由自然语言解析，没有环境标签和服务端校验。同时要防止规则只告警不闭环把表面指标带偏。
- **处理过程**：只暴露只读工具给模型，写操作生成变更单并由服务端校验目标、环境和审批，执行后自动验证健康状态。实施时把“对越权、提示注入、循环调用、错误重试和数据泄露做专门测试”写成上线检查项，并为每一项保留日志、样本和负责人。
- **验证方式**：示例系统把越权、误操作和不可回滚动作设为阻断级风险。验收至少同时看主指标、目标说明、完成条件、最大步数和失败分类和一次故障回放，不能只截取优化后最快的一次结果。
- **可迁移结论**：遇到类似标题时，先按“把任务目标、规划、工具、状态、权限、预算、评估和人工接管设计成受控系统，不允许模型绕过服务端授权直接执行高风险动作。”建立判断顺序，再决定是否调整代码、资源、口径或组织流程。

## 7. 架构与工程链路

| 层次 | 本文建议 | 关键问题 | 验收证据 |
| --- | --- | --- | --- |
| 数据源 | 数据目录、元数据平台、质量平台 | 权威源、更新频率、主键和权限 | 接口或表清单 |
| 接入 | 批、流或 CDC 按业务时延选择 | 重复、顺序、断点续传和回放 | 延迟与幂等测试 |
| 存储 | 按访问模式选择数据湖、数仓或 OLAP | 分区、格式、生命周期和成本 | 容量与查询评测 |
| 计算 | SQL、Spark、Flink 或 Python 服务 | 粒度、状态、资源和失败恢复 | 压测与执行计划 |
| 治理 | 元数据、质量、血缘、权限 | 责任、规则、影响分析和审计 | 规则结果与变更记录 |
| 服务 | 指标、API、看板或应用 | SLA、缓存、限流和版本 | 监控与验收样例 |

推荐把链路拆成六层：数据与知识准备、检索或特征、模型调用、工具执行、评估与审核、监控与反馈。每层都要有版本、日志和失败处理。Agent 工具调用应在服务端校验参数与权限，不能只依赖模型“自觉”。

## 8. 监控、成本与安全

- 监控请求量、延迟、错误码、超时、重试和缓存命中。
- 记录检索文档版本、模型版本、提示词版本和关键参数。
- 对失败分类：检索缺失、上下文过长、工具失败、权限拒绝、模型拒答、结果不合规。
- 设置单位任务成本、每租户预算和异常调用告警。
- 对提示注入、越权、敏感信息和危险动作做专门测试。
- 保留人工复核、转人工、回滚到旧模型和关闭工具的开关。

## 9. 第三个案例与上线验收

### 案例 3：华南某电商客服 Agent的“Agent权限审计与责任边界”现场

这是一个结合公开方法、常见工程故障和脱敏数据构造的复合案例，不对应任何单一企业事实。

- **标题落点**：先确认业务对象和系统边界，再讨论工具或参数。本例把“Agent权限审计与责任边界”映射到“AI Agent、工具调用与安全边界”中的状态，而不是泛泛讨论概念。
- **触发事件**：多轮对话中智能体反复调用订单和优惠工具，成本上升但问题解决率没有改善。
- **业务与数据范围**：会话状态、工具轨迹、调用参数、解决状态、转人工、时延和 token 成本。数据侧重点采集状态版本、来源、TTL 和会话隔离，并与数据目录、元数据平台、质量平台中的时间、状态和责任人信息对齐。
- **需要回答的问题**：上下文、记忆和中间结果是否准确、过期或污染。
- **关键障碍**：缺少停止条件，工具失败后继续重试，重复信息被反复放入上下文。同时要防止口径变更缺少影响分析把表面指标带偏。
- **处理过程**：增加任务状态机、最大步数、工具级超时与缓存，连续失败转人工，并按意图分层评估。实施时把“任务必须有完成条件、最大步数、超时、预算和转人工规则”写成上线检查项，并为每一项保留日志、样本和负责人。
- **验证方式**：复合案例以一次解决率、平均步数、P95 和单位任务成本验收。验收至少同时看主指标、状态版本、来源、TTL 和会话隔离和一次故障回放，不能只截取优化后最快的一次结果。
- **可迁移结论**：遇到类似标题时，先按“把任务目标、规划、工具、状态、权限、预算、评估和人工接管设计成受控系统，不允许模型绕过服务端授权直接执行高风险动作。”建立判断顺序，再决定是否调整代码、资源、口径或组织流程。

| --- | --- | --- |

2. 专题检查：任务必须有完成条件、最大步数、超时、预算和转人工规则
3. 专题检查：工具在服务端做身份、参数、对象、环境和权限校验
4. 专题检查：完整记录计划、工具参数、结果、错误、版本和人工操作
5. 专题检查：对越权、提示注入、循环调用、错误重试和数据泄露做专门测试
6. 明确“Agent权限审计与责任边界”服务的使用者、决策动作和不做范围，并把成功标准写成可观察指标。
7. 为数据资产、字段、指标分别确认主键、时间和状态，画出从源系统到结果的链路。
8. 先做字段血缘和质量画像，检查资产责任唯一、规则可执行且可解释、问题分级明确。
9. 用同周期基线和至少两个维度拆解问题，避免只比较一个异常周。
10. 抽取正常、异常和边界样本回查原始业务单据，记录抽样方法与结论。
11. 选择一种代码实现并保留参数、版本、执行日志和结果快照，确保别人可以复跑。
12. 上线前定义告警阈值、回滚条件和责任人；上线后按周观察主指标与护栏指标。
13. 复盘时区分数据问题、业务变化、方案偏差和外部因素，并把改进项转成有时限的任务。

### 扩展代码一：从Agent权限审计与责任边界回到可核对明细

```sql
-- Agent权限审计与责任边界：发布前质量画像
SELECT
  'agent' AS subject_key,
  stat_date,
  COUNT(*) AS row_cnt,
  COUNT(DISTINCT event_id) AS distinct_event_cnt,
  SUM(CASE WHEN event_id IS NULL THEN 1 ELSE 0 END) AS null_event_cnt,
  SUM(CASE WHEN check_time < business_time THEN 1 ELSE 0 END) AS time_reverse_cnt,
  SUM(CASE WHEN status NOT IN ('valid', 'completed', 'cancelled') THEN 1 ELSE 0 END) AS invalid_status_cnt,
  ROUND(COUNT(*) * 1.0 / NULLIF(COUNT(DISTINCT event_id), 0), 4) AS duplication_ratio
FROM fact_data_quality_result
WHERE stat_date BETWEEN :start_date AND :end_date
GROUP BY stat_date
HAVING SUM(CASE WHEN event_id IS NULL THEN 1 ELSE 0 END) > 0
    OR SUM(CASE WHEN check_time < business_time THEN 1 ELSE 0 END) > 0
    OR COUNT(*) <> COUNT(DISTINCT event_id)
ORDER BY stat_date;

-- 至少人工核对一次：资产责任唯一；规则可执行且可解释；问题分级明确。
```

### 扩展代码二：把Agent权限审计与责任边界的验收证据写成门禁

```python
from datetime import date
from hashlib import sha256

import pandas as pd

SUBJECT = "Agent权限审计与责任边界"
BLOCKING_RULES = ["资产责任唯一","规则可执行且可解释","问题分级明确"]


def validate_release(frame: pd.DataFrame, start: date, end: date) -> dict:
    scoped = frame.loc[
        frame["event_date"].between(pd.Timestamp(start), pd.Timestamp(end))
        & (frame["subject_key"] == "agent")
    ].copy()
    checks = {
        "has_rows": len(scoped) > 0,
        "event_id_unique": not scoped["event_id"].duplicated().any(),
        "entity_key_complete": scoped["entity_key"].notna().all(),
        "event_time_present": scoped["event_time"].notna().all(),
        "scope_matches": scoped["subject_key"].nunique() == 1,
    }
    payload = f"{SUBJECT}|{start}|{end}|{len(scoped)}|{sorted(checks.items())}"
    return {
        "subject": SUBJECT,
        "rows": len(scoped),
        "checks": checks,
        "blocking_rules": BLOCKING_RULES,
        "release_allowed": all(checks.values()),
        "evidence_hash": sha256(payload.encode("utf-8")).hexdigest(),
    }
```

示例中的行数、时间戳和版本号均为占位值。生产实现应从调度参数、数据契约和质量平台读取真实信息，并将失败结果回写到工单、发布系统和责任人，而不是只打印在日志中。
