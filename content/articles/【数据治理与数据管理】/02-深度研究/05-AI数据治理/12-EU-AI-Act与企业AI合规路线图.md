# EU-AI-Act与企业AI合规路线图

> [!warning] 核心判断
> “EU-AI-Act与企业AI合规路线图”在会议里常常只有一句话，落到数据团队却会展开成口径、主键、时间、状态、权限和交付责任。下面用一个从问题到上线的顺序展开，并穿插三个脱敏的复合案例，帮助你把标题里的知识迁移到真实项目。

## 1. 先判断应治理什么风险

“EU-AI-Act与企业AI合规路线图”通常不是买一个平台就能解决的问题。它至少涉及制度、标准、责任、流程、技术和审计六层。开始前先把风险写成可观察事实：

| 风险问题 | 观察信号 | 可能影响 | 首先核查 |
| --- | --- | --- | --- |
| 定义不一致 | 同名指标多个 SQL、多个业务解释 | 决策冲突、返工 | 指标字典与负责人 |
| 数据不完整 | 分区缺失、关键字段空值 | 报表失真、流程中断 | 采集与任务日志 |
| 责任不清 | 问题工单长期无人认领 | 修复延迟、同类复发 | 资产责任矩阵 |
| 访问过宽 | 长期权限、共享账号、无审计 | 泄漏与合规风险 | 权限清单与访问日志 |
| 变更不可见 | 表结构或逻辑变更无通知 | 下游批量故障 | 血缘与发布记录 |

1. **资产没有负责人**：需要在标准、系统或组织流程中设置对应控制。
2. **规则只告警不闭环**：需要在标准、系统或组织流程中设置对应控制。
3. **口径变更缺少影响分析**：需要在标准、系统或组织流程中设置对应控制。
4. **权限长期累积**：需要在标准、系统或组织流程中设置对应控制。
5. **数据目录与真实血缘脱节**：需要在标准、系统或组织流程中设置对应控制。

治理不是把所有数据都按同一优先级管理。建议依据使用范围、监管要求、决策影响和故障历史划分关键资产，再决定投入。关键资产应有唯一负责人、明确消费者、质量目标、访问策略和变更通知。

一个可执行的数据标准至少包括：

- **业务定义**：业务人员如何理解和适用。
- **技术定义**：字段类型、长度、格式、枚举和空值语义。
- **计算口径**：时间、粒度、分子分母和排除项。
- **权威来源**：哪个系统是事实源，冲突时以谁为准。
- **生命周期**：创建、变更、废弃和归档规则。
- **责任人**：业务负责人、数据负责人、技术负责人和审批人。

资产责任可以使用 RACI：业务负责人对定义负责，数据负责人对实现与质量负责，平台团队对工具和权限负责，安全合规对访问与审计负责，消费者对使用边界负责。只有“责任人”一个字段，没有决策权和时限，问题仍会回到治理团队自己处理。

## 4. 案例一：华南某制造集团

### 案例 1：华南某制造集团的“EU-AI-Act与企业AI合规路线图”现场

这是一个结合公开方法、常见工程故障和脱敏数据构造的复合案例，不对应任何单一企业事实。

- **标题落点**：先确认业务对象和系统边界，再讨论工具或参数。本例把“EU-AI-Act与企业AI合规路线图”映射到“技术选型、路线图与架构演进”中的落地，而不是泛泛讨论概念。
- **触发事件**：多个工厂希望采用不同湖仓产品，集团担心重复平台和长期维护成本。
- **业务与数据范围**：工厂规模、网络、实时需求、数据主权、现有技能和三年预算。数据侧重点采集PoC、灰度、双跑和决策门禁，并与数据目录、元数据平台、质量平台中的时间、状态和责任人信息对齐。
- **需要回答的问题**：试点、迁移、并行、验收和回滚如何安排。
- **关键障碍**：选型只比较存储格式和查询速度，没有计算跨厂治理与运维总成本。同时要防止资产没有负责人把表面指标带偏。
- **处理过程**：区分集团标准能力与工厂本地能力，建立兼容接口和集中元数据，保留例外审批。实施时把“记录被否决方案、决策假设、退出策略和复审日期”写成上线检查项，并为每一项保留日志、样本和负责人。
- **验证方式**：示例架构在标准化与业务灵活性之间设置可量化边界。验收至少同时看主指标、PoC、灰度、双跑和决策门禁和一次故障回放，不能只截取优化后最快的一次结果。
- **可迁移结论**：遇到类似标题时，先按“把业务约束、总拥有成本、团队能力、迁移风险和退出策略放进同一决策框架，避免用功能清单和短期演示做技术选型。”建立判断顺序，再决定是否调整代码、资源、口径或组织流程。

治理项目应先做小范围闭环，不要一开始铺满全公司。选择一个高影响业务域，完成从资产盘点、标准确认、质量规则、问题整改到复盘的完整链路，再复制机制。

### 发布前规则门禁

```python
# EU-AI-Act与企业AI合规路线图：发布前的数据质量与分层检查
import pandas as pd
import numpy as np
import hashlib

TOPIC = "EU-AI-Act与企业AI合规路线图"
TOPIC_KEY = "eu_ai_act_ai"
RULE_ID = "rule_governance_kg4l47"
GUIDE_CHECKS = [
    "选型从真实问题和现状基线出发，不使用厂商演示作为唯一证据",
    "评估功能、性能、总成本、风险、团队能力和迁移工作量",
    "PoC 覆盖真实查询、并发、权限、故障恢复和升级",
    "记录被否决方案、决策假设、退出策略和复审日期"
]
RULES = {
    "required_columns": ["event_id", "asset_id", "check_time", "status"],
    "duplicate_key": "event_id",
    "entity_key": "asset_id",
    "time_field": "check_time",
    "max_duplicate_rate": 0.0006,
    "max_null_rate": 0.004,
    "allowed_status": {"valid", "completed", "cancelled", "refunded"},
}

def validate(frame: pd.DataFrame) -> pd.DataFrame:
    missing = [c for c in RULES["required_columns"] if c not in frame.columns]
    if missing:
        raise ValueError(f"{TOPIC}/{TOPIC_KEY} missing required columns: {missing}")

    checks = []
    checks.append(("duplicate_rate", frame[RULES["duplicate_key"]].duplicated().mean(), RULES["max_duplicate_rate"]))
    checks.append(("entity_null_rate", frame[RULES["entity_key"]].isna().mean(), RULES["max_null_rate"]))
    event_time = pd.to_datetime(frame[RULES["time_field"]], errors="coerce")
    checks.append(("invalid_time_rate", event_time.isna().mean(), 0.0))
    bad_status = (~frame["status"].isin(RULES["allowed_status"])).mean()
    checks.append(("invalid_status_rate", bad_status, 0.0))

    result = pd.DataFrame(checks, columns=["check_name", "value", "threshold"])
    result["rule_id"] = RULE_ID + "." + result["check_name"]
    result["topic"] = TOPIC
    result["topic_key"] = TOPIC_KEY
    result["passed"] = result["value"].le(result["threshold"])
    result["sample_fingerprint"] = hashlib.sha1(
        f"{TOPIC}|{RULE_ID}|{len(frame)}".encode("utf-8")
    ).hexdigest()[:12]
    return result

def diagnose(frame: pd.DataFrame) -> pd.DataFrame:
    return (
        frame.assign(stat_date=pd.to_datetime(frame[RULES["time_field"]]).dt.date)
        .groupby(["stat_date", "status"], dropna=False)
        .agg(
            event_cnt=(RULES["duplicate_key"], "nunique"),
            entity_cnt=(RULES["entity_key"], "nunique"),
        )
        .reset_index()
        .assign(topic=TOPIC, topic_key=TOPIC_KEY, rule_id=RULE_ID)
        .sort_values("stat_date")
    )

def release_gate(result: pd.DataFrame) -> None:
    failed = result.loc[~result["passed"], ["topic_key", "check_name", "value", "threshold"]]
    if not failed.empty:
        raise RuntimeError({"topic": TOPIC, "failed_checks": failed.to_dict("records")})
```

### 治理对象与风险分层 SQL

```sql
-- EU-AI-Act与企业AI合规路线图：留存同期群诊断（规则类型 × 严重等级）
WITH scoped AS (
  SELECT
    asset_id AS entity_key,
    event_id,
    check_time AS event_date,
    dimension_value AS primary_dim,
    stage_code AS secondary_dim,
    metric_value,
    status
  FROM fact_data_quality_result
  WHERE check_time >= DATE '2026-08-01'
    AND check_time <  DATE '2026-11-01'
    AND subject_key = 'eu_ai_act_ai'
    AND is_deleted = 0
),
dedup AS (
  SELECT *
  FROM (
    SELECT
      scoped.*,
      ROW_NUMBER() OVER (
        PARTITION BY event_id
        ORDER BY event_date DESC
      ) AS version_no
    FROM scoped
  ) ranked
  WHERE version_no = 1
),
grouped AS (
  SELECT
    primary_dim,
    secondary_dim,
    COUNT(DISTINCT entity_key) AS entity_cnt,
    COUNT(DISTINCT event_id) AS event_cnt,
    SUM(metric_value) AS metric_sum,
    AVG(metric_value) AS metric_avg
  FROM dedup
  WHERE status IN ('valid', 'completed')
  GROUP BY primary_dim, secondary_dim
),
contribution AS (
  SELECT
    *,
    metric_sum * 1.0 / NULLIF(SUM(metric_sum) OVER (PARTITION BY secondary_dim), 0) AS contribution_ratio,
    metric_avg - AVG(metric_avg) OVER (PARTITION BY secondary_dim) AS delta_to_peer
  FROM grouped
)
SELECT
  '平均修复时长' AS checked_metric,
  primary_dim,
  secondary_dim,
  entity_cnt,
  event_cnt,
  ROUND(metric_sum, 4) AS metric_sum,
  ROUND(contribution_ratio, 4) AS contribution_ratio,
  ROUND(delta_to_peer, 4) AS delta_to_peer
FROM contribution
ORDER BY ABS(delta_to_peer) DESC, entity_cnt DESC;
```

规则设计要同时考虑三件事：能否自动执行、误报成本是否可接受、失败后谁来处理。只写“不能为空”不够，必须明确哪类对象允许为空、谁能在何种情况下豁免、豁免多久、是否需要审批和复核。

建议把规则分成四级：

1. **阻断**：涉及监管、资金、身份或核心发布，失败即停止。
2. **严重告警**：影响大但可先隔离，要求在约定时间内响应。
3. **观察告警**：可能是正常业务变化，先记录趋势。
4. **探索检查**：尚未形成稳定阈值，仅用于发现异常模式。

## 7. 权限、安全与审计

围绕“EU-AI-Act与企业AI合规路线图”，权限治理至少应回答：

- 谁能申请、谁审批、审批依据是什么？
- 权限是否按角色、数据级别和用途最小化？
- 临时权限何时收回，离职和转岗是否自动处理？
- 查询、下载和导出是否留痕，异常访问如何发现？
- 脱敏、加密、水印和审计日志是否与数据类型匹配？

敏感字段不应通过“复制一份测试数据”绕过问题。更合适的做法是分级脱敏、合成数据或受控计算环境。所有示例和代码都不应包含真实身份、账号、密钥、客户名单或未公开经营数据。

### 案例 4：EU-AI-Act与企业AI合规路线图失败后如何做到可恢复

一次例行发布后，负责“EU-AI-Act与企业AI合规路线图”的小组收到下游反馈：数字和源系统对不上，但任务本身全部成功。团队决定围绕“故障恢复与可回放”做一次完整回放。 下面的组织、规模和结果均为公开方法结合常见工作场景形成的脱敏复合示例，不对应任何单一企业事实。

- **为什么要做：** 让错误输入、处理版本、影响分区和恢复结果都能被独立回放和审计。在本场景里，核心风险还包括口径变更缺少影响分析，所以项目从一开始就把“结果能解释”与“结果能产出”放在同等位置。

- **核验证据：** 运行参数、代码版本、输入快照、输出摘要、受影响分区、回滚记录和补数对账。核验时至少抽取正常、边界、重复或迟到、权限拒绝四类样本，并让“数据开发”确认什么结果可以进入下一步。

- **可迁移结论：** 处理“EU-AI-Act与企业AI合规路线图”时，先验证PoC、灰度、双跑和决策门禁，再讨论工具参数或资源调整。若证据只能支持一个假设，就把它标成假设，并为下一轮验证保留对照与样本。

### 案例 7：EU-AI-Act与企业AI合规路线图从源事件到结果的长链路核查

某组织希望用“EU-AI-Act与企业AI合规路线图”支持一次真实决策，但在取数与评审阶段发现，结果表出现缺失或延迟，单看调度状态却显示成功，无法判断问题发生在源端、接入、计算还是服务层。这个案例因此从问题定义重新开始。 下面的组织、规模和结果均为公开方法结合常见工作场景形成的脱敏复合示例，不对应任何单一企业事实。

- **为什么要做：** 把业务发生时间、数据可见时间、任务完成时间和下游消费时间放到同一条证据链。在本场景里，核心风险还包括资产没有负责人，所以项目从一开始就把“结果能解释”与“结果能产出”放在同等位置。
- **对象与数据范围：** 本次只使用为了回答该问题所必需的脱敏范围：质量规则、问题工单及其在问题闭环前后的状态记录；时间窗覆盖一个完整业务周期，并保留行动前后的观察窗口。 主键重点关注rule_id与issue_id，时间上区分业务发生、数据可见和下游采用三个节点。
- **关键异常或争议：** 结果表出现缺失或延迟，单看调度状态却显示成功，无法判断问题发生在源端、接入、计算还是服务层。初看时，工单系统与审计平台的状态字段似乎可以互换，但抽取边界记录后发现二者更新节奏和责任人不同。
- **核验证据：** 源端操作日志、CDC/批次水位、分区清单、任务参数、血缘关系、下游请求日志。核验时至少抽取正常、边界、重复或迟到、权限拒绝四类样本，并让“平台团队”确认什么结果可以进入下一步。
- **处理步骤：** 第一步先冻结“EU-AI-Act与企业AI合规路线图”的当前定义并记录版本；第二步用质量规则明细核对工单系统到审计平台的关联；第三步按业务域与规则类型做基线和结构比较；第四步记录异常样本、规则豁免与人工判断；第五步发布小范围结果，观察规则通过率和护栏指标资产完整率。
- **行动与护栏：** 按时间轴核对每一跳的输入输出计数与水位，先阻断错误结果扩散，再确定重跑范围和补数窗口。专题检查项“记录被否决方案、决策假设、退出策略和复审日期”被写成发布门禁，无法证明数据完整的链路不进入正式发布，优先保留旧版本供下游读取。
- **失败路径：** 看到任务成功就立即补数，却没有确认重复、乱序和迟到事件。这类做法即使暂时让数字看起来一致，也会让后续无法区分“业务变化、数据缺失、规则例外和计算错误”。
- **可迁移结论：** 处理“EU-AI-Act与企业AI合规路线图”时，先验证三年 TCO、人员投入和沉淀资产，再讨论工具参数或资源调整。若证据只能支持一个假设，就把它标成假设，并为下一轮验证保留对照与样本。

> [!note] 本例验收
> 最终动作不是“把报表做出来”，而是由平台团队在明确时限内，根据规则通过率、资产完整率和资产责任唯一决定继续、回退、补查还是转人工。 若资产没有负责人或关键检查项没有证据，结论应停在“待核验”，不能用业务解释替代数据回放。

### 扩展代码一：从EU-AI-Act与企业AI合规路线图回到可核对明细

```sql
-- EU-AI-Act与企业AI合规路线图：状态链与时间间隔核查
WITH ordered_events AS (
  SELECT
    asset_id AS entity_key,
    event_id,
    stage_code,
    check_time AS event_time,
    LAG(stage_code) OVER (
      PARTITION BY asset_id
      ORDER BY check_time, event_id
    ) AS previous_stage,
    LAG(check_time) OVER (
      PARTITION BY asset_id
      ORDER BY check_time, event_id
    ) AS previous_time
  FROM fact_data_quality_result
  WHERE check_time >= :start_date
    AND check_time <  :end_date
    AND subject_key = 'eu_ai_act_ai'
)
SELECT
  entity_key,
  previous_stage,
  stage_code,
  event_time,
  event_time - previous_time AS elapsed,
  CASE
    WHEN event_time < previous_time THEN 'time_reversed'
    WHEN previous_stage = stage_code THEN 'duplicate_stage'
    WHEN previous_stage IS NULL THEN 'missing_prefix'
    ELSE 'candidate_delay'
  END AS exception_type
FROM ordered_events
WHERE event_time < previous_time
   OR previous_stage = stage_code
   OR event_time - previous_time > INTERVAL '1 hour'
ORDER BY exception_type, elapsed DESC;
```

执行这段 SQL 后，不要只看总量。应同时保存查询参数、口径版本、异常对象清单和对应原始记录抽样。若结果依赖人工过滤，要把过滤条件登记为规则，而不是留在个人脚本里。

### 扩展代码二：把EU-AI-Act与企业AI合规路线图的验收证据写成门禁

```python
from dataclasses import dataclass
from datetime import datetime


@dataclass(frozen=True)
class ReleaseEvidence:
    subject: str
    source_watermark: datetime
    output_watermark: datetime
    source_rows: int
    output_rows: int
    duplicate_rows: int
    blocked_rows: int
    code_version: str
    parameter_version: str


def release_gate(evidence: ReleaseEvidence) -> tuple[bool, list[str]]:
    reasons = []
    if evidence.source_watermark != evidence.output_watermark:
        reasons.append("watermark_mismatch")
    if evidence.source_rows != evidence.output_rows:
        reasons.append("row_count_mismatch")
    if evidence.duplicate_rows:
        reasons.append("duplicate_keys")
    if evidence.blocked_rows:
        reasons.append("blocking_quality_rule_failed")
    if not evidence.code_version or not evidence.parameter_version:
        reasons.append("release_provenance_missing")
    return not reasons, reasons


evidence = ReleaseEvidence(
    subject="EU-AI-Act与企业AI合规路线图",
    source_watermark=datetime.fromisoformat("2026-11-06T02:00:00"),
    output_watermark=datetime.fromisoformat("2026-11-06T02:00:00"),
    source_rows=0,
    output_rows=0,
    duplicate_rows=0,
    blocked_rows=0,
    code_version="demo-v1",
    parameter_version="scope-v1",
)
print(release_gate(evidence))
```

示例中的行数、时间戳和版本号均为占位值。生产实现应从调度参数、数据契约和质量平台读取真实信息，并将失败结果回写到工单、发布系统和责任人，而不是只打印在日志中。
