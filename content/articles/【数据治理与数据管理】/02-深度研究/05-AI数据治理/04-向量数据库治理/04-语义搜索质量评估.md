# 语义搜索质量评估

> [!tip] 核心原则
> “语义搜索质量评估”既可能是业务概念，也可能是技术方案，还可能是岗位能力。判断学习是否有效，要看能否在产品使用、账号行为、服务调用、订阅付费、研发交付、系统稳定性和客户支持中做出一个可复现的小闭环。本文用多个案例展示从需求到数据结果，再回到业务行动和复盘的完整路径。

## 1. 从业务任务定义 AI 能力

围绕“语义搜索质量评估”，先把任务写成输入、输出、成功标准和失败边界。不要从“上一套模型”或“接一个聊天框”开始。

| 设计项 | 必须回答的问题 | 错误示例 | 更好做法 |
| --- | --- | --- | --- |
| 用户 | 谁使用，谁复核，谁承担后果 | 所有人都能用 | 按角色和权限明确使用边界 |
| 输入 | 文本、表格、图片还是工具调用 | 把所有数据都塞进上下文 | 只提供任务所需且获授权的数据 |
| 输出 | 分类、生成、检索、SQL 还是动作 | 只要求“回答准确” | 定义可检查的输出结构 |
| 成功 | 任务完成、采纳、质量、时延和成本 | 只看离线准确率 | 离线 + 线上 + 人工复核 |
| 失败 | 无答案、拒答、转人工还是回滚 | 失败也生成看似合理内容 | 明确置信阈值和降级路径 |

## 2. 数据、知识库与版本

| 角色 | 业务对象 | 主键示例 | 在流程中的位置 |
| --- | --- | --- | --- |
| 核心对象 | 账号 | `account_id` | 获客 |
| 过程对象 | 设备 | `device_id` | 注册 |
| 过程对象 | 功能 | `feature_id` | 激活 |

| 专题分析 | 语义搜索质量评估 | `topic_key = 'subject'` | 用于把通用事件收窄到本主题 |

AI 项目的数据治理比传统报表更强调版本和来源。至少记录：

- 数据集和知识文档的来源、授权、时间、负责人和版本。
- 样本标注规则、标注人、抽检结果和争议处理。
- 训练、验证、测试与线上反馈是否隔离。
- 提示词、模型、温度、检索参数和工具权限的版本。
- 输入中的个人信息、商业秘密和敏感字段是否脱敏。

如果“语义搜索质量评估”使用 RAG，文档切片应尊重标题、章节、表格和条款结构；如果使用微调，先证明提示词、检索或流程优化不足；如果使用 Agent，先限制工具白名单和最大执行步数。

## 3. 评估：不要只看一个准确率

| 评估层 | 指标 | 说明 |
| --- | --- | --- |
| 检索 | Hit@K、MRR、版本正确率、权限过滤 | 正确内容是否被召回且可用 |
| 生成 | 引用支持率、事实一致性、完整性 | 回答是否有证据、是否遗漏关键条件 |
| 任务 | 完成率、转人工率、采纳率、重复澄清 | 用户问题是否真的解决 |
| 安全 | 越权、注入、敏感输出、违规动作 | 是否突破权限与安全边界 |
| 工程 | P50/P95 延迟、错误率、并发、成本 | 能否稳定且经济地服务 |
| 业务 | 节省时间、转化、质量、投诉 | 是否带来可解释价值 |

离线集要包含高频问题、长尾问题、边界问题、对抗问题和“应该拒答”的问题。线上评估要按用户、任务和风险等级分层，避免总体平均掩盖高危错误。

## 4. 案例一：华北某金融知识平台

### 案例 1：华北某金融知识平台的“语义搜索质量评估”现场

这是一个结合公开方法、常见工程故障和脱敏数据构造的复合案例，不对应任何单一企业事实。

- **标题落点**：先把正常链路跑通，再人为制造一次失败和恢复。本例把“语义搜索质量评估”映射到“RAG、检索与知识库工程”中的切分，而不是泛泛讨论概念。
- **触发事件**：RAG 上线后响应延迟和成本持续上升，团队不断缩小 TopK 导致漏召回。
- **业务与数据范围**：查询类型、召回数量、重排耗时、模型调用、缓存、答案采纳和成本。数据侧重点采集切片边界、重复率、版本和人工样例，并与埋点平台、账号系统、订阅计费中的时间、状态和责任人信息对齐。
- **需要回答的问题**：切片是否保留标题、条款、表格和上下文。
- **关键障碍**：所有请求走同一长上下文和大模型，简单问题与复杂分析没有分层。同时要防止机器流量误计把表面指标带偏。
- **处理过程**：按问题路由到 FAQ、检索或人工流程，增加缓存、批量重排和上下文预算，保留失败样本回流。实施时把“索引记录文档、切片、Embedding、权限和更新时间版本”写成上线检查项，并为每一项保留日志、样本和负责人。
- **验证方式**：示例工程在质量、P95 和单位成本之间建立可解释取舍。验收至少同时看主指标、切片边界、重复率、版本和人工样例和一次故障回放，不能只截取优化后最快的一次结果。
- **可迁移结论**：遇到类似标题时，先按“把文档解析、切片、索引、召回、重排、权限、引用和评估连成可回归链路，分别衡量检索是否命中、答案是否有据、任务是否完成。”建立判断顺序，再决定是否调整代码、资源、口径或组织流程。

## 5. Python：检索与任务评估

### 检索、Agent 或模型任务实现

```python
from dataclasses import dataclass

@dataclass
class SearchHit:
    chunk_id: str
    document_id: str
    version: str
    lexical_score: float
    vector_score: float
    acl_group: str

def hybrid_search(hits: list[SearchHit], user_groups: set[str], k: int = 5):
    allowed = [hit for hit in hits if hit.acl_group in user_groups | {"public"}]
    reranked = sorted(
        allowed,
        key=lambda hit: 0.45 * hit.lexical_score + 0.55 * hit.vector_score,
        reverse=True,
    )
    deduped, seen = [], set()
    for hit in reranked:
        if hit.document_id not in seen:
            seen.add(hit.document_id)
            deduped.append(hit)
    return deduped[:k]

# 主题："语义搜索质量评估"
# 分别评估解析、Hit@K、引用支持、回答完整、权限过滤、P95 和单次成本。
# 失败样本必须能回到切片、文档版本、召回片段和最终引用。
```

### 标题专属数据与失败分层 SQL

```sql
-- 语义搜索质量评估：同期基线诊断（地区 × 产品）
WITH scoped AS (
  SELECT
    account_id AS entity_key,
    event_id,
    event_time AS event_date,
    dimension_value AS primary_dim,
    stage_code AS secondary_dim,
    metric_value,
    status
  FROM fact_product_event
  WHERE event_time >= DATE '2026-02-01'
    AND event_time <  DATE '2026-05-01'
    AND subject_key = 'subject'
    AND is_deleted = 0
),
dedup AS (
  SELECT *
  FROM (
    SELECT
      scoped.*,
      ROW_NUMBER() OVER (
        PARTITION BY event_id
        ORDER BY event_date DESC
      ) AS version_no
    FROM scoped
  ) ranked
  WHERE version_no = 1
),
grouped AS (
  SELECT
    primary_dim,
    secondary_dim,
    COUNT(DISTINCT entity_key) AS entity_cnt,
    COUNT(DISTINCT event_id) AS event_cnt,
    SUM(metric_value) AS metric_sum,
    AVG(metric_value) AS metric_avg
  FROM dedup
  WHERE status IN ('valid', 'completed')
  GROUP BY primary_dim, secondary_dim
),
contribution AS (
  SELECT
    *,
    metric_sum * 1.0 / NULLIF(SUM(metric_sum) OVER (PARTITION BY secondary_dim), 0) AS contribution_ratio,
    metric_avg - AVG(metric_avg) OVER (PARTITION BY secondary_dim) AS delta_to_peer
  FROM grouped
)
SELECT
  '活跃率' AS checked_metric,
  primary_dim,
  secondary_dim,
  entity_cnt,
  event_cnt,
  ROUND(metric_sum, 4) AS metric_sum,
  ROUND(contribution_ratio, 4) AS contribution_ratio,
  ROUND(delta_to_peer, 4) AS delta_to_peer
FROM contribution
ORDER BY ABS(delta_to_peer) DESC, entity_cnt DESC;
```

示例代码只展示可测试结构。真实系统还需要模型服务、向量库、权限、日志、缓存、限流、敏感检查和人工反馈，不应把安全完全交给提示词。

## 6. 案例二：华东某企业制度知识库

### 案例 2：华东某企业制度知识库的“语义搜索质量评估”现场

这是一个结合公开方法、常见工程故障和脱敏数据构造的复合案例，不对应任何单一企业事实。

- **标题落点**：先把标题中的名词还原成一个可以观测的运行问题。本例把“语义搜索质量评估”映射到“RAG、检索与知识库工程”中的生成，而不是泛泛讨论概念。
- **触发事件**：员工问报销和休假规则时，助手引用了已废止版本，回答语气还很确定。
- **业务与数据范围**：制度文档、版本、生效日期、章节、权限、切片、召回片段和人工反馈。数据侧重点采集引用支持率、事实一致性、完整性和拒答，并与埋点平台、账号系统、订阅计费中的时间、状态和责任人信息对齐。

- **可迁移结论**：遇到类似标题时，先按“把文档解析、切片、索引、召回、重排、权限、引用和评估连成可回归链路，分别衡量检索是否命中、答案是否有据、任务是否完成。”建立判断顺序，再决定是否调整代码、资源、口径或组织流程。

| 层次 | 本文建议 | 关键问题 | 验收证据 |

## 8. 监控、成本与安全

- 监控请求量、延迟、错误码、超时、重试和缓存命中。
- 记录检索文档版本、模型版本、提示词版本和关键参数。
- 对失败分类：检索缺失、上下文过长、工具失败、权限拒绝、模型拒答、结果不合规。
- 设置单位任务成本、每租户预算和异常调用告警。
- 对提示注入、越权、敏感信息和危险动作做专门测试。
- 保留人工复核、转人工、回滚到旧模型和关闭工具的开关。

### 扩展代码一：从语义搜索质量评估回到可核对明细

```sql
-- 语义搜索质量评估：恢复后缺失、重复与跨期检查
WITH expected_keys AS (
  SELECT DISTINCT account_id AS entity_key, event_id
  FROM fact_product_event
  WHERE event_time >= :restore_start
    AND event_time <  :restore_end
    AND subject_key = 'subject'
),
restored_keys AS (
  SELECT account_id AS entity_key, event_id, load_version, loaded_at
  FROM fact_product_event
  WHERE event_time >= :restore_start
    AND event_time <  :restore_end
    AND subject_key = 'subject'
    AND load_version = :restore_version
),
coverage AS (
  SELECT
    (SELECT COUNT(*) FROM expected_keys) AS expected_cnt,
    (SELECT COUNT(*) FROM restored_keys) AS restored_cnt,
    (SELECT COUNT(*) FROM (
      SELECT entity_key, event_id
      FROM restored_keys
      GROUP BY entity_key, event_id
      HAVING COUNT(*) > 1
    ) duplicate_keys) AS duplicated_cnt,
    (SELECT COUNT(*) FROM (
      SELECT e.entity_key, e.event_id
      FROM expected_keys e
      LEFT JOIN restored_keys r USING (entity_key, event_id)
      WHERE r.entity_key IS NULL
    ) missing_keys) AS missing_cnt
)
SELECT *,
  CASE
    WHEN expected_cnt <> restored_cnt OR duplicated_cnt > 0 OR missing_cnt > 0
      THEN 'reject_release'
    ELSE 'accept_restore'
  END AS gate_result
FROM coverage;
```

执行这段 SQL 后，不要只看总量。应同时保存查询参数、口径版本、异常对象清单和对应原始记录抽样。若结果依赖人工过滤，要把过滤条件登记为规则，而不是留在个人脚本里。

```python
KEY = ["entity_key", "event_id"]
AMOUNT_COLUMNS = ["metric_value", "adjustment_value"]


def reconcile(source: pd.DataFrame, result: pd.DataFrame) -> pd.DataFrame:
    def aggregate(frame: pd.DataFrame, side: str) -> pd.DataFrame:
        grouped = (
            frame.groupby("entity_key", dropna=False)
            .agg(
                event_cnt=("event_id", "nunique"),
                metric_sum=("metric_value", "sum"),
                adjustment_sum=("adjustment_value", "sum"),
            )
            .reset_index()
        )
        return grouped.rename(columns={
            "event_cnt": f"{side}_event_cnt",
            "metric_sum": f"{side}_metric_sum",
            "adjustment_sum": f"{side}_adjustment_sum",
        })

    compared = aggregate(source, "source").merge(
        aggregate(result, "result"),
        on="entity_key",
        how="outer",
    )
    compared["metric_diff"] = (
        compared["result_metric_sum"].fillna(0)
        - compared["source_metric_sum"].fillna(0)
    )
    compared["event_diff"] = (
        compared["result_event_cnt"].fillna(0)
        - compared["source_event_cnt"].fillna(0)
    )
    compared["exception"] = compared.apply(
        lambda row: "missing_result" if pd.isna(row["result_metric_sum"])
        else "unexpected_result" if pd.isna(row["source_metric_sum"])
        else "count_diff" if row["event_diff"] != 0
        else "amount_diff",
        axis=1,
    )
    return compared.loc[
        (compared["metric_diff"].abs() > 0) | (compared["event_diff"] != 0)
    ].sort_values("metric_diff", key=lambda values: values.abs(), ascending=False)
```

示例中的行数、时间戳和版本号均为占位值。生产实现应从调度参数、数据契约和质量平台读取真实信息，并将失败结果回写到工单、发布系统和责任人，而不是只打印在日志中。
