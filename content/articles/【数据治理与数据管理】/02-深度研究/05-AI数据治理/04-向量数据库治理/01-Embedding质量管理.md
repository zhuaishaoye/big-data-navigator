# Embedding质量管理

> [!tip] 核心原则
> 讨论“Embedding质量管理”时，最容易犯的错误是直接从工具或报表开始。更有用的顺序是：先看业务链条，再找可观察指标，随后确认数据粒度，最后才选择 SQL、模型或平台组件。本文按这个顺序给出可执行方案和常见的失败样本。

## 1. 从业务任务定义 AI 能力

围绕“Embedding质量管理”，先把任务写成输入、输出、成功标准和失败边界。不要从“上一套模型”或“接一个聊天框”开始。

| 设计项 | 必须回答的问题 | 错误示例 | 更好做法 |
| --- | --- | --- | --- |
| 用户 | 谁使用，谁复核，谁承担后果 | 所有人都能用 | 按角色和权限明确使用边界 |
| 输入 | 文本、表格、图片还是工具调用 | 把所有数据都塞进上下文 | 只提供任务所需且获授权的数据 |
| 输出 | 分类、生成、检索、SQL 还是动作 | 只要求“回答准确” | 定义可检查的输出结构 |
| 成功 | 任务完成、采纳、质量、时延和成本 | 只看离线准确率 | 离线 + 线上 + 人工复核 |
| 失败 | 无答案、拒答、转人工还是回滚 | 失败也生成看似合理内容 | 明确置信阈值和降级路径 |

## 2. 数据、知识库与版本

| 角色 | 业务对象 | 主键示例 | 在流程中的位置 |
| --- | --- | --- | --- |
| 核心对象 | 数据资产 | `asset_id` | 资产盘点 |

AI 项目的数据治理比传统报表更强调版本和来源。至少记录：

- 数据集和知识文档的来源、授权、时间、负责人和版本。
- 样本标注规则、标注人、抽检结果和争议处理。
- 训练、验证、测试与线上反馈是否隔离。
- 提示词、模型、温度、检索参数和工具权限的版本。
- 输入中的个人信息、商业秘密和敏感字段是否脱敏。

如果“Embedding质量管理”使用 RAG，文档切片应尊重标题、章节、表格和条款结构；如果使用微调，先证明提示词、检索或流程优化不足；如果使用 Agent，先限制工具白名单和最大执行步数。

## 3. 评估：不要只看一个准确率

| 评估层 | 指标 | 说明 |
| --- | --- | --- |
| 检索 | Hit@K、MRR、版本正确率、权限过滤 | 正确内容是否被召回且可用 |
| 生成 | 引用支持率、事实一致性、完整性 | 回答是否有证据、是否遗漏关键条件 |
| 任务 | 完成率、转人工率、采纳率、重复澄清 | 用户问题是否真的解决 |
| 安全 | 越权、注入、敏感输出、违规动作 | 是否突破权限与安全边界 |
| 工程 | P50/P95 延迟、错误率、并发、成本 | 能否稳定且经济地服务 |
| 业务 | 节省时间、转化、质量、投诉 | 是否带来可解释价值 |

离线集要包含高频问题、长尾问题、边界问题、对抗问题和“应该拒答”的问题。线上评估要按用户、任务和风险等级分层，避免总体平均掩盖高危错误。

## 4. 案例一：华北某金融知识平台

### 案例 1：华北某金融知识平台的“Embedding质量管理”现场

这是一个结合公开方法、常见工程故障和脱敏数据构造的复合案例，不对应任何单一企业事实。

- **标题落点**：先把正常链路跑通，再人为制造一次失败和恢复。本例把“Embedding质量管理”映射到“RAG、检索与知识库工程”中的生成，而不是泛泛讨论概念。
- **触发事件**：RAG 上线后响应延迟和成本持续上升，团队不断缩小 TopK 导致漏召回。
- **业务与数据范围**：查询类型、召回数量、重排耗时、模型调用、缓存、答案采纳和成本。数据侧重点采集引用支持率、事实一致性、完整性和拒答，并与数据目录、元数据平台、质量平台中的时间、状态和责任人信息对齐。
- **需要回答的问题**：回答是否引用正确片段并覆盖关键条件。
- **关键障碍**：所有请求走同一长上下文和大模型，简单问题与复杂分析没有分层。同时要防止资产没有负责人把表面指标带偏。
- **处理过程**：按问题路由到 FAQ、检索或人工流程，增加缓存、批量重排和上下文预算，保留失败样本回流。实施时把“至少分别评估解析质量、检索命中、引用支持、任务完成和安全”写成上线检查项，并为每一项保留日志、样本和负责人。
- **验证方式**：示例工程在质量、P95 和单位成本之间建立可解释取舍。验收至少同时看主指标、引用支持率、事实一致性、完整性和拒答和一次故障回放，不能只截取优化后最快的一次结果。
- **可迁移结论**：遇到类似标题时，先按“把文档解析、切片、索引、召回、重排、权限、引用和评估连成可回归链路，分别衡量检索是否命中、答案是否有据、任务是否完成。”建立判断顺序，再决定是否调整代码、资源、口径或组织流程。

## 5. Python：检索与任务评估

### 检索、Agent 或模型任务实现

```python
from dataclasses import dataclass

@dataclass
class SearchHit:
    chunk_id: str
    document_id: str
    version: str
    lexical_score: float
    vector_score: float
    acl_group: str

def hybrid_search(hits: list[SearchHit], user_groups: set[str], k: int = 5):
    allowed = [hit for hit in hits if hit.acl_group in user_groups | {"public"}]
    reranked = sorted(
        allowed,
        key=lambda hit: 0.45 * hit.lexical_score + 0.55 * hit.vector_score,
        reverse=True,
    )
    deduped, seen = [], set()
    for hit in reranked:
        if hit.document_id not in seen:
            seen.add(hit.document_id)
            deduped.append(hit)
    return deduped[:k]

# 主题："Embedding质量管理"
# 分别评估解析、Hit@K、引用支持、回答完整、权限过滤、P95 和单次成本。
# 失败样本必须能回到切片、文档版本、召回片段和最终引用。
```

### 标题专属数据与失败分层 SQL

```sql
-- Embedding质量管理：结构贡献诊断（责任团队 × 业务域）
WITH scoped AS (
  SELECT
    asset_id AS entity_key,
    event_id,
    check_time AS event_date,
    dimension_value AS primary_dim,
    stage_code AS secondary_dim,
    metric_value,
    status
  FROM fact_data_quality_result
  WHERE check_time >= DATE '2026-01-01'
    AND check_time <  DATE '2026-04-01'
    AND subject_key = 'embedding'
    AND is_deleted = 0
),
dedup AS (
  SELECT *
  FROM (
    SELECT
      scoped.*,
      ROW_NUMBER() OVER (
        PARTITION BY event_id
        ORDER BY event_date DESC
      ) AS version_no
    FROM scoped
  ) ranked
  WHERE version_no = 1
),
grouped AS (
  SELECT
    primary_dim,
    secondary_dim,
    COUNT(DISTINCT entity_key) AS entity_cnt,
    COUNT(DISTINCT event_id) AS event_cnt,
    SUM(metric_value) AS metric_sum,
    AVG(metric_value) AS metric_avg
  FROM dedup
  WHERE status IN ('valid', 'completed')
  GROUP BY primary_dim, secondary_dim
),
contribution AS (
  SELECT
    *,
    metric_sum * 1.0 / NULLIF(SUM(metric_sum) OVER (PARTITION BY secondary_dim), 0) AS contribution_ratio,
    metric_avg - AVG(metric_avg) OVER (PARTITION BY secondary_dim) AS delta_to_peer
  FROM grouped
)
SELECT
  '规则通过率' AS checked_metric,
  primary_dim,
  secondary_dim,
  entity_cnt,
  event_cnt,
  ROUND(metric_sum, 4) AS metric_sum,
  ROUND(contribution_ratio, 4) AS contribution_ratio,
  ROUND(delta_to_peer, 4) AS delta_to_peer
FROM contribution
ORDER BY ABS(delta_to_peer) DESC, entity_cnt DESC;
```

示例代码只展示可测试结构。真实系统还需要模型服务、向量库、权限、日志、缓存、限流、敏感检查和人工反馈，不应把安全完全交给提示词。

## 6. 案例二：华东某企业制度知识库

### 案例 2：华东某企业制度知识库的“Embedding质量管理”现场

这是一个结合公开方法、常见工程故障和脱敏数据构造的复合案例，不对应任何单一企业事实。

- **标题落点**：先把标题中的名词还原成一个可以观测的运行问题。本例把“Embedding质量管理”映射到“RAG、检索与知识库工程”中的召回，而不是泛泛讨论概念。
- **触发事件**：员工问报销和休假规则时，助手引用了已废止版本，回答语气还很确定。
- **业务与数据范围**：制度文档、版本、生效日期、章节、权限、切片、召回片段和人工反馈。数据侧重点采集Hit@K、MRR、召回文档版本和权限过滤，并与数据目录、元数据平台、质量平台中的时间、状态和责任人信息对齐。
- **需要回答的问题**：关键词、向量和混合检索是否覆盖长尾与同义词。
- **关键障碍**：文档只按固定长度切分，旧版本仍在索引，引用只显示文档名不显示版本和条款。同时要防止规则只告警不闭环把表面指标带偏。
- **处理过程**：按标题与条款结构切片，过滤失效版本和用户权限，答案强制给出版本、条款和更新日期。实施时把“索引记录文档、切片、Embedding、权限和更新时间版本”写成上线检查项，并为每一项保留日志、样本和负责人。
- **验证方式**：示例项目把问题拆成解析、召回、生成和引用四层并建立回归集。验收至少同时看主指标、Hit@K、MRR、召回文档版本和权限过滤和一次故障回放，不能只截取优化后最快的一次结果。
- **可迁移结论**：遇到类似标题时，先按“把文档解析、切片、索引、召回、重排、权限、引用和评估连成可回归链路，分别衡量检索是否命中、答案是否有据、任务是否完成。”建立判断顺序，再决定是否调整代码、资源、口径或组织流程。

## 7. 架构与工程链路

| 层次 | 本文建议 | 关键问题 | 验收证据 |
| --- | --- | --- | --- |
| 数据源 | 数据目录、元数据平台、质量平台 | 权威源、更新频率、主键和权限 | 接口或表清单 |
| 接入 | 批、流或 CDC 按业务时延选择 | 重复、顺序、断点续传和回放 | 延迟与幂等测试 |
| 存储 | 按访问模式选择数据湖、数仓或 OLAP | 分区、格式、生命周期和成本 | 容量与查询评测 |
| 计算 | SQL、Spark、Flink 或 Python 服务 | 粒度、状态、资源和失败恢复 | 压测与执行计划 |
| 治理 | 元数据、质量、血缘、权限 | 责任、规则、影响分析和审计 | 规则结果与变更记录 |
| 服务 | 指标、API、看板或应用 | SLA、缓存、限流和版本 | 监控与验收样例 |

推荐把链路拆成六层：数据与知识准备、检索或特征、模型调用、工具执行、评估与审核、监控与反馈。每层都要有版本、日志和失败处理。Agent 工具调用应在服务端校验参数与权限，不能只依赖模型“自觉”。

## 8. 监控、成本与安全

- 监控请求量、延迟、错误码、超时、重试和缓存命中。
- 记录检索文档版本、模型版本、提示词版本和关键参数。
- 对失败分类：检索缺失、上下文过长、工具失败、权限拒绝、模型拒答、结果不合规。
- 设置单位任务成本、每租户预算和异常调用告警。
- 对提示注入、越权、敏感信息和危险动作做专门测试。
- 保留人工复核、转人工、回滚到旧模型和关闭工具的开关。

## 9. 第三个案例与上线验收

### 案例 3：华南某制造业客服团队的“Embedding质量管理”现场

这是一个结合公开方法、常见工程故障和脱敏数据构造的复合案例，不对应任何单一企业事实。

- **标题落点**：先确认业务对象和系统边界，再讨论工具或参数。本例把“Embedding质量管理”映射到“RAG、检索与知识库工程”中的切分，而不是泛泛讨论概念。
- **触发事件**：设备故障问答在离线演示准确，真实工单中经常找不到型号专用步骤。
- **业务与数据范围**：产品型号、手册章节、故障现象、历史工单、工程师反馈和召回结果。数据侧重点采集切片边界、重复率、版本和人工样例，并与数据目录、元数据平台、质量平台中的时间、状态和责任人信息对齐。
- **需要回答的问题**：切片是否保留标题、条款、表格和上下文。
- **关键障碍**：查询没有使用设备型号过滤，向量相似度偏好通用描述，长表格被错误切碎。同时要防止口径变更缺少影响分析把表面指标带偏。
- **处理过程**：先按型号和安全等级过滤，再做混合召回与重排，表格保留行列结构并加入引用校验。实施时把“按问题类型、租户、风险等级和语言分层评测”写成上线检查项，并为每一项保留日志、样本和负责人。
- **验证方式**：复合案例用 Top3 命中、引用正确率、一次解决率和转人工率评估。验收至少同时看主指标、切片边界、重复率、版本和人工样例和一次故障回放，不能只截取优化后最快的一次结果。
- **可迁移结论**：遇到类似标题时，先按“把文档解析、切片、索引、召回、重排、权限、引用和评估连成可回归链路，分别衡量检索是否命中、答案是否有据、任务是否完成。”建立判断顺序，再决定是否调整代码、资源、口径或组织流程。

| 验收项 | 最低要求 | 证据 |
| --- | --- | --- |
| 任务定义 | 输入输出和失败路径明确 | 产品说明、评测集 |
| 数据授权 | 来源、用途和权限可追溯 | 数据卡、授权记录 |
| 离线评估 | 覆盖常规、边界和拒答 | 评测报告 |
| 线上灰度 | 有对照组和护栏指标 | 实验或灰度记录 |
| 安全 | 越权、注入和敏感输出已测试 | 红队与审计报告 |
| 成本 | 单位请求预算和上限明确 | 账单与调用日志 |
| 运营 | 有反馈、复盘和回滚 | 周报、事故演练 |

1. 先写清“Embedding质量管理”的目标：把文档解析、切片、索引、召回、重排、权限、引用和评估连成可回归链路，分别衡量检索是否命中、答案是否有据、任务是否完成。
2. 专题检查：至少分别评估解析质量、检索命中、引用支持、任务完成和安全
3. 专题检查：索引记录文档、切片、Embedding、权限和更新时间版本
4. 专题检查：按问题类型、租户、风险等级和语言分层评测
5. 专题检查：低置信度、无证据、权限拒绝和工具失败都有明确降级路径
6. 明确“Embedding质量管理”服务的使用者、决策动作和不做范围，并把成功标准写成可观察指标。
7. 为数据资产、字段、指标分别确认主键、时间和状态，画出从源系统到结果的链路。
8. 先做字段血缘和质量画像，检查资产责任唯一、规则可执行且可解释、问题分级明确。
9. 用同周期基线和至少两个维度拆解问题，避免只比较一个异常周。
10. 抽取正常、异常和边界样本回查原始业务单据，记录抽样方法与结论。
11. 选择一种代码实现并保留参数、版本、执行日志和结果快照，确保别人可以复跑。
12. 上线前定义告警阈值、回滚条件和责任人；上线后按周观察主指标与护栏指标。
13. 复盘时区分数据问题、业务变化、方案偏差和外部因素，并把改进项转成有时限的任务。

  stat_date,
  COUNT(*) AS row_cnt,
  COUNT(DISTINCT event_id) AS distinct_event_cnt,
  SUM(CASE WHEN event_id IS NULL THEN 1 ELSE 0 END) AS null_event_cnt,
  SUM(CASE WHEN check_time < business_time THEN 1 ELSE 0 END) AS time_reverse_cnt,
  SUM(CASE WHEN status NOT IN ('valid', 'completed', 'cancelled') THEN 1 ELSE 0 END) AS invalid_status_cnt,

    OR COUNT(*) <> COUNT(DISTINCT event_id)
ORDER BY stat_date;

### 扩展代码二：把Embedding质量管理的验收证据写成门禁

```python
import pandas as pd

KEY = ["entity_key", "event_id"]
AMOUNT_COLUMNS = ["metric_value", "adjustment_value"]


def reconcile(source: pd.DataFrame, result: pd.DataFrame) -> pd.DataFrame:
    def aggregate(frame: pd.DataFrame, side: str) -> pd.DataFrame:
        grouped = (
            frame.groupby("entity_key", dropna=False)
            .agg(
                event_cnt=("event_id", "nunique"),
                metric_sum=("metric_value", "sum"),
                adjustment_sum=("adjustment_value", "sum"),
            )
            .reset_index()
        )
        return grouped.rename(columns={
            "event_cnt": f"{side}_event_cnt",
            "metric_sum": f"{side}_metric_sum",
            "adjustment_sum": f"{side}_adjustment_sum",
        })

    compared = aggregate(source, "source").merge(
        aggregate(result, "result"),
        on="entity_key",
        how="outer",
    )
    compared["metric_diff"] = (
        compared["result_metric_sum"].fillna(0)
        - compared["source_metric_sum"].fillna(0)
    )
    compared["event_diff"] = (
        compared["result_event_cnt"].fillna(0)
        - compared["source_event_cnt"].fillna(0)
    )
    compared["exception"] = compared.apply(
        lambda row: "missing_result" if pd.isna(row["result_metric_sum"])
        else "unexpected_result" if pd.isna(row["source_metric_sum"])
        else "count_diff" if row["event_diff"] != 0
        else "amount_diff",
        axis=1,
    )
    return compared.loc[
        (compared["metric_diff"].abs() > 0) | (compared["event_diff"] != 0)
    ].sort_values("metric_diff", key=lambda values: values.abs(), ascending=False)
```

示例中的行数、时间戳和版本号均为占位值。生产实现应从调度参数、数据契约和质量平台读取真实信息，并将失败结果回写到工单、发布系统和责任人，而不是只打印在日志中。
