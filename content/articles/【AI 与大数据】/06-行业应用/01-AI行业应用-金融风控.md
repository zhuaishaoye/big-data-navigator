# AI行业应用-金融风控

> [!tip] 分析目标
> 一个关于“AI行业应用-金融风控”的结论能不能被信任，取决于它是否能回到原始事件、明确时间和对象，并说明排除了哪些记录。下面不会用单一模板概括所有场景，而是结合金融行业中的多类任务，展示数据建模、代码分析和项目验收之间如何衔接。

## 1. 把主题翻译成可验证的问题

“AI行业应用-金融风控”不能直接等同于“做一张趋势图”。一个可执行的分析问题至少包含对象、时间、比较基准和行动：

> 在【观察周期】内，对【有效对象】按【机构、产品、渠道】比较【逾期率】与【风险拦截率】，判断变化来自结构、行为还是数据口径，并验证【策略动作】是否带来可解释的增量。

在金融行业场景中，用户行为、交易结果和策略曝光经常来自不同系统。先画数据流：

核心银行系统 → 信贷系统 → 支付清算系统 → 反洗钱系统 → CRM → 数据仓库

图中至少要有三个标记：业务事件发生时间、数据可见时间、策略或行动时间。只有三者分开，后续才能判断问题发生在业务、链路还是观察窗口。

## 2. 指标定义与分母检查

| 专题观测面 | 需要回答的问题 | 关键证据 | 判定与动作 |
| --- | --- | --- | --- |
| 任务（本标题优先） | 问题是分类、预测、生成、检索还是动作决策 | 输入输出、成功标准、失败成本 | 无需 AI 时优先规则或简单模型 |
| 部署 | 模型版本、漂移、延迟、成本、回滚和人工接管 | 监控、灰度、日志和事故演练 | 无回滚不进入关键流程 |
| 评估 | 离线、上线和人工评估是否一致 | 基线、时间切分、分群、任务完成和风险 | 高风险错误单独设门槛 |
| 数据 | 样本是否代表业务、是否泄漏、是否获授权 | 数据卡、标签、分群、版本和来源 | 数据不合格不先调模型 |

针对“AI行业应用-金融风控”，建议分别定义诊断指标、结果指标和护栏指标：

- **诊断指标**用于定位流程，例如曝光、有效访问、符合条件对象数和异常节点。
- **结果指标**用于判断是否改善，例如转化、留存、客单、毛利或处理时长。
- **护栏指标**用于防止局部优化伤害整体，例如退款、投诉、成本、公平性和长期留存。

每次计算都问四个问题：分母是谁、对象何时进入分母、例外状态怎么处理、窗口是否足够覆盖行为完成。尤其是敏感数据越权访问；授信金额与借据余额混用；产品口径随组织调整无法比较，任何一项没有解释清楚，指标都可能“看起来合理但无法决策”。

## 3. 方法选择：描述、诊断、预测还是因果

| 目标 | 适合的方法 | 需要的证据 | 不要混淆 |
| --- | --- | --- | --- |
| 描述现状 | 趋势、结构、同期群 | 完整口径、稳定时间窗 | 描述不等于原因 |
| 定位异常 | 分层、贡献度、漏斗、异常检测 | 原始事件、基线和质量检查 | 排名靠前不等于因果 |
| 预测未来 | 时间序列、回归、机器学习 | 时间切分验证、误差成本 | 离线准确率不等于业务收益 |
| 评估策略 | A/B、灰度、准实验 | 对照组、样本量、护栏指标 | 上线前后对比容易混入季节和选择偏差 |

如果问题只是“发生了什么”，先别急着建模；如果问题涉及“采取某策略会怎样”，就必须讨论反事实和识别条件。围绕“AI行业应用-金融风控”，应把观察分析、预测和因果评估的产出分开标注。

## 5. SQL：计算趋势、结构和贡献度

### 趋势、结构与贡献度诊断

```sql
-- AI行业应用-金融风控：留存同期群诊断（渠道 × 风险等级）
WITH scoped AS (
  SELECT
    customer_id AS entity_key,
    event_id,
    event_time AS event_date,
    dimension_value AS primary_dim,
    stage_code AS secondary_dim,
    metric_value,
    status
  FROM fact_finance_event
  WHERE event_time >= DATE '2026-04-01'
    AND event_time <  DATE '2026-07-01'
    AND subject_key = 'ai'
    AND is_deleted = 0
),
dedup AS (
  SELECT *
  FROM (
    SELECT
      scoped.*,
      ROW_NUMBER() OVER (
        PARTITION BY event_id
        ORDER BY event_date DESC
      ) AS version_no
    FROM scoped
  ) ranked
  WHERE version_no = 1
),
grouped AS (
  SELECT
    primary_dim,
    secondary_dim,
    COUNT(DISTINCT entity_key) AS entity_cnt,
    COUNT(DISTINCT event_id) AS event_cnt,
    SUM(metric_value) AS metric_sum,
    AVG(metric_value) AS metric_avg
  FROM dedup
  WHERE status IN ('valid', 'completed')
  GROUP BY primary_dim, secondary_dim
),
contribution AS (
  SELECT
    *,
    metric_sum * 1.0 / NULLIF(SUM(metric_sum) OVER (PARTITION BY secondary_dim), 0) AS contribution_ratio,
    metric_avg - AVG(metric_avg) OVER (PARTITION BY secondary_dim) AS delta_to_peer
  FROM grouped
)
SELECT
  '客户流失率' AS checked_metric,
  primary_dim,
  secondary_dim,
  entity_cnt,
  event_cnt,
  ROUND(metric_sum, 4) AS metric_sum,
  ROUND(contribution_ratio, 4) AS contribution_ratio,
  ROUND(delta_to_peer, 4) AS delta_to_peer
FROM contribution
ORDER BY ABS(delta_to_peer) DESC, entity_cnt DESC;
```

示例 SQL 只表达计算逻辑。实际实施应加入分区条件、业务状态过滤、时区和主题范围，并在结果中保留口径版本。

### 专题验证代码

```python
import pandas as pd
from sklearn.metrics import roc_auc_score, f1_score
from sklearn.model_selection import TimeSeriesSplit

TOPIC = "AI行业应用-金融风控"
EXPERIMENT_ID = "g_ai_foundation_mrvqvf"

def evaluate_time_ordered(
    frame: pd.DataFrame,
    features: list[str],
    target: str,
    train_model,
    prediction_to_label,
) -> list[dict]:
    ordered = frame.sort_values(["event_date", "entity_id"]).reset_index(drop=True)
    results = []
    for fold, (train_idx, test_idx) in enumerate(TimeSeriesSplit(n_splits=4, gap=7).split(ordered), 1):
        train = ordered.iloc[train_idx]
        test = ordered.iloc[test_idx]
        if train[target].nunique() < 2 or test[target].nunique() < 2:
            continue
        model = train_model()
        model.fit(train[features], train[target])
        score = model.predict_proba(test[features])[:, 1]
        label = prediction_to_label(score)
        results.append({
            "experiment_id": EXPERIMENT_ID,
            "topic": TOPIC,
            "fold": fold,
            "train_end": str(train["event_date"].max().date()),
            "test_start": str(test["event_date"].min().date()),
            "auc": round(roc_auc_score(test[target], score), 4),
            "f1_at_threshold": round(f1_score(test[target], label), 4),
        })
    return results
```

## 8. 异常、偏差与常见误区

- **辛普森悖论**：总体改善但每个分组都变差，可能由对象结构变化造成。
- **幸存者偏差**：只分析完成流程的对象，忽略中途流失和中止。
- **分母漂移**：渠道口径、登录状态、版本或活动范围变化，改变可比性。
- **回传延迟**：当天数据未回补，导致近期效果被系统性低估。
- **多重比较**：反复寻找显著分组，实际只是随机波动。
- **行动偏差**：只报告支持既定方案的结果，忽略反例和护栏指标。

围绕“AI行业应用-金融风控”，应预先写出至少三条反例检查。比如方案是否说明了成本、边界和停止条件、上线后是否有人负责观察和复盘，以及 关键口径是否经过业务与技术共同确认。

### 扩展代码一：从AI行业应用-金融风控回到可核对明细

```sql
-- AI行业应用-金融风控：行动前后与分组增量
WITH scoped AS (
  SELECT
    customer_id AS entity_key,
    渠道 AS decision_group,
    event_time AS event_date,
    metric_value,
    CASE
      WHEN event_time <  :action_date THEN 'before'
      ELSE 'after'
    END AS period_label
  FROM fact_finance_event
  WHERE event_time >= :analysis_start
    AND event_time <  :analysis_end
    AND subject_key = 'ai'
),
grouped AS (
  SELECT
    decision_group,
    period_label,
    COUNT(DISTINCT entity_key) AS entity_cnt,
    AVG(metric_value) AS metric_avg,
    SUM(metric_value) AS metric_sum
  FROM scoped
  GROUP BY decision_group, period_label
),
compared AS (
  SELECT
    decision_group,
    MAX(CASE WHEN period_label = 'before' THEN metric_avg END) AS before_avg,
    MAX(CASE WHEN period_label = 'after' THEN metric_avg END) AS after_avg,
    MAX(CASE WHEN period_label = 'before' THEN entity_cnt END) AS before_cnt,
    MAX(CASE WHEN period_label = 'after' THEN entity_cnt END) AS after_cnt
  FROM grouped
  GROUP BY decision_group
)
SELECT
  decision_group,
  before_avg,
  after_avg,
  after_avg - before_avg AS naive_delta,
  '风险拦截率' AS metric_name,
  '用简单基线和业务价值证明需要 AI' AS required_evidence
FROM compared
WHERE before_cnt >= 30 AND after_cnt >= 30
ORDER BY ABS(after_avg - before_avg) DESC;
```

```python
from dataclasses import dataclass
from datetime import datetime


@dataclass(frozen=True)
class ReleaseEvidence:
    subject: str
    source_watermark: datetime
    output_watermark: datetime
    source_rows: int
    output_rows: int
    duplicate_rows: int
    blocked_rows: int
    code_version: str
    parameter_version: str


def release_gate(evidence: ReleaseEvidence) -> tuple[bool, list[str]]:
    reasons = []
    if evidence.source_watermark != evidence.output_watermark:
        reasons.append("watermark_mismatch")
    if evidence.source_rows != evidence.output_rows:
        reasons.append("row_count_mismatch")
    if evidence.duplicate_rows:
        reasons.append("duplicate_keys")
    if evidence.blocked_rows:
        reasons.append("blocking_quality_rule_failed")
    if not evidence.code_version or not evidence.parameter_version:
        reasons.append("release_provenance_missing")
    return not reasons, reasons


evidence = ReleaseEvidence(
    subject="AI行业应用-金融风控",
    source_watermark=datetime.fromisoformat("2026-11-06T02:00:00"),
    output_watermark=datetime.fromisoformat("2026-11-06T02:00:00"),
    source_rows=0,
    output_rows=0,
    duplicate_rows=0,
    blocked_rows=0,
    code_version="demo-v1",
    parameter_version="scope-v1",
)
print(release_gate(evidence))
```
