# AI数据标注与数据飞轮

> [!warning] 核心判断
> 把“AI数据标注与数据飞轮”放进训练数据准备、模型实验、RAG 检索、Agent 编排、离线评估和线上监控，真正困难的通常不是解释名词，而是把它变成一条能被核对、能被复现、也能推动行动的工程链路。本文不追求堆满概念，而是围绕这个主题拆出业务对象、数据粒度、典型故障、代码验证和验收方式。

## 1. 先判断应治理什么风险

“AI数据标注与数据飞轮”通常不是买一个平台就能解决的问题。它至少涉及制度、标准、责任、流程、技术和审计六层。开始前先把风险写成可观察事实：

| 风险问题 | 观察信号 | 可能影响 | 首先核查 |
| --- | --- | --- | --- |
| 定义不一致 | 同名指标多个 SQL、多个业务解释 | 决策冲突、返工 | 指标字典与负责人 |
| 数据不完整 | 分区缺失、关键字段空值 | 报表失真、流程中断 | 采集与任务日志 |
| 责任不清 | 问题工单长期无人认领 | 修复延迟、同类复发 | 资产责任矩阵 |
| 访问过宽 | 长期权限、共享账号、无审计 | 泄漏与合规风险 | 权限清单与访问日志 |
| 变更不可见 | 表结构或逻辑变更无通知 | 下游批量故障 | 血缘与发布记录 |

1. **训练与线上样本泄漏**：需要在标准、系统或组织流程中设置对应控制。
2. **模型版本不可追溯**：需要在标准、系统或组织流程中设置对应控制。
3. **评测与业务目标脱节**：需要在标准、系统或组织流程中设置对应控制。
4. **RAG 召回污染**：需要在标准、系统或组织流程中设置对应控制。
5. **Agent 越权调用**：需要在标准、系统或组织流程中设置对应控制。

治理不是把所有数据都按同一优先级管理。建议依据使用范围、监管要求、决策影响和故障历史划分关键资产，再决定投入。关键资产应有唯一负责人、明确消费者、质量目标、访问策略和变更通知。

## 3. 资产、标准与责任矩阵

| 角色 | 业务对象 | 主键示例 | 在流程中的位置 |
| --- | --- | --- | --- |
| 核心对象 | 数据集 | `dataset_id` | 问题定义 |
| 过程对象 | 样本 | `sample_id` | 数据准备 |
| 过程对象 | 模型版本 | `model_version` | 方案设计 |
| 结果对象 | 应用请求 | `request_id` | 实验评估 |
| 结果对象 | 评测案例 | `eval_case_id` | 上线灰度 |
| 专题分析 | AI数据标注与数据飞轮 | `topic_key = 'ai'` | 用于把通用事件收窄到本主题 |

一个可执行的数据标准至少包括：

- **业务定义**：业务人员如何理解和适用。
- **技术定义**：字段类型、长度、格式、枚举和空值语义。
- **计算口径**：时间、粒度、分子分母和排除项。
- **权威来源**：哪个系统是事实源，冲突时以谁为准。
- **生命周期**：创建、变更、废弃和归档规则。
- **责任人**：业务负责人、数据负责人、技术负责人和审批人。

资产责任可以使用 RACI：业务负责人对定义负责，数据负责人对实现与质量负责，平台团队对工具和权限负责，安全合规对访问与审计负责，消费者对使用边界负责。只有“责任人”一个字段，没有决策权和时限，问题仍会回到治理团队自己处理。

## 4. 案例一：华东某医疗 AI 团队

### 案例 1：华东某医疗 AI 团队的“AI数据标注与数据飞轮”现场

这是一个结合公开方法、常见工程故障和脱敏数据构造的复合案例，不对应任何单一企业事实。

- **标题落点**：先把标题中的名词还原成一个可以观测的运行问题。本例把“AI数据标注与数据飞轮”映射到“AI 数据治理、合规与可解释性”中的版本，而不是泛泛讨论概念。
- **触发事件**：模型在总体测试集表现良好，但老年与罕见病人群错误率明显更高。
- **业务与数据范围**：影像、病历、年龄、疾病亚型、标注来源、训练版本和分群评估结果。数据侧重点采集版本标识、变更记录、回放和血缘，并与数据仓库、特征平台、向量数据库中的时间、状态和责任人信息对齐。
- **需要回答的问题**：数据、Prompt、特征、模型和评测能否互相对应。
- **关键障碍**：评测集人群结构失衡，数据卡没有记录排除标准。同时要防止训练与线上样本泄漏把表面指标带偏。
- **处理过程**：补充分群样本和专家复核，建立数据卡与模型卡，发布前检查弱势群体指标和错误类型。实施时把“训练、评测和生产数据记录来源、授权、用途、版本和负责人”写成上线检查项，并为每一项保留日志、样本和负责人。
- **验证方式**：示例治理将总体准确率改为分群效果、风险差异和人工复核共同验收。验收至少同时看主指标、版本标识、变更记录、回放和血缘和一次故障回放，不能只截取优化后最快的一次结果。
- **可迁移结论**：遇到类似标题时，先按“为 AI 数据建立来源、授权、质量、版本、偏差、隐私、血缘和使用反馈的控制链，让模型效果与风险都能解释和追溯。”建立判断顺序，再决定是否调整代码、资源、口径或组织流程。

治理项目应先做小范围闭环，不要一开始铺满全公司。选择一个高影响业务域，完成从资产盘点、标准确认、质量规则、问题整改到复盘的完整链路，再复制机制。

## 5. 规则与代码：让控制可执行

### 发布前规则门禁

```python
# AI数据标注与数据飞轮：发布前的数据质量与分层检查
import pandas as pd
import numpy as np
import hashlib

TOPIC = "AI数据标注与数据飞轮"
TOPIC_KEY = "ai"
RULE_ID = "rule_ai_1uaj3u0"
GUIDE_CHECKS = [
    "训练、评测和生产数据记录来源、授权、用途、版本和负责人",
    "按人群、场景和风险等级评估质量与偏差，不只报告总体平均",
    "数据、Prompt、特征、索引、模型和评测版本可以互相对应和回放",
    "建立隐私、越权、错误信息、滥用和人工复核控制"
]
RULES = {
    "required_columns": ["event_id", "dataset_id", "request_time", "status"],
    "duplicate_key": "event_id",
    "entity_key": "dataset_id",
    "time_field": "request_time",
    "max_duplicate_rate": 0.0006,
    "max_null_rate": 0.005,
    "allowed_status": {"valid", "completed", "cancelled", "refunded"},
}

def validate(frame: pd.DataFrame) -> pd.DataFrame:
    missing = [c for c in RULES["required_columns"] if c not in frame.columns]
    if missing:
        raise ValueError(f"{TOPIC}/{TOPIC_KEY} missing required columns: {missing}")

    checks = []
    checks.append(("duplicate_rate", frame[RULES["duplicate_key"]].duplicated().mean(), RULES["max_duplicate_rate"]))
    checks.append(("entity_null_rate", frame[RULES["entity_key"]].isna().mean(), RULES["max_null_rate"]))
    event_time = pd.to_datetime(frame[RULES["time_field"]], errors="coerce")
    checks.append(("invalid_time_rate", event_time.isna().mean(), 0.0))
    bad_status = (~frame["status"].isin(RULES["allowed_status"])).mean()
    checks.append(("invalid_status_rate", bad_status, 0.0))

    result = pd.DataFrame(checks, columns=["check_name", "value", "threshold"])
    result["rule_id"] = RULE_ID + "." + result["check_name"]
    result["topic"] = TOPIC
    result["topic_key"] = TOPIC_KEY
    result["passed"] = result["value"].le(result["threshold"])
    result["sample_fingerprint"] = hashlib.sha1(
        f"{TOPIC}|{RULE_ID}|{len(frame)}".encode("utf-8")
    ).hexdigest()[:12]
    return result

def diagnose(frame: pd.DataFrame) -> pd.DataFrame:
    return (
        frame.assign(stat_date=pd.to_datetime(frame[RULES["time_field"]]).dt.date)
        .groupby(["stat_date", "status"], dropna=False)
        .agg(
            event_cnt=(RULES["duplicate_key"], "nunique"),
            entity_cnt=(RULES["entity_key"], "nunique"),
        )
        .reset_index()
        .assign(topic=TOPIC, topic_key=TOPIC_KEY, rule_id=RULE_ID)
        .sort_values("stat_date")
    )

def release_gate(result: pd.DataFrame) -> None:
    failed = result.loc[~result["passed"], ["topic_key", "check_name", "value", "threshold"]]
    if not failed.empty:
        raise RuntimeError({"topic": TOPIC, "failed_checks": failed.to_dict("records")})

# 生产化时把结果写入质量平台，并携带批次、分区、代码版本、规则版本和处理工单。
```

### 治理对象与风险分层 SQL

```sql
-- AI数据标注与数据飞轮：结构贡献诊断（数据来源 × 业务场景）
WITH scoped AS (
  SELECT
    dataset_id AS entity_key,
    event_id,
    request_time AS event_date,
    dimension_value AS primary_dim,
    stage_code AS secondary_dim,
    metric_value,
    status
  FROM fact_ai_request
  WHERE request_time >= DATE '2026-01-01'
    AND request_time <  DATE '2026-04-01'
    AND subject_key = 'ai'
    AND is_deleted = 0
),
dedup AS (
  SELECT *
  FROM (
    SELECT
      scoped.*,
      ROW_NUMBER() OVER (
        PARTITION BY event_id
        ORDER BY event_date DESC
      ) AS version_no
    FROM scoped
  ) ranked
  WHERE version_no = 1
),
grouped AS (
  SELECT
    primary_dim,
    secondary_dim,
    COUNT(DISTINCT entity_key) AS entity_cnt,
    COUNT(DISTINCT event_id) AS event_cnt,
    SUM(metric_value) AS metric_sum,
    AVG(metric_value) AS metric_avg
  FROM dedup
  WHERE status IN ('valid', 'completed')
  GROUP BY primary_dim, secondary_dim
),
contribution AS (
  SELECT
    *,
    metric_sum * 1.0 / NULLIF(SUM(metric_sum) OVER (PARTITION BY secondary_dim), 0) AS contribution_ratio,
    metric_avg - AVG(metric_avg) OVER (PARTITION BY secondary_dim) AS delta_to_peer
  FROM grouped
)
SELECT
  '任务成功率' AS checked_metric,
  primary_dim,
  secondary_dim,
  entity_cnt,
  event_cnt,
  ROUND(metric_sum, 4) AS metric_sum,
  ROUND(contribution_ratio, 4) AS contribution_ratio,
  ROUND(delta_to_peer, 4) AS delta_to_peer
FROM contribution
ORDER BY ABS(delta_to_peer) DESC, entity_cnt DESC;
```

规则设计要同时考虑三件事：能否自动执行、误报成本是否可接受、失败后谁来处理。只写“不能为空”不够，必须明确哪类对象允许为空、谁能在何种情况下豁免、豁免多久、是否需要审批和复核。

建议把规则分成四级：

1. **阻断**：涉及监管、资金、身份或核心发布，失败即停止。
2. **严重告警**：影响大但可先隔离，要求在约定时间内响应。
3. **观察告警**：可能是正常业务变化，先记录趋势。
4. **探索检查**：尚未形成稳定阈值，仅用于发现异常模式。

### 案例 2：华南某客服 AI 团队的“AI数据标注与数据飞轮”现场

- **标题落点**：先确认业务对象和系统边界，再讨论工具或参数。本例把“AI数据标注与数据飞轮”映射到“AI 数据治理、合规与可解释性”中的质量，而不是泛泛讨论概念。

治理指标不要只统计“生成了多少文档、接入了多少资产”。更值得观察的是规则覆盖的关键资产、问题发现前移比例、问题复发率、变更影响分析耗时和业务是否愿意使用。

## 7. 权限、安全与审计

围绕“AI数据标注与数据飞轮”，权限治理至少应回答：

- 谁能申请、谁审批、审批依据是什么？
- 权限是否按角色、数据级别和用途最小化？
- 临时权限何时收回，离职和转岗是否自动处理？
- 查询、下载和导出是否留痕，异常访问如何发现？
- 脱敏、加密、水印和审计日志是否与数据类型匹配？

敏感字段不应通过“复制一份测试数据”绕过问题。更合适的做法是分级脱敏、合成数据或受控计算环境。所有示例和代码都不应包含真实身份、账号、密钥、客户名单或未公开经营数据。

## 8. 第三个案例：华北某政务问答团队

### 案例 3：华北某政务问答团队的“AI数据标注与数据飞轮”现场

这是一个结合公开方法、常见工程故障和脱敏数据构造的复合案例，不对应任何单一企业事实。

- **标题落点**：先把正常链路跑通，再人为制造一次失败和恢复。本例把“AI数据标注与数据飞轮”映射到“AI 数据治理、合规与可解释性”中的来源，而不是泛泛讨论概念。
- **触发事件**：生成式问答引用了过期政策，并可能包含个人信息。
- **业务与数据范围**：政策版本、权限、问题、检索片段、输出、敏感检测和人工反馈。数据侧重点采集数据卡、授权依据、采集时间和用途，并与数据仓库、特征平台、向量数据库中的时间、状态和责任人信息对齐。
- **需要回答的问题**：数据从哪里来、是否授权、能否用于训练或评测。
- **关键障碍**：知识更新没有失效机制，日志中保存了原始敏感文本。同时要防止评测与业务目标脱节把表面指标带偏。
- **处理过程**：建立政策有效期与来源校验，日志脱敏，输出前做敏感和引用检查，高风险问题转人工。实施时把“数据、Prompt、特征、索引、模型和评测版本可以互相对应和回放”写成上线检查项，并为每一项保留日志、样本和负责人。
- **验证方式**：示例项目以引用正确率、过期命中率、敏感输出率和转人工率评估。验收至少同时看主指标、数据卡、授权依据、采集时间和用途和一次故障回放，不能只截取优化后最快的一次结果。

- **关键异常或争议：** 分析结果本身可以访问，但派生字段、导出文件和临时表扩大了敏感数据范围，现有流程没有及时识别。初看时，监控平台与权限审计的状态字段似乎可以互换，但抽取边界记录后发现二者更新节奏和责任人不同。
- **核验证据：** 分类分级、授权记录、字段血缘、访问日志、导出清单、脱敏规则和过期清理记录。核验时至少抽取正常、边界、重复或迟到、权限拒绝四类样本，并让“平台工程师”确认什么结果可以进入下一步。
- **处理步骤：** 第一步先冻结“AI数据标注与数据飞轮”的当前定义并记录版本；第二步用应用请求明细核对监控平台到权限审计的关联；第三步按模型版本与数据来源做基线和结构比较；第四步记录异常样本、规则豁免与人工判断；第五步发布小范围结果，观察答案采纳率和护栏指标P95 延迟。
- **行动与护栏：** 按任务拆分数据集与角色，使用最小字段和临时授权，发布前检查派生表与导出是否出现敏感扩散。专题检查项“建立隐私、越权、错误信息、滥用和人工复核控制”被写成发布门禁，高风险字段缺少授权、脱敏或审计时不进入分析环境，紧急访问必须到期自动回收。
- **失败路径：** 把“内网可访问”当成“业务已授权”，或者用永久大权限账号支撑临时分析。这类做法即使暂时让数字看起来一致，也会让后续无法区分“业务变化、数据缺失、规则例外和计算错误”。
- **可迁移结论：** 处理“AI数据标注与数据飞轮”时，先验证红队、审计、人工复核和事故记录，再讨论工具参数或资源调整。若证据只能支持一个假设，就把它标成假设，并为下一轮验证保留对照与样本。

> [!note] 本例验收
> 最终动作不是“把报表做出来”，而是由平台工程师在明确时限内，根据答案采纳率、P95 延迟和版本可追溯决定继续、回退、补查还是转人工。 若模型版本不可追溯或关键检查项没有证据，结论应停在“待核验”，不能用业务解释替代数据回放。

### 扩展代码一：从AI数据标注与数据飞轮回到可核对明细

```sql
-- AI数据标注与数据飞轮：源表与结果表按对象对账
WITH source_side AS (
  SELECT
    dataset_id AS entity_key,
    COUNT(DISTINCT event_id) AS event_cnt,
    SUM(metric_value) AS metric_sum
  FROM fact_ai_request
  WHERE request_time >= :start_date
    AND request_time <  :end_date
    AND subject_key = 'ai'
    AND is_deleted = 0
  GROUP BY dataset_id
),
result_side AS (
  SELECT
    dataset_id AS entity_key,
    event_cnt,
    metric_sum
  FROM fact_ai_request_result
  WHERE stat_date BETWEEN :start_date AND :end_date
    AND subject_key = 'ai'
)
SELECT
  COALESCE(s.entity_key, r.entity_key) AS entity_key,
  s.event_cnt AS source_event_cnt,
  r.event_cnt AS result_event_cnt,
  s.metric_sum AS source_metric_sum,
  r.metric_sum AS result_metric_sum,
  COALESCE(r.metric_sum, 0) - COALESCE(s.metric_sum, 0) AS metric_diff
FROM source_side s
FULL OUTER JOIN result_side r USING (entity_key)
WHERE ABS(COALESCE(r.metric_sum, 0) - COALESCE(s.metric_sum, 0)) > 0
   OR COALESCE(s.event_cnt, 0) <> COALESCE(r.event_cnt, 0)
ORDER BY ABS(metric_diff) DESC;
```

执行这段 SQL 后，不要只看总量。应同时保存查询参数、口径版本、异常对象清单和对应原始记录抽样。若结果依赖人工过滤，要把过滤条件登记为规则，而不是留在个人脚本里。

### 扩展代码二：把AI数据标注与数据飞轮的验收证据写成门禁

```python
import json
from pathlib import Path


def build_evidence_manifest(
    subject: str,
    scope: dict,
    checks: dict,
    samples: list[dict],
    owner: str,
) -> dict:
    failed = [name for name, passed in checks.items() if not passed]
    return {
        "subject": subject,
        "scope": scope,
        "checks": checks,
        "failed_checks": failed,
        "sample_evidence": samples[:5],
        "owner": owner,
        "decision": "block" if failed else "review",
        "manual_questions": [
            "每一项失败是否已回到原始记录",
            "对象、时间和状态是否与指标字典一致",
            "回滚或修复后是否重新完成对账",
        ],
    }


manifest = build_evidence_manifest(
    subject="AI数据标注与数据飞轮",
    scope={"systems": ["数据仓库","特征平台","向量数据库","模型服务"]},
    checks={"definition_frozen": False, "reconciled": False},
    samples=[],
    owner="业务产品",
)
Path("release-evidence.json").write_text(
    json.dumps(manifest, ensure_ascii=False, indent=2),
    encoding="utf-8",
)
print(manifest["decision"])
```

示例中的行数、时间戳和版本号均为占位值。生产实现应从调度参数、数据契约和质量平台读取真实信息，并将失败结果回写到工单、发布系统和责任人，而不是只打印在日志中。
