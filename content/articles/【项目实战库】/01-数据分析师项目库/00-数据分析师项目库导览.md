# 数据分析师项目库导览

> [!abstract] 📋 这个项目库解决什么问题
> 很多数据分析学习内容会讲方法、模型和指标，但真实工作里更难的是：业务方说了一句含糊的话，你要把它翻译成可以分析、可以落地、可以汇报的项目。这个项目库就是用一个个小项目，把“需求怎么来、问题怎么拆、数据怎么用、结论怎么讲”讲清楚。

## 项目库定位

数据分析师项目库不是“案例大全”，也不是“行业报告”。它更像一组工作现场的复盘：

- 业务方原始需求是什么；
- 这个需求背后真正的问题是什么；
- 分析师如何拆解指标、口径、人群和链路；
- 需要准备哪些数据表和字段；
- 最终交付什么产出；
- 项目如何写进简历、如何在面试里讲。

> [!tip] 一句话理解
> **这里不是教你“知道一个分析方法”，而是带你走完一个数据分析项目从模糊需求到可交付成果的全过程。**

## 推荐学习方式

建议每个项目按三遍来学：

1. **第一遍看故事**：理解业务背景和项目脉络。
2. **第二遍看拆解**：重点看需求翻译、指标设计和分析路径。
3. **第三遍看迁移**：思考这个项目能不能改成你所在行业的版本。

如果你正在准备求职，建议每篇都重点看“简历怎么写”和“面试怎么讲”。这两部分可以直接转化成作品集和项目表达。

## 视觉化内容标准

项目库后续不只使用 Mermaid，也会在合适位置加入更接近真实工作现场的视觉材料：

- **BI 看板截图**：展示最终报表、核心指标、趋势图、明细表和筛选条件。
- **产品功能页面截图**：展示数据开发平台、调度平台、质量平台、标签平台等关键操作页面。
- **建模与链路图**：展示 ER 模型、表血缘、任务 DAG、数据流转路径。
- **诊断过程图**：展示 Spark Stage、Kafka Lag、质量规则运行结果、告警记录等排查依据。
- **检查清单卡**：把项目中的排查步骤、复盘要点和面试表达沉淀为可复用清单。


## 项目材料标准

为了避免项目案例停留在“讲得像”，后续每篇核心项目尽量配齐以下项目材料：

| 素材类型 | 适合项目 | 作用 |
|---|---|---|
| 表结构/DDL | 分析项目、数仓项目、质量项目 | 说明数据从哪里来，字段如何定义 |
| SQL/代码片段 | 所有项目 | 说明具体处理逻辑，而不是只讲思路 |
| BI 看板截图 | 分析项目、治理项目 | 展示最终交付物和业务使用方式 |
| 数据开发平台截图 | 数据开发项目 | 展示任务开发、运行日志、发布配置 |
| 调度 DAG 截图 | 数仓、实时、质量项目 | 展示依赖关系、实例状态和 SLA |
| ER 模型/血缘图 | 数仓、建模、治理项目 | 展示表关系、粒度和上下游影响 |
| 问题处理记录 | 所有项目 | 说明现场问题、定位方式、修复动作和验证结果 |

> [!note] 执行标准
> 图片不是为了装饰，而是为了让项目更像真实交付：读者看到图片、表、SQL 和问题记录时，能理解这个项目在工作中到底如何落地。

## 项目内容详细度 V2

后续项目不只写“思路”和“故事”，每篇核心项目至少补充以下实操细节：

```markdown
## 项目资料包

- 业务背景：公司/部门/场景/角色/时间压力
- 原始需求：业务方原话
- 约束条件：数据延迟、权限、成本、口径、排期

## 表结构与字段说明

- 涉及哪些表
- 每张表的关键字段
- 字段含义、粒度、更新频率
- 容易误用的字段

## 具体处理过程

- SQL / Python / Spark / Flink 代码示例
- 查询逻辑或任务逻辑
- 中间表和产出表
- 对账和验证方式

## 使用的产品或工具功能

- BI 工具、埋点平台、调度平台、数据开发平台
- 用了哪些具体功能
- 为什么这么用

## 问题处理记录

- 遇到的具体异常
- 如何定位
- 如何处理
- 如何验证修复有效
```

> [!warning] 内容标准
> 项目库不能只停留在“分析思路正确”。好的项目案例要让读者看到表、字段、代码、工具、问题和处理动作，最好能照着改成自己公司的版本。

## 每个项目的标准结构

```markdown
## 项目背景

业务方原始需求是什么？当时的业务场景是什么？

## 需求翻译

业务方说的话，如何翻译成数据问题？

## 拆解思路

从哪些维度拆？先看什么，后看什么？

## 数据准备

需要哪些表、字段、指标口径？

## 分析过程

具体怎么分析，如何验证假设？

## 关键产出

报表、SQL、看板、汇报结论、行动建议。

## 踩坑与取舍

哪里容易错？为什么不能直接这么干？

## 简历怎么写

把项目转成简历表达。

## 面试怎么讲

把项目转成 3 分钟项目介绍。
```

## 内容生产原则

1. 先写真实问题，再写分析方法。
2. 先讲业务方怎么提，再讲分析师怎么拆。
3. 不追求“大而全”，追求“一个问题讲透”。
4. 每个项目都要给出可复用产出。
5. 每个项目都要能服务求职表达和职场迁移。
