# 项目复刻与简历改写模板

> [!abstract] 这个模板怎么用
> 当你读完一个项目后，不要直接照搬原文。你要做的是保留项目结构，替换业务背景、数据来源、工具环境和个人动作，把它改成你能讲清楚的版本。

## 一、先判断项目能不能改成你的版本

| 判断项 | 可以继续 | 暂时不要写 |
|---|---|---|
| 业务场景 | 你理解业务目标和核心指标 | 你只知道技术名词 |
| 数据来源 | 能说清楚来自哪些表或系统 | 完全说不清数据从哪里来 |
| 处理过程 | 能讲清需求拆解、查询、排查和取舍 | 只能背最终结论 |
| 工具环境 | 能说清 SQL、BI、调度或平台怎么用 | 只写“使用某工具” |
| 最终产出 | 有看板、报告、任务、规则或接口 | 只有一句“提升效率” |

## 二、项目改写结构

每个项目建议按下面结构改写：

1. **业务背景**：谁提出需求，为什么提出；
2. **目标指标**：核心指标是什么，口径怎么算；
3. **数据来源**：用了哪些表、字段和系统；
4. **拆解方法**：从哪些维度定位问题；
5. **处理过程**：遇到哪些异常，怎么排查；
6. **最终产出**：交付了什么页面、报告、任务或接口；
7. **复盘反思**：哪些地方可以继续优化。

## 三、简历改写公式

```text
负责【业务场景】项目，基于【数据来源】构建【分析/开发/治理口径】，通过【关键方法】定位或解决【具体问题】，最终交付【看板/任务/规则/接口/报告】，支持【业务动作或工程收益】。
```

## 四、面试讲述顺序

建议按 1 分钟、3 分钟、8 分钟准备三个版本。

| 版本 | 讲什么 | 适用场景 |
|---|---|---|
| 1 分钟 | 背景、动作、结果 | 自我介绍后快速带项目 |
| 3 分钟 | 背景、拆解、关键问题、产出 | 面试官要求展开一个项目 |
| 8 分钟 | 表结构、SQL/代码、平台功能、踩坑、取舍 | 技术面深入追问 |

## 六、自检清单

- [ ] 是否能用一句话说清业务问题？
- [ ] 是否能写出核心指标公式？
- [ ] 是否能列出至少 2 张表和关键字段？
- [ ] 是否能解释一个具体问题的处理过程？
- [ ] 是否有最终交付物？
- [ ] 是否能准备 3 个面试追问回答？
- [ ] 是否避免夸大结果和空泛表达？
