# 复合型人才职业规划

> [!tip] 使用方式
> 讨论“复合型人才职业规划”时，最容易犯的错误是直接从工具或报表开始。更有用的顺序是：先看业务链条，再找可观察指标，随后确认数据粒度，最后才选择 SQL、模型或平台组件。本文按这个顺序给出可执行方案和常见的失败样本。

## 1. 岗位到底在解决什么问题

围绕“复合型人才职业规划”，数据分析相关岗位的价值不是掌握多少工具名称，而是能在经营监控、用户增长、活动复盘、用户分层、实验评估和策略迭代中把模糊问题转成可验证交付。看岗位 JD 时，把要求分成四层：

| 层级 | JD 常见表述 | 面试官真正想确认 | 可提供的证据 |
| --- | --- | --- | --- |
| 业务 | 理解业务、推动增长、支持决策 | 能否找到问题和行动 | 场景、口径、决策与复盘 |
| 方法 | 指标体系、实验、建模、治理 | 是否会选择合适方法 | 方案对比、假设、反例 |
| 工程 | SQL、Python、平台、调度、质量 | 能否稳定交付和排障 | 代码、监控、回滚记录 |
| 协作 | 跨团队、沟通、项目管理 | 是否能把事情推进完 | 争议、决策、责任和时间线 |

“复合型人才职业规划”在面试中不能只回答定义。准备一个真实案例，说明为什么做、你个人做了什么、如何验证、结果怎样、如果重做会改什么。团队成果和个人贡献要明确分开。

## 3. 案例一：用业务问题讲清技术选择

### 案例 1：华北某内容平台的“复合型人才职业规划”现场

这是一个结合公开方法、常见工程故障和脱敏数据构造的复合案例，不对应任何单一企业事实。

- **标题落点**：先把正常链路跑通，再人为制造一次失败和恢复。本例把“复合型人才职业规划”映射到“分析方法、指标与实验”中的行动，而不是泛泛讨论概念。
- **触发事件**：推荐策略让人均时长增加，但次日留存和创作者多样性下降。
- **业务与数据范围**：实验组、曝光、点击、时长、留存、内容类型、创作者分布和投诉。数据侧重点采集决策、负责人、主指标、护栏和复盘，并与埋点平台、CRM、订单系统中的时间、状态和责任人信息对齐。
- **需要回答的问题**：建议是否可执行，是否有护栏和观察周期。
- **关键障碍**：实验只看点击与时长，没有检查新奇效应、用户结构和内容供给副作用。同时要防止埋点重复把表面指标带偏。
- **处理过程**：增加分层分析、长期观察和多样性护栏，按用户活跃度评估策略差异。实施时把“描述、预测和因果结论分别命名并说明证据边界”写成上线检查项，并为每一项保留日志、样本和负责人。
- **验证方式**：示例项目证明主指标显著后仍需继续观察成本、体验和长期价值。验收至少同时看主指标、决策、负责人、主指标、护栏和复盘和一次故障回放，不能只截取优化后最快的一次结果。
- **可迁移结论**：遇到类似标题时，先按“把模糊问题翻译成对象、时间、比较基准和行动，检查数据口径与偏差，再选择描述、诊断、预测或因果方法。”建立判断顺序，再决定是否调整代码、资源、口径或组织流程。

面试表达可以压缩成 90 秒：

> 背景是【推荐策略让人均时长增加，但次日留存和创作者多样性下降】。我负责【对象、范围、数据与方案】。先处理【主键、时间、状态或权限】，再用【方法】验证。最终交付【表/指标/服务/规则】，业务采取【行动】。结果是【有口径的改善】，但仍有【限制】，下一版会【改进】。

数字要能回答来源、时间窗、计算方法和你的贡献，不要使用无法解释的百分比。

## 4. 案例二：故障与复盘如何讲

### 案例 2：华东某电商增长团队的“复合型人才职业规划”现场

这是一个结合公开方法、常见工程故障和脱敏数据构造的复合案例，不对应任何单一企业事实。

- **标题落点**：先把标题中的名词还原成一个可以观测的运行问题。本例把“复合型人才职业规划”映射到“分析方法、指标与实验”中的问题，而不是泛泛讨论概念。
- **触发事件**：新人券上线后首日转化提升，但一周后复购和毛利下降。
- **业务与数据范围**：曝光、领券、下单、支付、退款、复购、渠道和用户分层。数据侧重点采集决策记录、对象范围、时间窗口和行动负责人，并与埋点平台、CRM、订单系统中的时间、状态和责任人信息对齐。
- **需要回答的问题**：要改变谁的行为，比较基线和成功标准是什么。
- **关键障碍**：只比较活动前后，没有对照组；自然流量和付费流量归因重叠。同时要防止分母漂移把表面指标带偏。
- **处理过程**：按用户分层做对照实验，主指标看新增贡献，加入退款、毛利和长期留存护栏。实施时把“报告同时保留反例、样本量、护栏指标和停止条件”写成上线检查项，并为每一项保留日志、样本和负责人。
- **验证方式**：示例分析把短期提升与长期收益分开，并给出扩大或停止条件。验收至少同时看主指标、决策记录、对象范围、时间窗口和行动负责人和一次故障回放，不能只截取优化后最快的一次结果。
- **可迁移结论**：遇到类似标题时，先按“把模糊问题翻译成对象、时间、比较基准和行动，检查数据口径与偏差，再选择描述、诊断、预测或因果方法。”建立判断顺序，再决定是否调整代码、资源、口径或组织流程。

故障题按“影响、止血、定位、修复、复核、防复发”回答。比如数据异常时，先判断是否阻断发布和通知消费者，再检查源系统、任务、分区、口径、代码和维度映射。修复后要保留问题时间线、影响资产、根因和自动化措施。

## 5. 技术题与代码样例

### 面试可讲解的专题代码

```sql
-- "复合型人才职业规划"
WITH assigned AS (
  SELECT
    user_id,
    group_name,
    DATEDIFF(DAY, exposure_time, COALESCE(first_paid_at, CURRENT_TIMESTAMP)) AS pay_delay_days,
    paid_amount,
    refund_amount,
    support_ticket_cnt
  FROM experiment_user_day
  WHERE experiment_id = 'exp_202611'
),
summary AS (
  SELECT
    group_name,
    COUNT(DISTINCT user_id) AS user_cnt,
    AVG(CASE WHEN pay_delay_days <= 7 AND paid_amount > 0 THEN 1 ELSE 0 END) AS conversion_rate,
    SUM(paid_amount - refund_amount) / COUNT(DISTINCT user_id) AS net_revenue_per_user,
    SUM(support_ticket_cnt) * 1.0 / COUNT(DISTINCT user_id) AS ticket_per_user
  FROM assigned
  GROUP BY group_name
)
SELECT *, conversion_rate - MAX(CASE WHEN group_name = 'control' THEN conversion_rate END) OVER () AS uplift
FROM summary;

-- 同步检查分流一致性、样本比例、长期留存、退款、投诉、成本和停止条件。
```

### 质量验证与发布门禁

```python
# 复合型人才职业规划：发布前的数据质量与分层检查
import pandas as pd
import numpy as np
import hashlib

TOPIC = "复合型人才职业规划"
TOPIC_KEY = "subject"
RULE_ID = "rule_analytics_hkt56e"
GUIDE_CHECKS = [
    "分析问题写明对象、时间、比较基准、决策和行动负责人",
    "所有指标检查分母、状态、时间、去重和排除条件",
    "描述、预测和因果结论分别命名并说明证据边界",
    "报告同时保留反例、样本量、护栏指标和停止条件"
]
RULES = {
    "required_columns": ["event_id", "user_id", "event_time", "status"],
    "duplicate_key": "event_id",
    "entity_key": "user_id",
    "time_field": "event_time",
    "max_duplicate_rate": 0.0004,
    "max_null_rate": 0.003,
    "allowed_status": {"valid", "completed", "cancelled", "refunded"},
}

def validate(frame: pd.DataFrame) -> pd.DataFrame:
    missing = [c for c in RULES["required_columns"] if c not in frame.columns]
    if missing:
        raise ValueError(f"{TOPIC}/{TOPIC_KEY} missing required columns: {missing}")

    checks = []
    checks.append(("duplicate_rate", frame[RULES["duplicate_key"]].duplicated().mean(), RULES["max_duplicate_rate"]))
    checks.append(("entity_null_rate", frame[RULES["entity_key"]].isna().mean(), RULES["max_null_rate"]))
    event_time = pd.to_datetime(frame[RULES["time_field"]], errors="coerce")
    checks.append(("invalid_time_rate", event_time.isna().mean(), 0.0))
    bad_status = (~frame["status"].isin(RULES["allowed_status"])).mean()
    checks.append(("invalid_status_rate", bad_status, 0.0))

    result = pd.DataFrame(checks, columns=["check_name", "value", "threshold"])
    result["rule_id"] = RULE_ID + "." + result["check_name"]
    result["topic"] = TOPIC
    result["topic_key"] = TOPIC_KEY
    result["passed"] = result["value"].le(result["threshold"])
    result["sample_fingerprint"] = hashlib.sha1(
        f"{TOPIC}|{RULE_ID}|{len(frame)}".encode("utf-8")
    ).hexdigest()[:12]
    return result

def diagnose(frame: pd.DataFrame) -> pd.DataFrame:
    return (
        frame.assign(stat_date=pd.to_datetime(frame[RULES["time_field"]]).dt.date)
        .groupby(["stat_date", "status"], dropna=False)
        .agg(
            event_cnt=(RULES["duplicate_key"], "nunique"),
            entity_cnt=(RULES["entity_key"], "nunique"),
        )
        .reset_index()
        .assign(topic=TOPIC, topic_key=TOPIC_KEY, rule_id=RULE_ID)
        .sort_values("stat_date")
    )

def release_gate(result: pd.DataFrame) -> None:
    failed = result.loc[~result["passed"], ["topic_key", "check_name", "value", "threshold"]]
    if not failed.empty:
        raise RuntimeError({"topic": TOPIC, "failed_checks": failed.to_dict("records")})

# 主题专属门禁：分析问题写明对象、时间、比较基准、决策和行动负责人；所有指标检查分母、状态、时间、去重和排除条件；描述、预测和因果结论分别命名并说明证据边界；报告同时保留反例、样本量、护栏指标和停止条件
# 生产化时把结果写入质量平台，并携带批次、分区、代码版本、规则版本和处理工单。
```

## 6. 高频追问与回答骨架

**问：你如何定义“复合型人才职业规划”的成功？**

答：同时给出业务结果、过程诊断和护栏指标。业务结果说明是否改善，过程指标解释改善来自哪里，护栏指标防止成本、投诉、风险或长期价值恶化。

**问：指标下降了怎么办？**

答：先确认数据是否真实完整，再按对象、结构、行为和外部因素拆分，抽取正负样本回查，最后给出行动和验证方式。事件主键唯一、分子分母同口径、匿名与登录身份已打通。

**问：为什么选择这个方案？**

答：说明约束和目标，再比较至少两个替代方案。回答应包括开发成本、维护成本、时延、准确性、扩展性和失败后的影响。

**问：最大的困难是什么？**

答：选择一个可复现的技术或协作问题，例如“埋点重复”，讲清你如何定位、谁参与、采取了什么折中和最终防复发措施。

**问：如果重做会改什么？**

答：优先说可验证的改进，例如更早冻结口径、增加质量门禁、用小范围灰度、补充长期护栏指标或减少手工依赖。

### 扩展代码一：从复合型人才职业规划回到可核对明细

```sql
-- 复合型人才职业规划：发布前质量画像
SELECT
  'subject' AS subject_key,
  stat_date,
  COUNT(*) AS row_cnt,
  COUNT(DISTINCT event_id) AS distinct_event_cnt,
  SUM(CASE WHEN event_id IS NULL THEN 1 ELSE 0 END) AS null_event_cnt,
  SUM(CASE WHEN event_time < business_time THEN 1 ELSE 0 END) AS time_reverse_cnt,
  SUM(CASE WHEN status NOT IN ('valid', 'completed', 'cancelled') THEN 1 ELSE 0 END) AS invalid_status_cnt,
  ROUND(COUNT(*) * 1.0 / NULLIF(COUNT(DISTINCT event_id), 0), 4) AS duplication_ratio
FROM fact_analysis_event
WHERE stat_date BETWEEN :start_date AND :end_date
GROUP BY stat_date
HAVING SUM(CASE WHEN event_id IS NULL THEN 1 ELSE 0 END) > 0
    OR SUM(CASE WHEN event_time < business_time THEN 1 ELSE 0 END) > 0
    OR COUNT(*) <> COUNT(DISTINCT event_id)
ORDER BY stat_date;

-- 至少人工核对一次：事件主键唯一；分子分母同口径；匿名与登录身份已打通。
```

执行这段 SQL 后，不要只看总量。应同时保存查询参数、口径版本、异常对象清单和对应原始记录抽样。若结果依赖人工过滤，要把过滤条件登记为规则，而不是留在个人脚本里。

### 扩展代码二：把复合型人才职业规划的验收证据写成门禁

```python
import json
from pathlib import Path


def build_evidence_manifest(
    subject: str,
    scope: dict,
    checks: dict,
    samples: list[dict],
    owner: str,
) -> dict:
    failed = [name for name, passed in checks.items() if not passed]
    return {
        "subject": subject,
        "scope": scope,
        "checks": checks,
        "failed_checks": failed,
        "sample_evidence": samples[:5],
        "owner": owner,
        "decision": "block" if failed else "review",
        "manual_questions": [
            "每一项失败是否已回到原始记录",
            "对象、时间和状态是否与指标字典一致",
            "回滚或修复后是否重新完成对账",
        ],
    }


manifest = build_evidence_manifest(
    subject="复合型人才职业规划",
    scope={"systems": ["埋点平台","CRM","订单系统","实验平台"]},
    checks={"definition_frozen": False, "reconciled": False},
    samples=[],
    owner="业务负责人",
)
Path("release-evidence.json").write_text(
    json.dumps(manifest, ensure_ascii=False, indent=2),
    encoding="utf-8",
)
print(manifest["decision"])
```

示例中的行数、时间戳和版本号均为占位值。生产实现应从调度参数、数据契约和质量平台读取真实信息，并将失败结果回写到工单、发布系统和责任人，而不是只打印在日志中。

### 四个案例共用的验收清单

| 验证面 | 发布前问题 | 证据 | 不通过时 |
| --- | --- | --- | --- |

| 时间语义 | 业务发生、数据可见、决策采用是否混用 | event_time、入仓时间、行动时间轴 | 阻断 |
| 指标口径 | 转化率的分子、分母和排除项是否冻结 | 指标字典、SQL、对账结果 | 阻断正式指标 |
| 状态与关联 | 业务问题 → 指标定义 → 数据准备 → 探索分析是否可达且可追溯 | 状态机、明细、操作日志 | 阻断关键链路 |
