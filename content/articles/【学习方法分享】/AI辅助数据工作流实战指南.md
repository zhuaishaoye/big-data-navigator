# AI辅助数据工作流实战指南

> [!tip] 学习目标
> “AI辅助数据工作流实战指南”既可能是业务概念，也可能是技术方案，还可能是岗位能力。判断学习是否有效，要看能否在知识输入、问题拆解、主动练习、反馈校正、作品输出和长期复盘中做出一个可复现的小闭环。本文用多个案例展示从需求到数据结果，再回到业务行动和复盘的完整路径。

## 1. 先诊断，不要从收藏课程开始

围绕“AI辅助数据工作流实战指南”，把当前水平分成四层：

| 层级 | 你应该能做到 | 自测方式 | 常见缺口 |
| --- | --- | --- | --- |
| 知道 | 用自己的话解释概念和边界 | 不看资料讲 2 分钟 | 只会背定义 |
| 会用 | 跟随示例跑通最小闭环 | 从原始数据得到结果 | 依赖复制代码 |
| 会判断 | 发现异常、解释取舍和限制 | 处理缺失、重复和边界样本 | 不知道何时不适用 |
| 会交付 | 独立完成项目并被别人复跑 | 写文档、代码和验收 | 没有质量与复盘 |

给自己打 0-3 分，并选择最低的一项作为第一周重点。不要同时学十个工具，先把问题、资料、练习与提问、检索、理解、练习之间的关系画出来。

```sql
-- AI辅助数据工作流实战指南：留存同期群诊断（主题 × 资料类型）
WITH scoped AS (
  SELECT
    question_id AS entity_key,
    event_id,
    activity_date AS event_date,
    dimension_value AS primary_dim,
    stage_code AS secondary_dim,
    metric_value,
    status
  FROM fact_learning_activity
  WHERE activity_date >= DATE '2026-04-01'
    AND activity_date <  DATE '2026-07-01'
    AND subject_key = 'ai'
    AND is_deleted = 0
),
dedup AS (
  SELECT *
  FROM (
    SELECT
      scoped.*,
      ROW_NUMBER() OVER (
        PARTITION BY event_id
        ORDER BY event_date DESC
      ) AS version_no
    FROM scoped
  ) ranked
  WHERE version_no = 1
),
grouped AS (
  SELECT
    primary_dim,
    secondary_dim,
    COUNT(DISTINCT entity_key) AS entity_cnt,
    COUNT(DISTINCT event_id) AS event_cnt,
    SUM(metric_value) AS metric_sum,
    AVG(metric_value) AS metric_avg
  FROM dedup
  WHERE status IN ('valid', 'completed')
  GROUP BY primary_dim, secondary_dim
),
contribution AS (
  SELECT
    *,
    metric_sum * 1.0 / NULLIF(SUM(metric_sum) OVER (PARTITION BY secondary_dim), 0) AS contribution_ratio,
    metric_avg - AVG(metric_avg) OVER (PARTITION BY secondary_dim) AS delta_to_peer
  FROM grouped
)
SELECT
  '问题闭环率' AS checked_metric,
  primary_dim,
  secondary_dim,
  entity_cnt,
  event_cnt,
  ROUND(metric_sum, 4) AS metric_sum,
  ROUND(contribution_ratio, 4) AS contribution_ratio,
  ROUND(delta_to_peer, 4) AS delta_to_peer
FROM contribution
ORDER BY ABS(delta_to_peer) DESC, entity_cnt DESC;
```

### 练习题：质量检查

```python
# AI辅助数据工作流实战指南：发布前的数据质量与分层检查
import pandas as pd
import numpy as np
import hashlib

TOPIC = "AI辅助数据工作流实战指南"
TOPIC_KEY = "ai"
RULE_ID = "rule_method_1sxtwjn"
GUIDE_CHECKS = [
    "依赖必须区分任务完成、分区可读、文件到达和外部事件",
    "自动重跑前先验证幂等和事务边界",
    "补数要限流、分批、可暂停、可恢复并记录影响范围",
    "Schema、代码、配置、权限和数据变更进入同一发布审计"
]
RULES = {
    "required_columns": ["event_id", "question_id", "activity_date", "status"],
    "duplicate_key": "event_id",
    "entity_key": "question_id",
    "time_field": "activity_date",
    "max_duplicate_rate": 0.0008,
    "max_null_rate": 0.002,
    "allowed_status": {"valid", "completed", "cancelled", "refunded"},
}

def validate(frame: pd.DataFrame) -> pd.DataFrame:
    missing = [c for c in RULES["required_columns"] if c not in frame.columns]
    if missing:
        raise ValueError(f"{TOPIC}/{TOPIC_KEY} missing required columns: {missing}")

    checks = []
    checks.append(("duplicate_rate", frame[RULES["duplicate_key"]].duplicated().mean(), RULES["max_duplicate_rate"]))
    checks.append(("entity_null_rate", frame[RULES["entity_key"]].isna().mean(), RULES["max_null_rate"]))
    event_time = pd.to_datetime(frame[RULES["time_field"]], errors="coerce")
    checks.append(("invalid_time_rate", event_time.isna().mean(), 0.0))
    bad_status = (~frame["status"].isin(RULES["allowed_status"])).mean()
    checks.append(("invalid_status_rate", bad_status, 0.0))

    result = pd.DataFrame(checks, columns=["check_name", "value", "threshold"])
    result["rule_id"] = RULE_ID + "." + result["check_name"]
    result["topic"] = TOPIC
    result["topic_key"] = TOPIC_KEY
    result["passed"] = result["value"].le(result["threshold"])
    result["sample_fingerprint"] = hashlib.sha1(
        f"{TOPIC}|{RULE_ID}|{len(frame)}".encode("utf-8")
    ).hexdigest()[:12]
    return result

def diagnose(frame: pd.DataFrame) -> pd.DataFrame:
    return (
        frame.assign(stat_date=pd.to_datetime(frame[RULES["time_field"]]).dt.date)
        .groupby(["stat_date", "status"], dropna=False)
        .agg(
            event_cnt=(RULES["duplicate_key"], "nunique"),
            entity_cnt=(RULES["entity_key"], "nunique"),
        )
        .reset_index()
        .assign(topic=TOPIC, topic_key=TOPIC_KEY, rule_id=RULE_ID)
        .sort_values("stat_date")
    )

def release_gate(result: pd.DataFrame) -> None:
    failed = result.loc[~result["passed"], ["topic_key", "check_name", "value", "threshold"]]
    if not failed.empty:
        raise RuntimeError({"topic": TOPIC, "failed_checks": failed.to_dict("records")})

# 主题专属门禁：依赖必须区分任务完成、分区可读、文件到达和外部事件；自动重跑前先验证幂等和事务边界；补数要限流、分批、可暂停、可恢复并记录影响范围；Schema、代码、配置、权限和数据变更进入同一发布审计
# 生产化时把结果写入质量平台，并携带批次、分区、代码版本、规则版本和处理工单。
```

不要只运行代码。请故意破坏三件事：重复一个主键、删除一段日期、把状态改成未知值，确认质量检查能发现。再思考：数据量扩大十倍时，分组是否倾斜、查询是否全表扫描、日志是否足够、重跑是否幂等。

## 6. 工作案例一：华北某物流平台

### 案例 1：华北某物流平台的“AI辅助数据工作流实战指南”现场

这是一个结合公开方法、常见工程故障和脱敏数据构造的复合案例，不对应任何单一企业事实。

- **标题落点**：先把正常链路跑通，再人为制造一次失败和恢复。本例把“AI辅助数据工作流实战指南”映射到“数据调度、依赖与数据 DevOps”中的幂等，而不是泛泛讨论概念。
- **触发事件**：历史补数持续数天，期间正常任务资源被挤占。
- **业务与数据范围**：补数分区、任务并发、队列资源、执行时长、下游锁和业务优先级。数据侧重点采集写入模式、去重键、事务和回滚，并与笔记、代码仓库、问题清单中的时间、状态和责任人信息对齐。
- **需要回答的问题**：重跑同一分区是否会重复写入或重复产生副作用。
- **关键障碍**：所有补数任务同时启动，没有资源配额和分层优先级。同时要防止信息过载把表面指标带偏。
- **处理过程**：按影响范围分批，设置并发上限与夜间窗口，任务内部记录每个分区的输入输出和处理状态。实施时把“Schema、代码、配置、权限和数据变更进入同一发布审计”写成上线检查项，并为每一项保留日志、样本和负责人。
- **验证方式**：示例项目用补数速度、正常 SLA、失败重试和人工介入次数评估。验收至少同时看主指标、写入模式、去重键、事务和回滚和一次故障回放，不能只截取优化后最快的一次结果。
- **可迁移结论**：遇到类似标题时，先按“把任务、数据、时间和外部系统依赖显式建模，保证重跑幂等、失败可恢复、变更可回滚、SLA 可观察。”建立判断顺序，再决定是否调整代码、资源、口径或组织流程。

从案例中提取一个练习：用表中的检查项和 SQL 结构，写出你所在场景的对象、时间和指标。即使没有企业数据，也可以用公开数据集或合成数据完成，但必须说明数据来源和使用边界。

## 8. 反馈与复盘机制

### 案例 3：华南某金融数据团队的“AI辅助数据工作流实战指南”现场

这是一个结合公开方法、常见工程故障和脱敏数据构造的复合案例，不对应任何单一企业事实。

- **标题落点**：先确认业务对象和系统边界，再讨论工具或参数。本例把“AI辅助数据工作流实战指南”映射到“数据调度、依赖与数据 DevOps”中的补数，而不是泛泛讨论概念。
- **触发事件**：一次表结构变更导致数十个下游任务同时失败。
- **业务与数据范围**：任务血缘、表版本、字段依赖、发布顺序、失败日志和影响资产。数据侧重点采集补数计划、限流、顺序和完成校验，并与笔记、代码仓库、问题清单中的时间、状态和责任人信息对齐。

- **可迁移结论**：遇到类似标题时，先按“把任务、数据、时间和外部系统依赖显式建模，保证重跑幂等、失败可恢复、变更可回滚、SLA 可观察。”建立判断顺序，再决定是否调整代码、资源、口径或组织流程。

复盘时把“不会”拆成可学习项：概念不清、数据不可得、代码结构错误、验证方法缺失或表达没有证据。每一项分别对应阅读、练习、代码评审和口头复述，避免用再看一门课掩盖真正缺口。

### 扩展代码一：从AI辅助数据工作流实战指南回到可核对明细

```sql
-- AI辅助数据工作流实战指南：恢复后缺失、重复与跨期检查
WITH expected_keys AS (
  SELECT DISTINCT question_id AS entity_key, event_id
  FROM fact_learning_activity
  WHERE activity_date >= :restore_start
    AND activity_date <  :restore_end
    AND subject_key = 'ai'
),
restored_keys AS (
  SELECT question_id AS entity_key, event_id, load_version, loaded_at
  FROM fact_learning_activity
  WHERE activity_date >= :restore_start
    AND activity_date <  :restore_end
    AND subject_key = 'ai'
    AND load_version = :restore_version
),
coverage AS (
  SELECT
    (SELECT COUNT(*) FROM expected_keys) AS expected_cnt,
    (SELECT COUNT(*) FROM restored_keys) AS restored_cnt,
    (SELECT COUNT(*) FROM (
      SELECT entity_key, event_id
      FROM restored_keys
      GROUP BY entity_key, event_id
      HAVING COUNT(*) > 1
    ) duplicate_keys) AS duplicated_cnt,
    (SELECT COUNT(*) FROM (
      SELECT e.entity_key, e.event_id
      FROM expected_keys e
      LEFT JOIN restored_keys r USING (entity_key, event_id)
      WHERE r.entity_key IS NULL
    ) missing_keys) AS missing_cnt
)
SELECT *,
  CASE
    WHEN expected_cnt <> restored_cnt OR duplicated_cnt > 0 OR missing_cnt > 0
      THEN 'reject_release'
    ELSE 'accept_restore'
  END AS gate_result
FROM coverage;
```

### 扩展代码二：把AI辅助数据工作流实战指南的验收证据写成门禁

```python
from datetime import date
from hashlib import sha256

import pandas as pd

SUBJECT = "AI辅助数据工作流实战指南"
BLOCKING_RULES = ["目标可验证","资料有出处","练习有反馈"]


def validate_release(frame: pd.DataFrame, start: date, end: date) -> dict:
    scoped = frame.loc[
        frame["event_date"].between(pd.Timestamp(start), pd.Timestamp(end))
        & (frame["subject_key"] == "ai")
    ].copy()
    checks = {
        "has_rows": len(scoped) > 0,
        "event_id_unique": not scoped["event_id"].duplicated().any(),
        "entity_key_complete": scoped["entity_key"].notna().all(),
        "event_time_present": scoped["event_time"].notna().all(),
        "scope_matches": scoped["subject_key"].nunique() == 1,
    }
    payload = f"{SUBJECT}|{start}|{end}|{len(scoped)}|{sorted(checks.items())}"
    return {
        "subject": SUBJECT,
        "rows": len(scoped),
        "checks": checks,
        "blocking_rules": BLOCKING_RULES,
        "release_allowed": all(checks.values()),
        "evidence_hash": sha256(payload.encode("utf-8")).hexdigest(),
    }
```

示例中的行数、时间戳和版本号均为占位值。生产实现应从调度参数、数据契约和质量平台读取真实信息，并将失败结果回写到工单、发布系统和责任人，而不是只打印在日志中。
