# 视觉营销

> [!abstract] 商品内容与视觉增长实战手册
> 视觉营销是用图片、视频、场景、版式和品牌表达影响用户理解与购买决策的过程。数据工作要把素材版本、商品、渠道、场景、曝光、点击、转化、退货和品牌护栏关联起来，区分素材效果、商品差异和流量结构。

## 1. 视觉营销：定义、适用边界与决策出口

视觉营销是用图片、视频、场景、版式和品牌表达影响用户理解与购买决策的过程。数据工作要把素材版本、商品、渠道、场景、曝光、点击、转化、退货和品牌护栏关联起来，区分素材效果、商品差异和流量结构。

**本篇的适用边界。** 本篇覆盖商品主图、详情页、短视频、店铺页和广告创意等视觉素材的生产与效果评估，不把视觉审美本身简化为一个点击率分数。

**最常见的错误替代。** 不能用点击率上涨直接证明视觉更好；高点击可能来自误导、夸张承诺或非目标人群，最终还需观察转化、退货、投诉和品牌一致性。

**最终决策。** 内容、商品和投放团队要判断：哪些素材值得扩量，哪些版本存在误导风险，某次改版是否真正带来增量，以及如何按商品和人群复用有效视觉语言。 因此，这篇内容不从“应该建哪张表”开始，而从业务动作、责任人和失败后果开始。只有先确定谁在什么时点做出什么决定，字段、SQL、看板和模型才有明确用途。

围绕“视觉营销”，工作中至少要区分四类问题：

1. **身份问题**：对象是谁，主键能否跨系统稳定关联，合并、拆分、撤销后历史是否还看得见。
2. **时间问题**：业务发生、状态生效、数据入仓、计算完成和人员行动分别发生在哪一刻。
3. **状态问题**：当前状态是一段事件、一张快照还是最终结果，空值代表未发生、未采集还是已删除。
4. **责任问题**：谁确认口径，谁处理异常，谁有权放行或停止，谁在观察期后复盘。

## 2. 视觉营销的完整业务流程

| 环节 | 要做的事 | 最小证据 | 失败后先查什么 |
| --- | --- | --- | --- |
| 商品与卖点梳理 | 确认目标人群、核心卖点、限制条件和必须展示的信息 | 商品资料、卖点清单、合规口径 | 广告请求或加载开始即计为曝光 |
| 创意与脚本评审 | 形成场景、构图、文案和视频脚本版本 | 创意 brief、脚本、审核意见 | 同一实验混入多个文案或图片 |
| 素材生产与质检 | 完成拍摄、设计、转码、裁切和品牌检查 | 原片、设计源文件、版本和质检记录 | 高点击低转化、高退货仍被扩量 |
| 渠道发布与匹配 | 按渠道、版位、商品和人群配置素材 | 发布任务、素材映射、生效时间 | 不同意图渠道被合成一个指标 |
| 曝光点击与浏览 | 记录请求、可见曝光、点击、停留和完播 | 事件日志、设备、页面和素材版本 | 广告请求或加载开始即计为曝光 |
| 转化与售后 | 关联加购、下单、支付、退款、退货和投诉 | 订单、售后、归因路径 | 同一实验混入多个文案或图片 |
| 实验复盘 | 比较版本、人群、商品和渠道增量，沉淀可复用规则 | 实验设计、基线、显著性、品牌护栏 | 高点击低转化、高退货仍被扩量 |

把 商品与卖点梳理、创意与脚本评审、素材生产与质检、渠道发布与匹配、曝光点击与浏览、转化与售后、实验复盘 串起来后可以看出，视觉营销不是一个孤立字段，而是一条会跨系统、跨岗位、跨时间的证据链。流程图上每一段都应标出输入、输出、状态、时间戳、责任人和异常出口。只要其中一段只能靠口头解释，后续的统计、追责和自动化就会失去基础。

一个合格的需求说明应该写成：

> 在【授权数据范围】和【观察窗口】内，围绕“视觉营销”的【视觉素材】，按【creative_version_id、channel_id、placement_id、audience_segment】比较【素材可见点击率】及其【首屏停留时长】，定位一个可干预节点；行动后同时观察主指标、样本量和护栏，任何高风险异常先阻断再调查。

## 3. 视觉营销的数据对象与系统契约

| 数据对象 | 建议主键 | 一行代表什么 | 不允许混淆 |
| --- | --- | --- | --- |
| 视觉素材 | `creative_asset_id` | 一个可独立发布和追踪的图片、视频或页面版本 | 对象身份与业务事件 |
| 创意版本 | `creative_version_id` | 素材在特定文案、裁切和渠道下的版本 | 事件、状态快照和结果粒度 |
| 商品与卖点 | `product_content_id` | 商品内容与核心卖点的有效期组合 | 事件、状态快照和结果粒度 |
| 发布映射 | `placement_id` | 素材在渠道、版位和人群上的发布关系 | 事件、状态快照和结果粒度 |
| 用户反馈 | `feedback_id` | 点击后浏览、转化、退货或投诉证据 | 事件、状态快照和结果粒度 |
| 实验 | `experiment_id` | 一个具有目标、分流和分析方案的效果验证 | 事件、状态快照和结果粒度 |

对象表不是把所有字段塞进一张宽表。事件、状态快照和结果表应该分别保留粒度，再通过稳定主键与版本建立关联。尤其要避免三个常见混算：把一次业务事件算成多个对象、把每日快照相加当事件总量、把最新状态覆盖历史状态。

本主题的数据契约至少应包含：

- `creative_exposure_id` 的唯一性规则、生成方式和跨系统映射。
- `exposed_at` 的业务含义、时区、迟到和补录规则。
- `event_status` 的完整状态集合，以及删除、撤销、冻结和失效的表示方法。
- 控制对象 `mkt_creative_release.creative_version_id` 与主对象的关系。
- 每次口径、规则、模型或源版本变化的影响范围和下游通知对象。
- 敏感字段、允许用途、访问角色、导出限制和审计保留时间。

## 4. 视觉营销的指标、样本与验收口径

| 指标 | 公式或定义 | 口径提醒 |
| --- | --- | --- |
| 素材可见点击率 | 可见曝光后的有效点击次数 / 可见曝光次数 | 请求和未可见曝光不能进入分母 |
| 首屏停留时长 | 有效浏览会话停留秒数 / 有效会话数 | 过滤机器人和异常短会话，按渠道分层 |
| 素材到支付转化率 | 归因支付订单数 / 素材有效点击会话数 | 需要排除已下架、缺货和重复订单 |
| 退货关联率 | 使用该素材触达后发生退货的订单数 / 归因订单数 | 按商品和人群比较，避免把商品问题归咎于素材 |
| 品牌合规问题率 | 存在禁用词、错误标识或品牌冲突的发布版本数 / 审核版本数 | 上线前检查和上线后巡检都要统计 |

指标字典至少写到“任何人都能按同一份数据复跑”的程度：中文名、业务定义、公式、分子、分母、事实粒度、时间字段、对象范围、排除项、版本、负责人和验收样例，一个都不能少。比例指标必须同时展示分子、分母和样本量；金额或数量必须做守恒；状态指标必须能回到事件时间线。

对于“视觉营销”，建议把观察分成三层：

| 层次 | 看什么 | 不能替代什么 |
| --- | --- | --- |
| 业务结果 | 素材可见点击率、首屏停留时长 | 不能替代过程证据和个案回查 |
| 过程护栏 | 素材到支付转化率、退货关联率、品牌合规问题率 | 不能因为护栏暂时正常就跳过异常调查 |
| 数据证据 | 主键、时间、状态、版本、来源目标对账 | 不能只看任务成功或报表能打开 |

## 5. 视觉营销：七个真实工作场景

以下七组场景均为公开方法结合常见工作流程构造的“脱敏复合示例”，不对应任何单一企业、患者、客户或雇员事实。场景的目的，是展示如何从现象走到证据、行动和验收，而不是虚构经营成果。

### 1. 点击率上涨但退货率同步上升

**现场。** 新主图点击率明显高于旧版，团队准备全量替换。

**怎么查。** 按商品、渠道、人群和订单回查，发现新图突出低价但详情页规格说明不足，吸引来的人群与商品定位不一致。

**怎么处理。** 延长观察窗口，把转化、退货、差评和客服咨询一并纳入；保留对比版本；详情页补充规格后再测试。

**验收结论。** 视觉素材的第一层指标是注意力，最终指标仍是可持续的购买与满意。

### 2. 同一素材跨渠道表现相反

**现场。** 同一短视频在信息流表现很好，在搜索场景却点击低。

**怎么查。** 核对素材裁切、首帧、文案、版位和用户意图，发现搜索用户更关心参数对比，而视频突出的是场景氛围。

**怎么处理。** 建立渠道专用版本，不混算全渠道平均；素材效果按渠道意图和版位分层。

**验收结论。** 平均指标可能掩盖渠道冲突。素材版本必须有明确的适用场景。

### 3. 设计系统升级导致品牌不一致

**现场。** 多个团队同时改版，短期转化没有下降，但品牌识别和页面一致性变差。

**怎么查。** 把字体、颜色、留白、Logo 位置、图片比例和组件版本结构化登记，抽样比对线上页面。

**怎么处理。** 将品牌规则设为发布门禁；允许业务模板在限定范围内变化；新组件先小流量验证再进入组件库。

**验收结论。** 视觉规范也需要版本和检测。只靠设计评审记忆无法管理规模化内容生产。

### 4. 爆款素材被错误复制到所有商品

**现场。** 某个高客单商品素材表现好，运营批量套用到低客单商品。

**怎么查。** 比较商品价格、受众、场景、卖点和承接页，发现两个商品决策路径完全不同。

**怎么处理。** 把成功要素拆成可复用原则而不是整张图片；按商品类目和目标人群重新验证；建立素材复用白名单。

**验收结论。** 素材复制的不是设计文件，而是假设。假设换了对象就必须重新测试。

### 5. A/B 实验在发布中途被污染

**现场。** 实验组素材上线后又多次替换文案，最终两组差异无法解释。

**怎么查。** 回查发布记录、缓存、CDN、人群分流和各版本曝光时间，发现实验组至少包含三个素材版本。

**怎么处理。** 固定实验版本和变更冻结窗口；结果表关联素材版本；发生重大变更时停止实验并重新分组。

**验收结论。** 没有版本约束的实验只是在比较一段混乱历史。

### 6. 素材审核通过但上线版本不同

**现场。** 审核系统显示版本合规，线上巡检仍发现禁用词和错误价格。

**怎么查。** 核对审核文件哈希、发布任务、CDN 地址和页面缓存，发现设计稿通过后运营又替换了文案。

**怎么处理。** 发布使用不可变素材版本和内容哈希；上线后自动截图识别；未审核版本禁止投放。

**验收结论。** 审核对象和发布对象必须是同一个版本，否则流程只是形式。

### 7. 多语言市场中的文化误读

**现场。** 同一视觉在多个地区投放，部分市场反馈负面。

**怎么查。** 按地区、语言、模特、色彩、节日和产品使用场景检查反馈与投诉，区分翻译问题和文化语义。

**怎么处理。** 建立地区化素材审查；保留当地业务复核；不把全球点击率简单平均。

**验收结论。** 跨市场内容不能只做语言替换。数据字典也要记录地区化版本。

七个场景可以归成一条共同判断顺序：先确认对象和时间，再确认状态和版本；然后做总量、结构和明细三层对账；最后才讨论策略、模型或工具。若一条结论不能指出对应的原始记录、责任人和行动出口，就只能算观察，不能作为生产结论。

## 6. 视觉营销的第一段 SQL：重建业务链路

下面的 SQL 用于说明对象、时间、状态、版本和分层口径如何进入同一条可复查路径。表名和部分字段是通用示例，落地时应映射到企业数据字典；SQL 方言也需按实际引擎调整。

```sql
-- 视觉营销：按业务对象重建链路，避免事件、快照和结果混算
WITH ranked_creative_exposure_id AS (
  SELECT
    *,
    ROW_NUMBER() OVER (
      PARTITION BY creative_exposure_id
      ORDER BY updated_at DESC
    ) AS version_no
  FROM mkt_creative_exposure_event
  WHERE exposed_at >= TIMESTAMP '{start_time}'
    AND exposed_at <  TIMESTAMP '{end_time}'
    AND event_status NOT IN ('deleted', 'test')
),
valid_rows AS (
  SELECT
    creative_exposure_id,
    creative_version_id,
    channel_id,
    placement_id,
    audience_segment,
    exposed_at,
    event_status,
    ingested_at
  FROM ranked_creative_exposure_id
  WHERE version_no = 1
)
SELECT
  creative_version_id, channel_id, placement_id, audience_segment,
  COUNT(DISTINCT creative_exposure_id) AS object_cnt,
  COUNT(DISTINCT CASE WHEN clicked AND is_viewable THEN session_id END) AS numerator_value,
  COUNT(DISTINCT CASE WHEN is_viewable THEN exposure_id END) AS denominator_value,
  CAST(COUNT(DISTINCT CASE WHEN clicked AND is_viewable THEN session_id END) AS DOUBLE PRECISION)
    / NULLIF(COUNT(DISTINCT CASE WHEN is_viewable THEN exposure_id END), 0) AS metric_value,
  MIN(exposed_at) AS first_event_at,
  MAX(exposed_at) AS last_event_at
FROM valid_rows
GROUP BY creative_version_id, channel_id, placement_id, audience_segment
ORDER BY metric_value DESC, object_cnt DESC;
```

执行后至少回答六个问题：

- 同一对象是否因为多源回传产生多版本，版本保留是否符合业务要求？
- 业务时间与入仓时间是否分开，补录和迟到数据是否进入正确分区？
- 分子分母是否来自同一对象范围和同一统计窗口？
- 维度使用的是事件当时值还是当前值，跨期比较是否一致？
- 删除、撤销、冻结和测试数据是否按规则处理？
- 分组结果能否在明细中抽样复现？

## 7. 视觉营销的第二段 SQL：源、控制和结果三方对账

```sql
-- 视觉营销：源对象、控制对象和结果对象三方对账
WITH population AS (
  SELECT
    creative_exposure_id,
    exposed_at,
    event_status
  FROM mkt_creative_exposure_event
  WHERE exposed_at >= TIMESTAMP '{start_time}'
    AND exposed_at <  TIMESTAMP '{end_time}'
),
control AS (
  SELECT
    creative_exposure_id,
    SUM(release_version) AS control_value,
    COUNT(DISTINCT creative_version_id) AS control_cnt,
    MAX(updated_at) AS control_updated_at
  FROM mkt_creative_release
  WHERE updated_at >= TIMESTAMP '{start_time}'
  GROUP BY creative_exposure_id
),
result AS (
  SELECT
    creative_exposure_id,
    COUNT(*) AS result_cnt,
    MAX(calculated_at) AS calculated_at
  FROM mart_creative_exposure_id
  WHERE business_date BETWEEN DATE '{start_date}' AND DATE '{end_date}'
  GROUP BY creative_exposure_id
)
SELECT
  COALESCE(p.creative_exposure_id, c.creative_exposure_id, r.creative_exposure_id) AS object_key,
  CASE
    WHEN p.creative_exposure_id IS NULL THEN 'source_missing'
    WHEN c.creative_exposure_id IS NULL THEN 'control_missing'
    WHEN r.creative_exposure_id IS NULL THEN 'result_missing'
    WHEN ABS(COALESCE(c.control_value, 0) - COALESCE(r.result_cnt, 0)) > 0 THEN 'count_or_value_gap'
    ELSE 'matched'
  END AS reconciliation_status,
  p.event_status,
  c.control_value,
  c.control_cnt,
  r.result_cnt,
  c.control_updated_at,
  r.calculated_at
FROM population p
FULL OUTER JOIN control c ON p.creative_exposure_id = c.creative_exposure_id
FULL OUTER JOIN result r ON COALESCE(p.creative_exposure_id, c.creative_exposure_id) = r.creative_exposure_id
WHERE p.creative_exposure_id IS NULL
   OR c.creative_exposure_id IS NULL
   OR r.creative_exposure_id IS NULL
   OR ABS(COALESCE(c.control_value, 0) - COALESCE(r.result_cnt, 0)) > 0;
```

这段查询故意不使用“总数相差小于某个随意百分比就算通过”。它先找出缺失对象和状态差异，再检查控制值与结果值。对于视觉营销，数量、金额、时长或状态任意一项无法解释，都不能用“业务波动”代替排查。

对账结果建议分成四类处理：

1. **阻断**：对象缺失、关键时间为空、状态非法、金额或数量不守恒、权限越界。
2. **严重**：比例或总量显著偏离基线，且无法由已确认的对象结构变化解释。
3. **观察**：小范围波动但来源、样本和趋势可控，进入责任人和观察窗口。
4. **探索**：只有弱信号或假设，不进入正式结论，更不直接触发业务处罚。

## 8. 视觉营销的 Python 发布门禁与指标护栏

第一段代码把发布条件写成可执行对象，避免“检查过了”只存在聊天记录里：

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class CreativeExposureIdBatch:
    batch_id: str
    source_rows: int
    valid_rows: int
    duplicate_keys: int
    missing_required_fields: int
    reconciliation_gap: float

def release_creative_exposure_id(batch: CreativeExposureIdBatch) -> dict:
    checks = {
        "source_not_empty": batch.source_rows > 0,
        "valid_rows_in_range": 0 <= batch.valid_rows <= batch.source_rows,
        "duplicate_rate_ok": batch.duplicate_keys / max(batch.source_rows, 1) <= 0.001,
        "required_fields_ok": batch.missing_required_fields == 0,
        "reconciliation_ok": abs(batch.reconciliation_gap) <= 0.01,
    }
    return {
        "topic": "视觉营销",
        "batch_id": batch.batch_id,
        "checks": checks,
        "release_allowed": all(checks.values()),
        "blocking_checks": [name for name, passed in checks.items() if not passed],
    }
```

第二段代码演示如何为比例类结果附带样本证据和小样本下界。它不是替代统计学家的模型，而是防止把少量偶然样本直接包装成稳定结论：

```python
from dataclasses import dataclass
from math import sqrt

@dataclass(frozen=True)
class CreativeExposureIdObservation:
    object_id: str
    numerator: float
    denominator: float
    sample_size: int
    scope_version: str

def calculate_creative_exposure_id(rows: list[CreativeExposureIdObservation]) -> list[dict]:
    output = []
    for row in rows:
        value = row.numerator / row.denominator if row.denominator > 0 else None
        # 小样本用 Wilson 下界做护栏，不把偶然的高比例直接当稳定结果。
        z = 1.96
        p = value or 0
        n = max(row.sample_size, 1)
        center = p + z * z / (2 * n)
        margin = z * sqrt((p * (1 - p) + z * z / (4 * n)) / n)
        lower = max(0, (center - margin) / (1 + z * z / n))
        output.append({
            "object_id": row.object_id,
            "metric": "素材可见点击率",
            "value": value,
            "lower_bound": lower if value is not None else None,
            "sample_size": row.sample_size,
            "scope_version": row.scope_version,
            "caution": "请求和未可见曝光不能进入分母",
        })
    return output
```

真正上线时还要补充参数配置、日志、血缘、告警级别、重跑幂等、异常样本保存和审批记录。代码通过不代表业务通过；自动检查只能证明已经定义的规则没有被违反，无法证明规则本身一定正确。

## 9. 视觉营销的失败反例与上线验收

| 风险信号 | 错误做法 | 必须补齐的证据 | 发布或行动规则 |
| --- | --- | --- | --- |
| 请求当曝光 | 广告请求或加载开始即计为曝光 | 可见标准、曝光时间和设备证据 | 点击率只用有效可见曝光 |
| 素材版本混算 | 同一实验混入多个文案或图片 | 内容哈希、版本和发布记录 | 版本变化时停止或重新分组 |
| 只看点击 | 高点击低转化、高退货仍被扩量 | 支付、退款、退货和投诉 | 设置成交和品牌护栏 |
| 跨渠道平均 | 不同意图渠道被合成一个指标 | 渠道、版位和人群分层 | 分别评估与分配预算 |

上线验收不应只有一句“报表正常”。建议按下面四层验收：

| 验收对象 | 结构要求 | 测试样本 | 结果证据 |
| --- | --- | --- | --- |
| 视觉素材 | `creative_asset_id` 能唯一定位一个可独立发布和追踪的图片、视频或页面版本 | 正常、重复、缺失、撤销与跨期样本 | 素材可见点击率可回到原始对象 |
| 创意版本 | `creative_version_id` 能唯一定位素材在特定文案、裁切和渠道下的版本 | 正常、重复、缺失、撤销与跨期样本 | 首屏停留时长可回到原始对象 |
| 商品与卖点 | `product_content_id` 能唯一定位商品内容与核心卖点的有效期组合 | 正常、重复、缺失、撤销与跨期样本 | 素材到支付转化率可回到原始对象 |
| 发布映射 | `placement_id` 能唯一定位素材在渠道、版位和人群上的发布关系 | 正常、重复、缺失、撤销与跨期样本 | 退货关联率可回到原始对象 |
| 用户反馈 | `feedback_id` 能唯一定位点击后浏览、转化、退货或投诉证据 | 正常、重复、缺失、撤销与跨期样本 | 品牌合规问题率可回到原始对象 |
| 实验 | `experiment_id` 能唯一定位一个具有目标、分流和分析方案的效果验证 | 正常、重复、缺失、撤销与跨期样本 | 素材可见点击率可回到原始对象 |

还应为每一次发布保留一组固定回归样本：正常对象、边界状态、重复记录、缺失字段、撤销或退款、跨期、权限拒绝和失败恢复。回归样本不是演示数据，而是以后每次改规则都能重复执行的质量资产。

## 10. 视觉营销的 30 天落地与复盘

| 阶段 | 主要交付 | 通过条件 |
| --- | --- | --- |
| 第 1 周：定义 | 对象、流程、状态、指标、排除项和责任矩阵 | 业务、数据、安全或质量负责人对同一口径签字 |
| 第 2 周：打通 | 源字段、主键、时间、版本、控制对象和失败样本 | 正常与异常样本都能回到原始记录 |
| 第 3 周：验证 | 总量对账、分层对账、抽样回查、权限测试、回滚演练 | 阻断问题清零，严重问题有责任人与期限 |
| 第 4 周：发布 | 灰度、SLO、监控、行动清单、停止条件和复盘模板 | 使用者在真实场景中完成一次闭环行动 |

如果必须用 90 秒说明“视觉营销”是否做对，可以按这个顺序自测：

1. 一行数据代表什么，主键是什么，哪些对象绝不能混在同一粒度？
2. 业务发生、数据可见、计算完成和行动确认分别在哪个时间点？
3. 本主题最重要的两个主指标、三个护栏和最小样本量是什么？
4. 一个异常出现时，先从原始记录、链路版本还是业务动作开始查？
5. 哪类错误必须阻断发布或停止使用，谁有权批准例外？
6. 上线后由谁在多长时间内观察，什么条件下回滚或结束？

> [!check] 完成标准
> 当另一位数据同事不看聊天记录，只根据口径卡、回归样本和代码就能复跑同一结果；当业务负责人能指出一个异常对应的原始对象、处置动作和复核证据；当系统能够阻止未授权或状态非法的数据进入下游，这篇“视觉营销”才算真正落到工作里。
