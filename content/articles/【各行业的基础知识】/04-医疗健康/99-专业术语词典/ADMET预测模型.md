# ADMET预测模型

> [!tip] 分析目标
> 一个关于“ADMET预测模型”的结论能不能被信任，取决于它是否能回到原始事件、明确时间和对象，并说明排除了哪些记录。下面不会用单一模板概括所有场景，而是结合医疗健康中的多类任务，展示数据建模、代码分析和项目验收之间如何衔接。

## 1. 把主题翻译成可验证的问题

“ADMET预测模型”不能直接等同于“做一张趋势图”。一个可执行的分析问题至少包含对象、时间、比较基准和行动：

> 在【观察周期】内，对【有效对象】按【院区、科室、病种】比较【异常检验占比】与【费用偏差率】，判断变化来自结构、行为还是数据口径，并验证【策略动作】是否带来可解释的增量。

在医疗健康场景中，用户行为、交易结果和策略曝光经常来自不同系统。先画数据流：

HIS → EMR → LIS → RIS → PACS → 医保结算系统

图中至少要有三个标记：业务事件发生时间、数据可见时间、策略或行动时间。只有三者分开，后续才能判断问题发生在业务、链路还是观察窗口。

## 2. 指标定义与分母检查

| 专题观测面 | 需要回答的问题 | 关键证据 | 判定与动作 |
| --- | --- | --- | --- |
| 特征（本标题优先） | 特征在预测时是否可得，训练与线上计算是否一致 | 特征时间、版本、缺失率、训练服务一致性和血缘 | 禁止使用未来信息 |
| 运营 | 数据漂移、模型漂移、延迟、成本和回滚是否可观察 | 输入分布、预测分布、业务指标、版本和告警 | 设置自动降级与人工复核 |
| 评估 | 时间、用户、设备分组是否防止泄漏，误报成本如何 | 时间切分、分组验证、基线和成本矩阵 | 离线提升不等于线上有效 |
| 标签 | 标签代表什么、何时可用、是否有延迟或反馈偏差 | 标签定义、成熟窗口、正负样本和标注质量 | 标签泄漏时停止训练 |

| 指标 | 计算思路 | 主要维度 | 使用边界 |
| --- | --- | --- | --- |
| 门急诊人次 | `COUNT(DISTINCT visit_id)`（视图字段 `visit_cnt`） | 院区、科室、病种 | 不混用测试、撤销和跨期状态；与“ADMET预测模型”相关时还要补充主题筛选 |
| 平均住院日 | `SUM(discharge_days) / COUNT(DISTINCT inpatient_visit_id)`（视图字段 `avg_los`） | 科室、病种、人群 | 不混用测试、撤销和跨期状态；与“ADMET预测模型”相关时还要补充主题筛选 |
| 复诊率 | `COUNT(DISTINCT revisit_patient_id) / COUNT(DISTINCT index_patient_id)`（视图字段 `revisit_rate`） | 病种、人群、支付方式 | 不混用测试、撤销和跨期状态；与“ADMET预测模型”相关时还要补充主题筛选 |
| 异常检验占比 | `COUNT(DISTINCT abnormal_report_id) / COUNT(DISTINCT report_id)`（视图字段 `abnormal_rate`） | 人群、支付方式 | 不混用测试、撤销和跨期状态；与“ADMET预测模型”相关时还要补充主题筛选 |

针对“ADMET预测模型”，建议分别定义诊断指标、结果指标和护栏指标：

- **诊断指标**用于定位流程，例如曝光、有效访问、符合条件对象数和异常节点。
- **结果指标**用于判断是否改善，例如转化、留存、客单、毛利或处理时长。
- **护栏指标**用于防止局部优化伤害整体，例如退款、投诉、成本、公平性和长期留存。

每次计算都问四个问题：分母是谁、对象何时进入分母、例外状态怎么处理、窗口是否足够覆盖行为完成。尤其是患者隐私泄露；多院区患者主索引重复；临床时间与计费时间混用，任何一项没有解释清楚，指标都可能“看起来合理但无法决策”。

## 3. 方法选择：描述、诊断、预测还是因果

| 目标 | 适合的方法 | 需要的证据 | 不要混淆 |
| --- | --- | --- | --- |
| 描述现状 | 趋势、结构、同期群 | 完整口径、稳定时间窗 | 描述不等于原因 |
| 定位异常 | 分层、贡献度、漏斗、异常检测 | 原始事件、基线和质量检查 | 排名靠前不等于因果 |
| 预测未来 | 时间序列、回归、机器学习 | 时间切分验证、误差成本 | 离线准确率不等于业务收益 |
| 评估策略 | A/B、灰度、准实验 | 对照组、样本量、护栏指标 | 上线前后对比容易混入季节和选择偏差 |

如果问题只是“发生了什么”，先别急着建模；如果问题涉及“采取某策略会怎样”，就必须讨论反事实和识别条件。围绕“ADMET预测模型”，应把观察分析、预测和因果评估的产出分开标注。

## 4. 案例一：华东某零售推荐团队

### 案例 1：华东某零售推荐团队的“ADMET预测模型”现场

这是一个结合公开方法、常见工程故障和脱敏数据构造的复合案例，不对应任何单一企业事实。

- **标题落点**：先把标题中的名词还原成一个可以观测的运行问题。本例把“ADMET预测模型”映射到“机器学习、特征与 MLOps”中的特征，而不是泛泛讨论概念。
- **触发事件**：离线 AUC 提升但线上点击率下降，推荐结果集中在少数热门商品。
- **业务与数据范围**：曝光、点击、购买、用户特征、商品特征、召回、排序和实验分组。数据侧重点采集特征时间、版本、缺失率、训练服务一致性和血缘，并与HIS、EMR、LIS中的时间、状态和责任人信息对齐。
- **需要回答的问题**：特征在预测时是否可得，训练与线上计算是否一致。
- **关键障碍**：训练样本使用曝光后信息，评价只看总体 AUC，没有看多样性和长期留存。同时要防止患者隐私泄露把表面指标带偏。
- **处理过程**：按时间重建样本，加入召回覆盖、多样性、冷启动和长期留存护栏，并做线上对照实验。实施时把“上线监控覆盖数据漂移、模型漂移、业务指标、成本和回滚”写成上线检查项，并为每一项保留日志、样本和负责人。
- **验证方式**：示例项目把离线和线上指标统一到同一用户与时间窗口。验收至少同时看主指标、特征时间、版本、缺失率、训练服务一致性和血缘和一次故障回放，不能只截取优化后最快的一次结果。
- **可迁移结论**：遇到类似标题时，先按“把问题定义、标签、特征、时间切分、基线、离线评估、线上服务、漂移和回滚连接起来，避免用随机切分和单一准确率掩盖真实风险。”建立判断顺序，再决定是否调整代码、资源、口径或组织流程。

落地时建议先把一个总指标拆成可行动的树：

```text
ADMET预测模型｜专题诊断画布
├── 业务问题：把问题定义、标签、特征、时间切分、基线、离线评估、线上服务、漂移和回滚连接起来，避免用随机切分和单一准确率掩盖真实风险。
├── 观测对象：患者 / 就诊
├── 主指标：异常检验占比；辅助指标：费用偏差率
├── 风险边界：患者隐私泄露；多院区患者主索引重复；临床时间与计费时间混用
└── 验收证据：SQL 结果 + 明细样本 + 责任人 + 观察窗口
```

如果某一分支变化最大，再进入下一层，而不是一开始就按十几个维度切碎。每个分层结果都应同时报告样本量，避免小样本的极端比例抢走注意力。

## 5. SQL：计算趋势、结构和贡献度

### 趋势、结构与贡献度诊断

```sql
-- ADMET预测模型：留存同期群诊断（人群 × 院区）
WITH scoped AS (
  SELECT
    patient_id AS entity_key,
    event_id,
    event_date AS event_date,
    dimension_value AS primary_dim,
    stage_code AS secondary_dim,
    metric_value,
    status
  FROM fact_medical_event
  WHERE event_date >= DATE '2026-08-01'
    AND event_date <  DATE '2026-11-01'
    AND subject_key = 'admet'
    AND is_deleted = 0
),
dedup AS (
  SELECT *
  FROM (
    SELECT
      scoped.*,
      ROW_NUMBER() OVER (
        PARTITION BY event_id
        ORDER BY event_date DESC
      ) AS version_no
    FROM scoped
  ) ranked
  WHERE version_no = 1
),
grouped AS (
  SELECT
    primary_dim,
    secondary_dim,
    COUNT(DISTINCT entity_key) AS entity_cnt,
    COUNT(DISTINCT event_id) AS event_cnt,
    SUM(metric_value) AS metric_sum,
    AVG(metric_value) AS metric_avg
  FROM dedup
  WHERE status IN ('valid', 'completed')
  GROUP BY primary_dim, secondary_dim
),
contribution AS (
  SELECT
    *,
    metric_sum * 1.0 / NULLIF(SUM(metric_sum) OVER (PARTITION BY secondary_dim), 0) AS contribution_ratio,
    metric_avg - AVG(metric_avg) OVER (PARTITION BY secondary_dim) AS delta_to_peer
  FROM grouped
)
SELECT
  '门急诊人次' AS checked_metric,
  primary_dim,
  secondary_dim,
  entity_cnt,
  event_cnt,
  ROUND(metric_sum, 4) AS metric_sum,
  ROUND(contribution_ratio, 4) AS contribution_ratio,
  ROUND(delta_to_peer, 4) AS delta_to_peer
FROM contribution
ORDER BY ABS(delta_to_peer) DESC, entity_cnt DESC;
```

示例 SQL 只表达计算逻辑。实际实施应加入分区条件、业务状态过滤、时区和主题范围，并在结果中保留口径版本。

## 6. 案例二：华北某医学影像中心

### 案例 2：华北某医学影像中心的“ADMET预测模型”现场

这是一个结合公开方法、常见工程故障和脱敏数据构造的复合案例，不对应任何单一企业事实。

- **标题落点**：先确认业务对象和系统边界，再讨论工具或参数。本例把“ADMET预测模型”映射到“机器学习、特征与 MLOps”中的运营，而不是泛泛讨论概念。
- **触发事件**：影像检查量持续增长，但报告及时率波动明显，疑似与设备、检查部位和审核流程有关。
- **业务与数据范围**：检查申请、排队、扫描、图像归档、初诊、复审和报告发布日志。数据侧重点采集输入分布、预测分布、业务指标、版本和告警，并与HIS、EMR、LIS中的时间、状态和责任人信息对齐。
- **需要回答的问题**：数据漂移、模型漂移、延迟、成本和回滚是否可观察。
- **关键障碍**：PACS 与 RIS 状态含义不同，设备停机时间没有进入分析链路，节假日排班缺失。同时要防止多院区患者主索引重复把表面指标带偏。
- **处理过程**：统一检查状态机，补充设备日历和人员排班，按检查部位、设备型号与班次分析报告时延。实施时把“先建立简单基线和业务成本，再训练复杂模型”写成上线检查项，并为每一项保留日志、样本和负责人。
- **验证方式**：示例项目将问题拆分为设备等待、初诊积压和复审返工三类，并建立分位数时延监控。验收至少同时看主指标、输入分布、预测分布、业务指标、版本和告警和一次故障回放，不能只截取优化后最快的一次结果。
- **可迁移结论**：遇到类似标题时，先按“把问题定义、标签、特征、时间切分、基线、离线评估、线上服务、漂移和回滚连接起来，避免用随机切分和单一准确率掩盖真实风险。”建立判断顺序，再决定是否调整代码、资源、口径或组织流程。

当业务方要求“解释为什么下降”时，可以按下面顺序回答：

1. 先确认下降是否真实存在，排查采集、任务、维表和状态映射。
2. 把变化拆成对象数量、行为强度和结构占比。
3. 找到贡献最大的分组，但保留其他分组的抵消效应。
4. 抽取正负样本回查业务事件和操作日志。
5. 把尚不能证明的解释标为假设，并设计下一轮验证。

## 7. 代码验证：专题指标、实验或模型

### 专题验证代码

```python
import pandas as pd
from sklearn.model_selection import TimeSeriesSplit
from sklearn.metrics import roc_auc_score
from sklearn.ensemble import HistGradientBoostingClassifier

def evaluate_time_aware(frame: pd.DataFrame, features: list[str], target: str) -> list[dict]:
    frame = frame.sort_values("event_date").reset_index(drop=True)
    scores = []
    for train_idx, test_idx in TimeSeriesSplit(n_splits=5, gap=7).split(frame):
        train, test = frame.iloc[train_idx], frame.iloc[test_idx]
        if train[target].nunique() < 2 or test[target].nunique() < 2:
            continue
        model = HistGradientBoostingClassifier(max_depth=4)
        model.fit(train[features], train[target])
        proba = model.predict_proba(test[features])[:, 1]
        scores.append({"model_auc": roc_auc_score(test[target], proba)})
    return scores

# 主题："ADMET预测模型"
# 检查标签成熟时间、未来信息、同实体泄漏、训练服务一致性、误报成本和漂移。
```

## 8. 异常、偏差与常见误区

- **辛普森悖论**：总体改善但每个分组都变差，可能由对象结构变化造成。
- **幸存者偏差**：只分析完成流程的对象，忽略中途流失和中止。
- **分母漂移**：渠道口径、登录状态、版本或活动范围变化，改变可比性。
- **回传延迟**：当天数据未回补，导致近期效果被系统性低估。
- **多重比较**：反复寻找显著分组，实际只是随机波动。
- **行动偏差**：只报告支持既定方案的结果，忽略反例和护栏指标。

围绕“ADMET预测模型”，应预先写出至少三条反例检查。比如权限和敏感信息是否遵循最小必要原则、结论是否能回到明细，以及 指标是否在同一对象和同一时间窗内计算。

## 9. 第三个案例：华南某银行风控团队

### 案例 3：华南某银行风控团队的“ADMET预测模型”现场

这是一个结合公开方法、常见工程故障和脱敏数据构造的复合案例，不对应任何单一企业事实。

- **标题落点**：先把正常链路跑通，再人为制造一次失败和恢复。本例把“ADMET预测模型”映射到“机器学习、特征与 MLOps”中的评估，而不是泛泛讨论概念。
- **触发事件**：模型在历史数据表现很好，但新客群逾期率明显高于预期。
- **业务与数据范围**：申请、授信、交易、还款、客群、规则版本、模型分数和人工审批。数据侧重点采集时间切分、分组验证、基线和成本矩阵，并与HIS、EMR、LIS中的时间、状态和责任人信息对齐。
- **需要回答的问题**：时间、用户、设备分组是否防止泄漏，误报成本如何。
- **关键障碍**：拒绝样本被排除，模型只学习已通过客户；规则变化又没有进入特征版本。同时要防止临床时间与计费时间混用把表面指标带偏。
- **处理过程**：分析选择偏差，建立时间外验证和分群监控，记录规则版本并保留人工复核样本。实施时把“训练、验证和测试按时间或实体隔离，检查标签与特征泄漏”写成上线检查项，并为每一项保留日志、样本和负责人。
- **验证方式**：复合案例用召回、误拒、逾期、稳定性和可解释性多维评估。验收至少同时看主指标、时间切分、分组验证、基线和成本矩阵和一次故障回放，不能只截取优化后最快的一次结果。
- **可迁移结论**：遇到类似标题时，先按“把问题定义、标签、特征、时间切分、基线、离线评估、线上服务、漂移和回滚连接起来，避免用随机切分和单一准确率掩盖真实风险。”建立判断顺序，再决定是否调整代码、资源、口径或组织流程。

### 案例 4：ADMET预测模型的最小权限与越权核查

团队准备把“ADMET预测模型”从个人分析脚本升级为多人共用的数据能力。第一次评审就暴露出：分析结果本身可以访问，但派生字段、导出文件和临时表扩大了敏感数据范围，现有流程没有及时识别。 下面的组织、规模和结果均为公开方法结合常见工作场景形成的脱敏复合示例，不对应任何单一企业事实。

- **为什么要做：** 让数据用途、最小字段、访问角色、加工产物、保存期限和撤回机制都可追溯。在本场景里，核心风险还包括检验单位不统一，所以项目从一开始就把“结果能解释”与“结果能产出”放在同等位置。
- **对象与数据范围：** 本次只使用为了回答该问题所必需的脱敏范围：患者、就诊及其在诊断与治疗前后的状态记录；时间窗覆盖一个完整业务周期，并保留行动前后的观察窗口。 主键重点关注patient_id与visit_id，时间上区分业务发生、数据可见和下游采用三个节点。
- **关键异常或争议：** 分析结果本身可以访问，但派生字段、导出文件和临时表扩大了敏感数据范围，现有流程没有及时识别。初看时，HIS与EMR的状态字段似乎可以互换，但抽取边界记录后发现二者更新节奏和责任人不同。
- **核验证据：** 分类分级、授权记录、字段血缘、访问日志、导出清单、脱敏规则和过期清理记录。核验时至少抽取正常、边界、重复或迟到、权限拒绝四类样本，并让“患者”确认什么结果可以进入下一步。

- **失败路径：** 把“内网可访问”当成“业务已授权”，或者用永久大权限账号支撑临时分析。这类做法即使暂时让数字看起来一致，也会让后续无法区分“业务变化、数据缺失、规则例外和计算错误”。
- **可迁移结论：** 处理“ADMET预测模型”时，先验证特征时间、版本、缺失率、训练服务一致性和血缘，再讨论工具参数或资源调整。若证据只能支持一个假设，就把它标成假设，并为下一轮验证保留对照与样本。

- **失败路径：** 用上线前后两张趋势图直接宣称方案有效，忽略选择偏差与自然增长。这类做法即使暂时让数字看起来一致，也会让后续无法区分“业务变化、数据缺失、规则例外和计算错误”。
- **可迁移结论：** 处理“ADMET预测模型”时，先验证标签定义、成熟窗口、正负样本和标注质量，再讨论工具参数或资源调整。若证据只能支持一个假设，就把它标成假设，并为下一轮验证保留对照与样本。

> [!note] 本例验收
> 最终动作不是“把报表做出来”，而是由医技科室在明确时限内，根据平均住院日、异常检验占比和就诊时间与医嘱时间有序决定继续、回退、补查还是转人工。 若多院区患者主索引重复或关键检查项没有证据，结论应停在“待核验”，不能用业务解释替代数据回放。

### 扩展代码一：从ADMET预测模型回到可核对明细

```sql
-- ADMET预测模型：行动前后与分组增量
WITH scoped AS (
  SELECT
    patient_id AS entity_key,
    人群 AS decision_group,
    event_date AS event_date,
    metric_value,
    CASE
      WHEN event_date <  :action_date THEN 'before'
      ELSE 'after'
    END AS period_label
  FROM fact_medical_event
  WHERE event_date >= :analysis_start
    AND event_date <  :analysis_end
    AND subject_key = 'admet'
),
grouped AS (
  SELECT
    decision_group,
    period_label,
    COUNT(DISTINCT entity_key) AS entity_cnt,
    AVG(metric_value) AS metric_avg,
    SUM(metric_value) AS metric_sum
  FROM scoped
  GROUP BY decision_group, period_label
),
compared AS (
  SELECT
    decision_group,
    MAX(CASE WHEN period_label = 'before' THEN metric_avg END) AS before_avg,
    MAX(CASE WHEN period_label = 'after' THEN metric_avg END) AS after_avg,
    MAX(CASE WHEN period_label = 'before' THEN entity_cnt END) AS before_cnt,
    MAX(CASE WHEN period_label = 'after' THEN entity_cnt END) AS after_cnt
  FROM grouped
  GROUP BY decision_group
)
SELECT
  decision_group,
  before_avg,
  after_avg,
  after_avg - before_avg AS naive_delta,
  '费用偏差率' AS metric_name,
  '先建立简单基线和业务成本，再训练复杂模型' AS required_evidence
FROM compared
WHERE before_cnt >= 30 AND after_cnt >= 30
ORDER BY ABS(after_avg - before_avg) DESC;
```

执行这段 SQL 后，不要只看总量。应同时保存查询参数、口径版本、异常对象清单和对应原始记录抽样。若结果依赖人工过滤，要把过滤条件登记为规则，而不是留在个人脚本里。

### 扩展代码二：把ADMET预测模型的验收证据写成门禁

```python
from datetime import date
from hashlib import sha256

import pandas as pd

SUBJECT = "ADMET预测模型"
BLOCKING_RULES = ["患者主索引跨院区唯一","就诊时间与医嘱时间有序","诊断编码在有效版本内"]


def validate_release(frame: pd.DataFrame, start: date, end: date) -> dict:
    scoped = frame.loc[
        frame["event_date"].between(pd.Timestamp(start), pd.Timestamp(end))
        & (frame["subject_key"] == "admet")
    ].copy()
    checks = {
        "has_rows": len(scoped) > 0,
        "event_id_unique": not scoped["event_id"].duplicated().any(),
        "entity_key_complete": scoped["entity_key"].notna().all(),
        "event_time_present": scoped["event_time"].notna().all(),
        "scope_matches": scoped["subject_key"].nunique() == 1,
    }
    payload = f"{SUBJECT}|{start}|{end}|{len(scoped)}|{sorted(checks.items())}"
    return {
        "subject": SUBJECT,
        "rows": len(scoped),
        "checks": checks,
        "blocking_rules": BLOCKING_RULES,
        "release_allowed": all(checks.values()),
        "evidence_hash": sha256(payload.encode("utf-8")).hexdigest(),
    }
```

示例中的行数、时间戳和版本号均为占位值。生产实现应从调度参数、数据契约和质量平台读取真实信息，并将失败结果回写到工单、发布系统和责任人，而不是只打印在日志中。
