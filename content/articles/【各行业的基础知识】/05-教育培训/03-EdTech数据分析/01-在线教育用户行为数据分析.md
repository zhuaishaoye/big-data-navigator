# 在线教育用户行为数据分析

> [!tip] 分析目标
> 一个关于“在线教育用户行为数据分析”的结论能不能被信任，取决于它是否能回到原始事件、明确时间和对象，并说明排除了哪些记录。下面不会用单一模板概括所有场景，而是结合教育培训中的多类任务，展示数据建模、代码分析和项目验收之间如何衔接。

## 1. 把主题翻译成可验证的问题

“在线教育用户行为数据分析”不能直接等同于“做一张趋势图”。一个可执行的分析问题至少包含对象、时间、比较基准和行动：

> 在【观察周期】内，对【有效对象】按【渠道、课程、班级】比较【到课率】与【完课率】，判断变化来自结构、行为还是数据口径，并验证【策略动作】是否带来可解释的增量。

在教育培训场景中，用户行为、交易结果和策略曝光经常来自不同系统。先画数据流：

CRM → LMS → SIS → 教务系统 → 直播课堂 → 订单与支付系统

图中至少要有三个标记：业务事件发生时间、数据可见时间、策略或行动时间。只有三者分开，后续才能判断问题发生在业务、链路还是观察窗口。

## 2. 指标定义与分母检查

| 指标 | 计算思路 | 主要维度 | 使用边界 |
| --- | --- | --- | --- |
| 线索转化率 | `COUNT(DISTINCT paid_student_id) / COUNT(DISTINCT valid_lead_id)`（视图字段 `lead_cvr`） | 渠道、课程、班级 | 不混用测试、撤销和跨期状态；与“在线教育用户行为数据分析”相关时还要补充主题筛选 |
| 到课率 | `COUNT(DISTINCT attended_session_id) / COUNT(DISTINCT scheduled_session_id)`（视图字段 `attendance_rate`） | 课程、班级、地区 | 不混用测试、撤销和跨期状态；与“在线教育用户行为数据分析”相关时还要补充主题筛选 |
| 完课率 | `COUNT(DISTINCT completed_student_id) / COUNT(DISTINCT enrolled_student_id)`（视图字段 `completion_rate`） | 班级、地区、学员阶段 | 不混用测试、撤销和跨期状态；与“在线教育用户行为数据分析”相关时还要补充主题筛选 |
| 续费率 | `COUNT(DISTINCT renewed_student_id) / COUNT(DISTINCT renewable_student_id)`（视图字段 `renewal_rate`） | 地区、学员阶段 | 不混用测试、撤销和跨期状态；与“在线教育用户行为数据分析”相关时还要补充主题筛选 |

针对“在线教育用户行为数据分析”，建议分别定义诊断指标、结果指标和护栏指标：

- **诊断指标**用于定位流程，例如曝光、有效访问、符合条件对象数和异常节点。
- **结果指标**用于判断是否改善，例如转化、留存、客单、毛利或处理时长。
- **护栏指标**用于防止局部优化伤害整体，例如退款、投诉、成本、公平性和长期留存。

每次计算都问四个问题：分母是谁、对象何时进入分母、例外状态怎么处理、窗口是否足够覆盖行为完成。尤其是试听行为混入正式转化；自动播放造成虚假学习时长；同一学员多平台账号重复，任何一项没有解释清楚，指标都可能“看起来合理但无法决策”。

## 3. 方法选择：描述、诊断、预测还是因果

| 目标 | 适合的方法 | 需要的证据 | 不要混淆 |
| --- | --- | --- | --- |
| 描述现状 | 趋势、结构、同期群 | 完整口径、稳定时间窗 | 描述不等于原因 |
| 定位异常 | 分层、贡献度、漏斗、异常检测 | 原始事件、基线和质量检查 | 排名靠前不等于因果 |
| 预测未来 | 时间序列、回归、机器学习 | 时间切分验证、误差成本 | 离线准确率不等于业务收益 |
| 评估策略 | A/B、灰度、准实验 | 对照组、样本量、护栏指标 | 上线前后对比容易混入季节和选择偏差 |

如果问题只是“发生了什么”，先别急着建模；如果问题涉及“采取某策略会怎样”，就必须讨论反事实和识别条件。围绕“在线教育用户行为数据分析”，应把观察分析、预测和因果评估的产出分开标注。

## 4. 案例一：西南某高校继续教育平台

### 案例 1：西南某高校继续教育平台的“在线教育用户行为数据分析”问题

这是一个脱敏后的复合场景，不代表任何单一客户的事实数据。

- **触发事件**：线上培训项目报名人数多，但证书完成率和企业满意度偏低。本次讨论的重点是“在线教育用户行为数据分析”，所以团队先要求把先冻结对象与时间窗写进项目目标，而不是直接开始做报表。
- **数据范围**：企业报名、学员账号、课程资源、考试、证书、学习支持和满意度问卷。同时收集CRM、LMS、SIS、教务系统中的状态、时间和负责人信息，避免分析只停留在结果表。
- **关键障碍**：企业管理员替员工报名导致身份错配，考试补考次数未记录，满意度样本严重偏斜。进一步检查后发现，如果不先处理试听行为混入正式转化，“在线教育用户行为数据分析”很容易被一个表面相关指标替代。
- **处理过程**：建立企业项目-学员-课程三级模型，拆分首次通过和补考通过，补充分层抽样回访。团队把需求拆成对象、粒度、指标、质量、发布五个检查点，并为每个检查点指定原始证据。
- **结果与边界**：示例项目发现移动端兼容和考试提醒不足是主要完成障碍，并推动课程包重构。这组示例说明方法与行动之间的关系，真实项目仍应以本企业口径、样本和验收记录为准。
- **和本主题的联系**：在“在线教育用户行为数据分析”上，最有价值的产出不是一张漂亮的总览图，而是能从异常分组下钻到事件明细，并明确下一步由谁在什么时间前处理。

```text

├── 业务问题：围绕招生线索、课程报名、学习行为、作业考试、续费退费、就业与教学质量管理定位一个可干预节点
├── 观测对象：学员 / 线索

├── 风险边界：试听行为混入正式转化；自动播放造成虚假学习时长；同一学员多平台账号重复
└── 验收证据：SQL 结果 + 明细样本 + 责任人 + 观察窗口
```

如果某一分支变化最大，再进入下一层，而不是一开始就按十几个维度切碎。每个分层结果都应同时报告样本量，避免小样本的极端比例抢走注意力。

## 5. SQL：计算趋势、结构和贡献度

### 趋势、结构与贡献度诊断

```sql
-- 在线教育用户行为数据分析：留存同期群诊断（课程 × 地区）
WITH scoped AS (
  SELECT
    student_id AS entity_key,
    event_id,
    event_time AS event_date,
    dimension_value AS primary_dim,
    stage_code AS secondary_dim,
    metric_value,
    status
  FROM fact_education_event
  WHERE event_time >= DATE '2026-08-01'
    AND event_time <  DATE '2026-11-01'
    AND subject_key = 'subject'
    AND is_deleted = 0
),
dedup AS (
  SELECT *
  FROM (
    SELECT
      scoped.*,
      ROW_NUMBER() OVER (
        PARTITION BY event_id
        ORDER BY event_date DESC
      ) AS version_no
    FROM scoped
  ) ranked
  WHERE version_no = 1
),
grouped AS (
  SELECT
    primary_dim,
    secondary_dim,
    COUNT(DISTINCT entity_key) AS entity_cnt,
    COUNT(DISTINCT event_id) AS event_cnt,
    SUM(metric_value) AS metric_sum,
    AVG(metric_value) AS metric_avg
  FROM dedup
  WHERE status IN ('valid', 'completed')
  GROUP BY primary_dim, secondary_dim
),
contribution AS (
  SELECT
    *,
    metric_sum * 1.0 / NULLIF(SUM(metric_sum) OVER (PARTITION BY secondary_dim), 0) AS contribution_ratio,
    metric_avg - AVG(metric_avg) OVER (PARTITION BY secondary_dim) AS delta_to_peer
  FROM grouped
)
SELECT
  '续费率' AS checked_metric,
  primary_dim,
  secondary_dim,
  entity_cnt,
  event_cnt,
  ROUND(metric_sum, 4) AS metric_sum,
  ROUND(contribution_ratio, 4) AS contribution_ratio,
  ROUND(delta_to_peer, 4) AS delta_to_peer
FROM contribution
ORDER BY ABS(delta_to_peer) DESC, entity_cnt DESC;
```

示例 SQL 只表达计算逻辑。实际实施应加入分区条件、业务状态过滤、时区和主题范围，并在结果中保留口径版本。

- **关键障碍**：不同校区测评试卷不同，教师更换记录缺失，续费窗口按自然月而非课程结束日。进一步检查后发现，如果不先处理自动播放造成虚假学习时长，“在线教育用户行为数据分析”很容易被一个表面相关指标替代。

- **和本主题的联系**：在“在线教育用户行为数据分析”上，最有价值的产出不是一张漂亮的总览图，而是能从异常分组下钻到事件明细，并明确下一步由谁在什么时间前处理。

当业务方要求“解释为什么下降”时，可以按下面顺序回答：

1. 先确认下降是否真实存在，排查采集、任务、维表和状态映射。
2. 把变化拆成对象数量、行为强度和结构占比。
3. 找到贡献最大的分组，但保留其他分组的抵消效应。
4. 抽取正负样本回查业务事件和操作日志。
5. 把尚不能证明的解释标为假设，并设计下一轮验证。

## 8. 异常、偏差与常见误区

- **辛普森悖论**：总体改善但每个分组都变差，可能由对象结构变化造成。
- **幸存者偏差**：只分析完成流程的对象，忽略中途流失和中止。
- **分母漂移**：渠道口径、登录状态、版本或活动范围变化，改变可比性。
- **回传延迟**：当天数据未回补，导致近期效果被系统性低估。
- **多重比较**：反复寻找显著分组，实际只是随机波动。
- **行动偏差**：只报告支持既定方案的结果，忽略反例和护栏指标。

围绕“在线教育用户行为数据分析”，应预先写出至少三条反例检查。比如权限和敏感信息是否遵循最小必要原则、结论是否能回到明细，以及 指标是否在同一对象和同一时间窗内计算。

| 交付物 | 应包含 | 质量要求 |

1. 明确“在线教育用户行为数据分析”服务的使用者、决策动作和不做范围，并把成功标准写成可观察指标。

-- 在线教育用户行为数据分析：行动前后与分组增量
WITH scoped AS (
  SELECT
    student_id AS entity_key,
    课程 AS decision_group,
    event_time AS event_date,
    metric_value,
    CASE
      WHEN event_time <  :action_date THEN 'before'
      ELSE 'after'
    END AS period_label
  FROM fact_education_event
  WHERE event_time >= :analysis_start
    AND event_time <  :analysis_end
    AND subject_key = 'subject'
),
grouped AS (
  SELECT
    decision_group,
    period_label,
    COUNT(DISTINCT entity_key) AS entity_cnt,
    AVG(metric_value) AS metric_avg,
    SUM(metric_value) AS metric_sum
  FROM scoped
  GROUP BY decision_group, period_label
),
compared AS (
  SELECT
    decision_group,
    MAX(CASE WHEN period_label = 'before' THEN metric_avg END) AS before_avg,
    MAX(CASE WHEN period_label = 'after' THEN metric_avg END) AS after_avg,
    MAX(CASE WHEN period_label = 'before' THEN entity_cnt END) AS before_cnt,
    MAX(CASE WHEN period_label = 'after' THEN entity_cnt END) AS after_cnt
  FROM grouped
  GROUP BY decision_group
)
SELECT
  decision_group,
  before_avg,
  after_avg,
  after_avg - before_avg AS naive_delta,
  '完课率' AS metric_name,
  '试听与正式课分开统计' AS required_evidence
FROM compared
WHERE before_cnt >= 30 AND after_cnt >= 30
ORDER BY ABS(after_avg - before_avg) DESC;

        "subject": subject,
        "scope": scope,
        "checks": checks,
        "failed_checks": failed,
        "sample_evidence": samples[:5],
        "owner": owner,
        "decision": "block" if failed else "review",
        "manual_questions": [
            "每一项失败是否已回到原始记录",
            "对象、时间和状态是否与指标字典一致",
            "回滚或修复后是否重新完成对账",
        ],
    }


manifest = build_evidence_manifest(
    subject="在线教育用户行为数据分析",
    scope={"systems": ["CRM","LMS","SIS","教务系统"]},
    checks={"definition_frozen": False, "reconciled": False},
    samples=[],
    owner="学员",
)
Path("release-evidence.json").write_text(
    json.dumps(manifest, ensure_ascii=False, indent=2),
    encoding="utf-8",
)
print(manifest["decision"])

示例中的行数、时间戳和版本号均为占位值。生产实现应从调度参数、数据契约和质量平台读取真实信息，并将失败结果回写到工单、发布系统和责任人，而不是只打印在日志中。
