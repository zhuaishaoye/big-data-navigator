# SQL实战进阶

> [!tip] 学习目标
> 把“SQL实战进阶”放进岗位分析、技能准备、项目复盘、简历表达、技术面试、案例面试和薪资沟通，真正困难的通常不是解释名词，而是把它变成一条能被核对、能被复现、也能推动行动的工程链路。本文不追求堆满概念，而是围绕这个主题拆出业务对象、数据粒度、典型故障、代码验证和验收方式。

## 1. 先诊断，不要从收藏课程开始

围绕“SQL实战进阶”，把当前水平分成四层：

| 层级 | 你应该能做到 | 自测方式 | 常见缺口 |
| --- | --- | --- | --- |
| 知道 | 用自己的话解释概念和边界 | 不看资料讲 2 分钟 | 只会背定义 |
| 会用 | 跟随示例跑通最小闭环 | 从原始数据得到结果 | 依赖复制代码 |
| 会判断 | 发现异常、解释取舍和限制 | 处理缺失、重复和边界样本 | 不知道何时不适用 |
| 会交付 | 独立完成项目并被别人复跑 | 写文档、代码和验收 | 没有质量与复盘 |

给自己打 0-3 分，并选择最低的一项作为第一周重点。不要同时学十个工具，先把岗位、能力项、项目与岗位研究、能力盘点、项目证据、简历定制之间的关系画出来。

## 4. 练习项目：做一个可复现的闭环

### 练习题：标题专属分析代码

```sql
-- SQL实战进阶：结构贡献诊断（岗位方向 × 能力类型）
WITH scoped AS (
  SELECT
    job_id AS entity_key,
    event_id,
    event_date AS event_date,
    dimension_value AS primary_dim,
    stage_code AS secondary_dim,
    metric_value,
    status
  FROM fact_job_interview
  WHERE event_date >= DATE '2026-05-01'
    AND event_date <  DATE '2026-08-01'
    AND subject_key = 'sql'
    AND is_deleted = 0
),
dedup AS (
  SELECT *
  FROM (
    SELECT
      scoped.*,
      ROW_NUMBER() OVER (
        PARTITION BY event_id
        ORDER BY event_date DESC
      ) AS version_no
    FROM scoped
  ) ranked
  WHERE version_no = 1
),
grouped AS (
  SELECT
    primary_dim,
    secondary_dim,
    COUNT(DISTINCT entity_key) AS entity_cnt,
    COUNT(DISTINCT event_id) AS event_cnt,
    SUM(metric_value) AS metric_sum,
    AVG(metric_value) AS metric_avg
  FROM dedup
  WHERE status IN ('valid', 'completed')
  GROUP BY primary_dim, secondary_dim
),
contribution AS (
  SELECT
    *,
    metric_sum * 1.0 / NULLIF(SUM(metric_sum) OVER (PARTITION BY secondary_dim), 0) AS contribution_ratio,
    metric_avg - AVG(metric_avg) OVER (PARTITION BY secondary_dim) AS delta_to_peer
  FROM grouped
)
SELECT
  '能力覆盖度' AS checked_metric,
  primary_dim,
  secondary_dim,
  entity_cnt,
  event_cnt,
  ROUND(metric_sum, 4) AS metric_sum,
  ROUND(contribution_ratio, 4) AS contribution_ratio,
  ROUND(delta_to_peer, 4) AS delta_to_peer
FROM contribution
ORDER BY ABS(delta_to_peer) DESC, entity_cnt DESC;
```

### 练习题：质量检查

```python
# SQL实战进阶：发布前的数据质量与分层检查
import pandas as pd
import numpy as np
import hashlib

TOPIC = "SQL实战进阶"
TOPIC_KEY = "sql"
RULE_ID = "rule_career_b6ieec"
GUIDE_CHECKS = [
    "每个子查询和 Join 都说明行粒度、主键和预期基数",
    "窗口函数写明分区、排序、边界、并列和空值规则",
    "使用固定参数与结果快照，避免刷新时口径漂移",
    "性能优化以执行计划、扫描量、Shuffle和结果正确性为依据"
]
RULES = {
    "required_columns": ["event_id", "job_id", "event_date", "status"],
    "duplicate_key": "event_id",
    "entity_key": "job_id",
    "time_field": "event_date",
    "max_duplicate_rate": 0.0009,
    "max_null_rate": 0.002,
    "allowed_status": {"valid", "completed", "cancelled", "refunded"},
}

def validate(frame: pd.DataFrame) -> pd.DataFrame:
    missing = [c for c in RULES["required_columns"] if c not in frame.columns]
    if missing:
        raise ValueError(f"{TOPIC}/{TOPIC_KEY} missing required columns: {missing}")

    checks = []
    checks.append(("duplicate_rate", frame[RULES["duplicate_key"]].duplicated().mean(), RULES["max_duplicate_rate"]))
    checks.append(("entity_null_rate", frame[RULES["entity_key"]].isna().mean(), RULES["max_null_rate"]))
    event_time = pd.to_datetime(frame[RULES["time_field"]], errors="coerce")
    checks.append(("invalid_time_rate", event_time.isna().mean(), 0.0))
    bad_status = (~frame["status"].isin(RULES["allowed_status"])).mean()
    checks.append(("invalid_status_rate", bad_status, 0.0))

    result = pd.DataFrame(checks, columns=["check_name", "value", "threshold"])
    result["rule_id"] = RULE_ID + "." + result["check_name"]
    result["topic"] = TOPIC
    result["topic_key"] = TOPIC_KEY
    result["passed"] = result["value"].le(result["threshold"])
    result["sample_fingerprint"] = hashlib.sha1(
        f"{TOPIC}|{RULE_ID}|{len(frame)}".encode("utf-8")
    ).hexdigest()[:12]
    return result

def diagnose(frame: pd.DataFrame) -> pd.DataFrame:
    return (
        frame.assign(stat_date=pd.to_datetime(frame[RULES["time_field"]]).dt.date)
        .groupby(["stat_date", "status"], dropna=False)
        .agg(
            event_cnt=(RULES["duplicate_key"], "nunique"),
            entity_cnt=(RULES["entity_key"], "nunique"),
        )
        .reset_index()
        .assign(topic=TOPIC, topic_key=TOPIC_KEY, rule_id=RULE_ID)
        .sort_values("stat_date")
    )

def release_gate(result: pd.DataFrame) -> None:
    failed = result.loc[~result["passed"], ["topic_key", "check_name", "value", "threshold"]]
    if not failed.empty:
        raise RuntimeError({"topic": TOPIC, "failed_checks": failed.to_dict("records")})

# 主题专属门禁：每个子查询和 Join 都说明行粒度、主键和预期基数；窗口函数写明分区、排序、边界、并列和空值规则；使用固定参数与结果快照，避免刷新时口径漂移；性能优化以执行计划、扫描量、Shuffle和结果正确性为依据
# 生产化时把结果写入质量平台，并携带批次、分区、代码版本、规则版本和处理工单。
```

不要只运行代码。请故意破坏三件事：重复一个主键、删除一段日期、把状态改成未知值，确认质量检查能发现。再思考：数据量扩大十倍时，分组是否倾斜、查询是否全表扫描、日志是否足够、重跑是否幂等。

## 6. 工作案例一：华东某零售分析团队

### 案例 1：华东某零售分析团队的“SQL实战进阶”现场

这是一个结合公开方法、常见工程故障和脱敏数据构造的复合案例，不对应任何单一企业事实。

- **标题落点**：先把标题中的名词还原成一个可以观测的运行问题。本例把“SQL实战进阶”映射到“SQL、窗口函数与查询优化”中的性能，而不是泛泛讨论概念。
- **触发事件**：复购率在同一时间窗内出现多个版本，运营无法判断活动是否有效。
- **业务与数据范围**：用户、订单、支付状态、退款、活动曝光和首次购买日期。数据侧重点采集执行计划、扫描字节、Shuffle、文件数，并与招聘网站、ATS、代码评测中的时间、状态和责任人信息对齐。
- **需要回答的问题**：扫描量、Join 策略、数据倾斜和结果写出是否合理。
- **关键障碍**：复购窗口按自然日截断，退款订单未冲减，匿名与登录身份也未合并。同时要防止工具堆砌把表面指标带偏。
- **处理过程**：固定用户主键、观察窗和完成购买定义，使用窗口函数生成首购与后续购买间隔，并输出边界样本。实施时把“每个子查询和 Join 都说明行粒度、主键和预期基数”写成上线检查项，并为每一项保留日志、样本和负责人。
- **验证方式**：示例分析用可复算 SQL 与明细抽样统一复购口径。验收至少同时看主指标、执行计划、扫描字节、Shuffle、文件数和一次故障回放，不能只截取优化后最快的一次结果。
- **可迁移结论**：遇到类似标题时，先按“先把业务问题翻译成正确的行粒度、连接关系和窗口范围，再通过执行计划、分区裁剪和数据分布优化性能。”建立判断顺序，再决定是否调整代码、资源、口径或组织流程。

从案例中提取一个练习：用表中的检查项和 SQL 结构，写出你所在场景的对象、时间和指标。即使没有企业数据，也可以用公开数据集或合成数据完成，但必须说明数据来源和使用边界。

## 9. 案例三：从一次失败中建立学习反馈

### 案例 3：华北某物流分析平台的“SQL实战进阶”现场

- **标题落点**：先把正常链路跑通，再人为制造一次失败和恢复。本例把“SQL实战进阶”映射到“SQL、窗口函数与查询优化”中的窗口，而不是泛泛讨论概念。

- **可迁移结论**：遇到类似标题时，先按“先把业务问题翻译成正确的行粒度、连接关系和窗口范围，再通过执行计划、分区裁剪和数据分布优化性能。”建立判断顺序，再决定是否调整代码、资源、口径或组织流程。

### 扩展代码一：从SQL实战进阶回到可核对明细

```sql
-- SQL实战进阶：源表与结果表按对象对账
WITH source_side AS (
  SELECT
    job_id AS entity_key,
    COUNT(DISTINCT event_id) AS event_cnt,
    SUM(metric_value) AS metric_sum
  FROM fact_job_interview
  WHERE event_date >= :start_date
    AND event_date <  :end_date
    AND subject_key = 'sql'
    AND is_deleted = 0
  GROUP BY job_id
),
result_side AS (
  SELECT
    job_id AS entity_key,
    event_cnt,
    metric_sum
  FROM fact_job_interview_result
  WHERE stat_date BETWEEN :start_date AND :end_date
    AND subject_key = 'sql'
)
SELECT
  COALESCE(s.entity_key, r.entity_key) AS entity_key,
  s.event_cnt AS source_event_cnt,
  r.event_cnt AS result_event_cnt,
  s.metric_sum AS source_metric_sum,
  r.metric_sum AS result_metric_sum,
  COALESCE(r.metric_sum, 0) - COALESCE(s.metric_sum, 0) AS metric_diff
FROM source_side s
FULL OUTER JOIN result_side r USING (entity_key)
WHERE ABS(COALESCE(r.metric_sum, 0) - COALESCE(s.metric_sum, 0)) > 0
   OR COALESCE(s.event_cnt, 0) <> COALESCE(r.event_cnt, 0)
ORDER BY ABS(metric_diff) DESC;
```

执行这段 SQL 后，不要只看总量。应同时保存查询参数、口径版本、异常对象清单和对应原始记录抽样。若结果依赖人工过滤，要把过滤条件登记为规则，而不是留在个人脚本里。

### 扩展代码二：把SQL实战进阶的验收证据写成门禁

```python
import json
from pathlib import Path


def build_evidence_manifest(
    subject: str,
    scope: dict,
    checks: dict,
    samples: list[dict],
    owner: str,
) -> dict:
    failed = [name for name, passed in checks.items() if not passed]
    return {
        "subject": subject,
        "scope": scope,
        "checks": checks,
        "failed_checks": failed,
        "sample_evidence": samples[:5],
        "owner": owner,
        "decision": "block" if failed else "review",
        "manual_questions": [
            "每一项失败是否已回到原始记录",
            "对象、时间和状态是否与指标字典一致",
            "回滚或修复后是否重新完成对账",
        ],
    }


manifest = build_evidence_manifest(
    subject="SQL实战进阶",
    scope={"systems": ["招聘网站","ATS","代码评测","项目仓库"]},
    checks={"definition_frozen": False, "reconciled": False},
    samples=[],
    owner="候选人",
)
Path("release-evidence.json").write_text(
    json.dumps(manifest, ensure_ascii=False, indent=2),
    encoding="utf-8",
)
print(manifest["decision"])
```

示例中的行数、时间戳和版本号均为占位值。生产实现应从调度参数、数据契约和质量平台读取真实信息，并将失败结果回写到工单、发布系统和责任人，而不是只打印在日志中。
