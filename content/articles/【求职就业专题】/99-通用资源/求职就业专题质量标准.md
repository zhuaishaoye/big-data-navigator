# 📋 求职就业专题质量标准与规范

> [!abstract] 📋 标准概览
> - 🎯 **目标**：确保求职就业专题内容的专业性、实用性和一致性
> - 📚 **适用范围**：所有求职就业专题下的文档内容
> - ⏱️ **检查频次**：每次内容更新时必须遵守
> - 🎖️ **重要程度**：★★★★★

## 🎯 内容定位与价值标准

### 核心价值原则
**求职就业专题的独特价值**：
- **实用导向**：所有内容必须能直接指导求职实践
- **结果导向**：内容要能帮助求职者获得具体的求职成果
- **差异化价值**：与网上泛泛而谈的求职建议区别开来，提供深度专业的指导
- **系统性完整**：覆盖求职全流程，形成完整的知识体系

### 内容价值评判标准
**高价值内容特征**：
- ✅ 基于真实行业经验和数据洞察
- ✅ 提供具体可执行的方法和工具
- ✅ 包含量化的标准和评估方法
- ✅ 结合数据行业的特殊性和专业要求
- ✅ 能够解决求职者的具体痛点和困惑

**低价值内容特征**：
- ❌ 空泛的求职鸡汤和正确的废话
- ❌ 缺乏数据行业针对性的通用建议
- ❌ 没有实操价值的纯理论内容
- ❌ 过时的或不准确的市场信息
- ❌ 重复网上已有的基础求职常识

## 📝 代码内容管理规则

### 代码使用规范
**核心原则**：除了技术面试题之外，求职就业专题中的内容不应该有任何具体代码实现。

**具体规则**：

**✅ 允许保留代码的场景**：
- **技术面试专项文档**：如"技术面试专项.md"、"算法面试专项.md"、"系统设计面试专项.md"等
- **面试题目和解答**：用于帮助求职者准备技术面试的具体题目
- **面试考察点说明**：展示面试官可能会问到的技术细节

**❌ 需要移除代码的场景**：
- **技能提升路径文档**：如"Python编程进阶.md"、"大数据技术栈精通.md"等
- **岗位认知与准备文档**：如"数学统计基础要求.md"、"岗位深度解析.md"等
- **简历优化指南**：简历制作和优化相关的所有文档
- **薪资谈判和职业发展**：非技术类求职指导内容

### 代码替换标准
**将代码转换为概念说明的方法**：

**原则1：保留技术概念，移除具体实现**
````markdown
❌ 错误示例：
```python
def calculate_mean(data):
    return sum(data) / len(data)
```

✅ 正确示例：
- **均值计算**：掌握基础统计函数的实现原理，理解数值计算的精度问题
````

**原则2：突出技能要点，强化学习目标**
```markdown
❌ 错误示例：
显示大段SQL查询代码

✅ 正确示例：
- **复杂查询能力**：掌握多表关联、窗口函数、CTE等高级SQL技巧
- **性能优化思维**：理解索引设计、查询计划、执行效率等优化要点
```

**原则3：提供学习路径，不提供具体代码**
```markdown
❌ 错误示例：
完整的机器学习模型实现代码

✅ 正确示例：
- **模型构建流程**：从数据预处理到模型评估的完整workflow掌握
- **框架应用能力**：熟练使用scikit-learn、TensorFlow等主流框架
- **调参优化技巧**：掌握超参数调优和模型选择的方法论
```

## ✍️ 写作风格与语言标准

### 语言风格要求
**专业性与亲和力并重**：
- **专业术语准确**：使用正确的行业术语和概念
- **表达清晰简洁**：避免冗长复杂的句子结构
- **语调友好鼓励**：保持积极正面的语调，给予求职者信心
- **逻辑清晰严谨**：内容组织有序，逻辑关系明确

### 特殊内容格式
**使用标准化的提示框**：
- `> [!abstract]` - 文档概览
- `> [!note]` - 重要提醒
- `> [!tip]` - 实用技巧
- `> [!warning]` - 注意事项
- `> [!example]` - 案例示例
- `> [!quote]` - 总结引语

**统一的强调格式**：
- **加粗**：用于重点概念和关键信息
- *斜体*：用于外文术语和特殊名词
- `代码格式`：用于技术名词和工具名称（但不用于代码实现）
